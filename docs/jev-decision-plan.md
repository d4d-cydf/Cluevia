# Codex 설계와 Jev 반복 판정

Codex가 자료별 온톨로지와 선택형 질문을 설계하면 서버가 같은 정의를 반복 적용합니다. 실행 형식은 검증된 JSON이며, 모델이 작성한 JavaScript나 Python을 실행하지 않습니다.

```text
자료 프로필 → Codex: 객체·속성·관계·컬럼 매핑·선택형 질문 설계
                       ↓
표의 정형 필드 ─────→ 검증된 매핑으로 코드 변환
표의 본문·설명 열 ─→ Jev: 서술 분류·관계 유형 후보 판정
                       ├─ 독립적인 짧은 기록 → 원문 여러 개를 묶어 Codex 분석
                       └─ 복잡·불확실·오류   → 원문을 개별 Codex 분석
                       ↓
                 인용·유형·식별 키 검증 → 그래프 저장
```

## 자료별 선택형 질문

`sourceMappings[].semanticColumns`는 표에서 추가 의미 분석이 필요한 열입니다. `processing.decisionRules`에 해당 자료·열에 적용할 질문과 선택지를 선언합니다.

```json
{
  "textStrategy": "codex",
  "jevEligibleLinkTypes": [],
  "rationale": "본문의 서술 유형은 반복 분류하고, 실제 객체·관계는 원문으로 확인",
  "decisionRules": [
    {
      "apiName": "reportKind",
      "displayName": "문서 유형",
      "purpose": "classification",
      "sourceName": "reports.jsonl",
      "columns": ["text"],
      "question": "이 기록의 서술 유형은 무엇인가?",
      "choices": [
        { "apiName": "directReport", "description": "작성자가 직접 보고한 서술" },
        { "apiName": "quotedReport", "description": "다른 자료를 재인용한 서술" },
        { "apiName": "uncertain", "description": "자료만으로 구분 불가" }
      ]
    }
  ]
}
```

이 예시는 `reports.jsonl`의 매핑에 `text`가 의미 분석 열로 선언된 경우에 사용합니다. 규칙은 최대 8개, 규칙당 선택지는 2–8개이며 `uncertain` 선택지를 반드시 포함합니다. 서버는 실제 파일·의미 분석 열과의 참조를 검증합니다.

**반복 분류는 `textStrategy: "codex"`이거나 `jevEligibleLinkTypes: []`여도 작동합니다.** 이 두 필드는 Jev가 그래프를 직접 추출하는 별도 경로의 조건입니다. 이전 온톨로지에 사용자 정의 질문이 없어도, 의미 분석 열이 선언된 기록에는 서버의 기본 서술·복잡도·관계 유형 후보 질문을 사용할 수 있습니다. 단순 정형 데이터만 있고 의미 분석할 열이 없으면 분류를 위한 Jev 호출은 하지 않습니다.

## Jev가 실제로 판정하는 내용

고정 실행기가 원문 한 기록과 온톨로지에서 질문을 구성합니다.

- 직접 서술인지, 재인용·부정·반박 등이 포함되어 있는지.
- 해당 기록만으로 해석할 수 있는지, 다른 문서나 복잡한 문맥이 필요한지.
- 허용된 관계 유형 중 검토할 후보가 있는지.
- Codex가 선언한 자료별 질문에 어떤 선택지가 해당하는지.

여러 질문을 한 API 요청으로 보내고 각각의 응답·선택지·확신도를 검증합니다. 따라서 화면의 **Jev 호출 수**와 **Jev 분류·후보 판정 수**는 다릅니다. 불확실하다는 유효한 답변도 판정 건수에 포함합니다.

분류 결과는 **분석 경로를 정하는 보조 정보**입니다. Jev가 관계 후보를 골랐다는 이유로 연결을 확정하거나 실제 식별자를 만들지 않습니다. 후보가 없다는 답변도 원문을 버리는 근거로 사용하지 않습니다. Codex에는 원문과 함께 보조 판정임을 명시해서 전달합니다.

## 묶음 분석과 개별 분석

서술 태도와 독립 처리 가능성을 모두 최소 0.9 이상의 확신도로 판정하고 원문에 부정·재인용·문서 참조 단서가 없는 짧은 기록은 최대 4개, 합계 최대 6,000자 범위에서 묶어 Codex에 전달합니다. 원문과 각 출처 ID를 유지합니다. 이 두 핵심 판정이 불확실하거나 복잡한 문맥·부정·반박·제공자 오류가 있는 자료는 개별 분석 경로로 보냅니다. Jev 요청 크기 한도를 넘는 기록도 잘라 분류 결과만 믿는 대신 원문 분석 경로를 사용합니다.

관계 유형 후보나 자료별 추가 분류가 불확실한 경우에는 그 불확실성을 기록하고 Codex가 원문으로 확인합니다. 이 보조 질문의 낮은 확신도만으로 묶음 분석을 막지는 않습니다. 어느 경로든 원문 전체와 출처를 유지하며, 분류를 검증된 사실로 저장하지 않습니다.

이 방식은 짧은 기록마다 Codex 프로세스를 시작하던 횟수를 줄일 수 있습니다. **Jev 보조 분류 자체가 Codex 추출을 생략하는 것은 아닙니다.** Jev 요청 시간도 추가되므로 전체 속도와 비용은 묶을 수 있는 기록 비율과 실제 모델 응답에 따라 달라집니다. 확신도는 실제 정확도 보장이 아닙니다.

## 단순 관계의 직접 추출

`textStrategy: "jev-assisted"`와 `jevEligibleLinkTypes`가 선언된 경우에는 기존의 제한된 직접 추출 경로도 사용할 수 있습니다. 한 문장에 서로 다른 이름 두 개가 인용되고, 이름만으로 식별되는 두 객체 사이의 관계 하나로 전체 내용을 표현할 수 있어야 합니다.

서버는 전체 표현 가능 여부·양쪽 객체 유형·관계 방향을 독립 질문으로 판정하고 응답의 일관성과 원문 인용을 검증합니다. 부정·시간·수치·복합 주장·추가 속성 등이 있거나 확신이 부족하면 Codex가 원문을 분석합니다. 직접 추출의 수용 기준은 최소 0.9이며 `TYPESAFE_MIN_CONFIDENCE`가 더 높으면 높은 값을 적용합니다.

## 진행 내역과 재사용

분석 화면의 **Jev 처리**에는 서버가 선택한 경로와 미사용 사유를 표시합니다. **Jev 판정 내역**을 펼치면 자료별 분석 경로·사유·선택 결과·확신도를 조회합니다. 필요할 때 펼치거나 새로고침하여 최대 100개 기록을 조회하며 화면에는 앞 20개를 표시합니다. **처리 내역**에서 다음을 구분할 수 있습니다.

| 표시 | 의미 |
| --- | --- |
| Jev 호출 | 실제 API 요청 수 |
| Jev 분류·후보 판정 | 유효한 응답으로 확인한 질문 수. 불확실 판정 포함 |
| Jev 보조 분석 | 유효한 분류 응답을 받은 원문 구간 수 |
| Jev 개별 검토 판정 | 복잡성·불확실성·분류 오류 등으로 개별 분석에 배정한 구간 수. 묶을 이웃 기록이 없어 단독 처리한 구간은 제외 |
| Codex 묶음 분석 | 여러 짧은 기록을 한 번에 전달한 실제 Codex 실행 수 |

구간 추출 캐시는 원문·온톨로지 정의·처리 설정·판정 코드 버전을 구분합니다. 같은 조건의 완료 결과는 재사용하고 출처 ID를 현재 업로드에 맞춰 연결합니다. 중단한 작업의 완료 구간도 다시 분석하지 않습니다. 새로운 질문으로 온톨로지가 바뀌면 같은 파일이라도 분석이 다시 필요할 수 있습니다.

## 실제 자료 검증

2026-10-10에 기존 업로드와 저장된 온톨로지를 읽어, 운영 작업을 변경하지 않는 별도 DB에서 확인했습니다.

| 항목 | 확인 결과 |
| --- | --- |
| 정형 변환 대상 | 1,147행 |
| 의미 분석할 원문 | 40개 기록 모두 유지 |
| Jev 요청 | 40회, 준비·판정 약 3.1초 |
| 유효한 선택형 판정 | 117건. 정상 판정을 얻지 못한 1개 기록은 개별 Codex 분석으로 배정 |
| Codex 처리 계획 | 기존 40단위 → 20단위: 28개 기록을 8묶음으로, 나머지 12개를 개별 처리 |
| 실제 추출·저장 확인 | 4개 기록 묶음 1개를 Codex 1회로 분석, 약 40.7초 후 노드 4개·관계 2개 저장 |

40→20은 준비된 처리 단위 수입니다. 전체 20단위를 실행해 총 소요 시간이나 추출 정확도를 비교한 결과는 아닙니다. 검증 오류·시간 초과에 따른 재시도는 호출 수를 늘릴 수 있습니다. 기존에 준비가 끝난 작업은 저장된 계획을 유지하므로, 새 판정 경로는 서버 재시작 후 **새 분석**에서 확인합니다.
