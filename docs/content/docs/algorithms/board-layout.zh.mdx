`GraphRenderer.tsx` 中的 `boardLayout` 与 `lanesLayout` 根据对象和关系计算场景大小及卡片中心坐标。下述 Board 力计算用于初始布局；同一 Board 的后续结果在保留已有坐标的前提下增量加入。屏幕距离不表示置信度或地理距离。

## 1. 按度确定排序 [#1-차수로-순서를-정한다]

Board 对每条关系的两个端点各增加 1 度，再按**度降序 → ID 的 `localeCompare` 顺序**排列对象。自环使同一对象的度增加 2，但不参与后续弹簧力计算。

若存在 A–B 和 A–C 两条边，则 A 的度为 2，B、C 的度均为 1，因此从 A 开始初始化。度相同时的比较结果可能受运行环境的字符串排序规则影响。

## 2. 用黄金角展开初始坐标 [#2-황금각으로-초기-좌표를-펼친다]

设对象数为 `V`，排序后的序号为 `i`，按下式初始化：

```text
columns = max(3, ceil(sqrt(V × 1.4)))
width   = max(940, columns × 240 + 80)
height  = max(580, ceil(V / columns) × 160 + 100)
angle   = i × 2.399963229728653
radius  = sqrt((i + 0.6) / max(1, V))
x       = width / 2  + cos(angle) × radius × (width / 2 - 120)
y       = height / 2 + sin(angle) × radius × (height / 2 - 70)
```

布局从中心向外展开，不使用随机数。度较大的对象初始位置更靠近中心。

## 3. 进行 150 轮力与碰撞计算 [#3-힘과-충돌을-150번-계산한다]

| 计算 | 规则 |
| --- | --- |
| 每对对象之间的斥力 | 距离 `d = max(1, hypot(dx, dy))`，大小 `min(24, 11000 / d²)` |
| 各关系的弹簧力 | 中心距离与 255px 之差乘以 `0.012` |
| 向心力 | 到场景中心的横向、纵向距离分别乘以 `0.004` |
| 坐标移动 | 各轴位移限制为 ±16px，并将坐标限制在场景边界内 |

若某轴的坐标差为 0，则在该轴使用 `0.01`。存在多条关系时，分别累加各条关系的弹簧力。横向坐标范围为 `115..width-115`，纵向为 `70..height-70`。

卡片尺寸为182×74px,碰撞检查每轴增加28px的距离。

```text
overlapX = 182 + 28 - abs(xA - xB)
overlapY = 74  + 28 - abs(yA - yB)
```

两个重叠量均为正时，选择重叠较小的轴，使两张卡片沿相反方向各移动重叠距离的 51%，再将坐标限制到边界内。每轮力计算后执行一次；150 轮结束后不再单独迭代碰撞分离。由于存在边界和迭代上限，无法保证所有输入都完全无重叠。

## 大规模输入与探索范围 [#큰-입력과-탐색-범위]

`boardLayout` 本身包含对象数超过 200 时按组使用网格的分支。组按首次出现的顺序排列，组内对象保持原顺序，横向间距为 250px，纵向间距为 135px。

当前渲染器在**对象超过 200 个、关系超过 1,000 条、事件超过 500 个**中的任一条件成立时，先构建[探索子图](/zh/docs/algorithms/exploration)。由于默认对象显示上限为 200，这一子图的初始 Board 布局仍采用力计算。网格分支与实际界面的分页限制属于不同层次。

若小型图未超过三项上限，则直接传入原图，不调用 `exploreGraph`。选择或搜索变化时，不重复计算不必要的探索投影；搜索结果的突出及淡化由画布处理。

## Lanes：将组转换为列 [#lanes-그룹을-열로-바꾼다]

按 `groups` 的顺序创建列，各组对象按原数组顺序以 124px 的纵向间距排列。函数本身保留空组对应的列；大图的探索投影会预先排除没有可显示对象的组。

```text
width     = max(900, 그룹 수 × 254 + 40)
laneWidth = (width - 40) / max(1, 그룹 수)
x         = 20 + laneWidth × (열 번호 + 0.5)
y         = 140 + 행 번호 × 124
```

这不是自动聚类，而是根据输入中的 `node.group` 进行布局。

## 更新与手动布局 [#갱신과-수동-배치]

Board 与 Lanes 的基础布局依据 `topologyKey` 以及视图类型的变化重新计算。该键由图 ID、对象 ID 与组、关系的两端 ID、组 ID 按数组顺序构成。仅名称、说明、属性或处理量变化时，不重新计算基础布局；数组顺序变化也会改变该键。Timeline 则依据事件和日期单独计算。

保持同一图 ID 的 Board 时，新显示集合中仍存在的对象保留原坐标。即使部分对象退出显示，其余对象也不会从头重新布局。退出对象的坐标从当前场景移除，**仅新增对象**按以下顺序放置。

1. 收集现有卡片所占的位置。 用户拖动的卡片使用手动坐标。
2. 从与新对象相连的对象中，选择第一个已有坐标的对象作为参考点；参考点也优先采用用户手动设置的坐标。
3. 依次检查参考点周围的六个候选位置，以横向 230px、纵向 125px 的间距生成候选；排除与已有位置在横向 210px、纵向 105px 范围内发生重叠的候选。
4. 若附近无空位或没有参考点，则在五列网格中查找空位。新放置的卡片也参与下一张卡片的碰撞检查，并据此扩展场景大小。

最后应用当前图的手动坐标覆盖结果。同一 Board 的更新不重复完整力计算；切换到其他图或 Lanes 时，计算对应视图的基础布局。由于手动坐标由用户指定，不能保证所有位置均无重叠。

拖动坐标按图 ID 与视图保存在 `localStorage` 中，不改变图内容或服务器的对象识别规则。

## 复杂性和验证 [#복잡도와-검증]

小型 Board 的初始布局包含排序及 150 轮两两作用力与碰撞检查，复杂度为 `O(V log V + 150(V² + E))`，额外空间为 `O(V + E)`。大规模输入的网格分支为 `O(V)`；逐组筛选对象的 Lanes 为 `O(GV)`。更新还涉及结构键生成、现有坐标与邻接表检查，以及新对象候选位置的搜索。每次候选检查均遍历已占用位置，因此成本取决于新增对象数和网格占用情况。
