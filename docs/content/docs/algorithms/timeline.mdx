---
title: 시간축 배치
description: 사건의 절대 시각을 가로 좌표에 투영하고, 객체별 행에서 겹치지 않는 트랙을 선택합니다.
---

`timelineLayout`은 그래프의 사건을 날짜순으로 정렬해 행·트랙·기간 막대와 눈금을 계산합니다. `events`가 비어 있으면 날짜를 추정하지 않고 빈 시간축을 표시합니다.

## 1. 시간대를 반영해 정렬한다

시작일과 종료일을 `Date.parse`로 읽습니다. 시작 시각 오름차순으로 정렬하고 동률은 ID의 `localeCompare`로 정합니다.

```text
2017-08-12T01:30:00+09:00
→ 2017-08-11T16:30:00Z와 같은 좌표
```

시간축과 사건 카드의 날짜는 UTC 기준의 일 단위로 표시합니다. 따라서 원문 시간대의 날짜와 하루 차이가 날 수 있고, 같은 날 다른 시각도 같은 날짜 라벨로 보일 수 있습니다.

## 2. 시각을 가로 좌표로 투영한다

모든 시작·종료 시각의 최솟값과 최댓값을 구합니다. 사건 수를 `T`라 하면 다음을 사용합니다.

```text
span  = max(86,400,000ms, maxTime - minTime)
width = max(1100, min(6000, T × 125 + 500))
x(t)  = 240 + (t - minTime) / span × (width - 490)
```

기간이 하루보다 짧아도 최소 하루 폭을 기준으로 계산합니다. 모든 사건이 같은 시각이면 같은 x 좌표에 놓이고 트랙으로 나뉩니다.

## 3. 관련 객체별 행과 트랙을 선택한다

각 사건의 `nodeIds`에서 실제 그래프에 존재하는 첫 객체를 행으로 사용합니다. 하나의 사건이 여러 객체를 참조해도 한 행에만 놓습니다. 객체를 찾지 못하면 공통 사건 행을 사용합니다.

행 안에서는 시작일순으로 다음 규칙을 적용합니다.

```text
track = 저장된 끝점 + 20px < 이번 사건의 x인 첫 트랙
        없으면 새 트랙
끝점  = max(x + 194px, 종료일의 x)
y     = 행 시작 + 24px + 트랙 번호 × 92px
행 높이 = max(110px, 트랙 수 × 92px + 34px)
```

예를 들어 같은 시각의 사건 3개는 서로 다른 트랙에 놓입니다. 기간 막대가 길면 이후 사건은 그 막대가 끝난 뒤에야 같은 트랙을 쓸 수 있습니다. 먼저 쓸 수 있는 트랙을 고르는 탐욕적 배치입니다.

## 4. 눈금을 균등하게 나눈다

최솟값과 최댓값이 같으면 눈금은 1개입니다. 다르면 다음 개수로 두 시각 사이를 등분합니다.

```text
tickCount = min(7, max(2, ceil((maxTime - minTime) / 하루) + 1))
```

월의 시작이나 자정에 맞추는 달력 눈금 알고리즘은 아닙니다. 날짜 표시는 UTC 일 단위이므로 짧은 구간에서는 눈금 라벨이 중복될 수 있습니다.

## 복잡도와 한계

정렬은 `O(T log T)`, 한 행에 트랙이 계속 늘어나는 경우 트랙 탐색은 최악 `O(T²)`입니다. 사건의 객체 참조 수 합을 `R`, 객체 수를 `V`, 그룹 수를 `G`라 하면 현재 선형 검색을 포함한 전체 상한은 `O(T log T + T² + RV + T(V + G))`로 볼 수 있습니다. 결과 저장 공간은 `O(T)`입니다.

시간축은 그래프에 명시된 사건만 보여줍니다. 객체 속성의 날짜를 자동으로 사건으로 바꾸거나, 불확실한 날짜를 추정하지 않습니다. 큰 케이스에서는 현재 [탐색 투영](/docs/algorithms/exploration)에 포함된 사건을 배치합니다.
