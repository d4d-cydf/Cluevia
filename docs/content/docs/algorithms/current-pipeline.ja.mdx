Clueviaは資料から**オブジェクト・関係・事件・出典**を抽出し、同じデータをBoard・Lanes・Timelineで示します。このドキュメントでは、各ステップの入力と出力、計算ルール、制限を実際の実装に関連付けます。

## 全体の処理フロー [#전체-처리-흐름]

```text
질문 · 자료 미리보기 → 확인 질문 → 분석 범위 확정
                                    │
원본 자료 업로드 ────────────────────┤
                                    ▼
                   온톨로지 설계 또는 기존 정의 선택
                                    │
                   ┌────────────────┴─────────────────┐
                   ▼                                  ▼
            표 데이터 컬럼 매핑                  문서 구간 분석
            규칙으로 행 변환                  Codex · 선택적 Jev
                   └────────────────┬─────────────────┘
                                    ▼
                    스키마 · 식별 키 · 원문 인용 검증
                                    ▼
                    SQLite 저장 → 분석 기록별 결과 통합
                                    ▼
                       탐색 범위 선택 → 좌표 계산
                         Board · Lanes · Timeline
```

質問だけがオントロジー構造を設計し、実際のオブジェクトとの関係は作成しません。完成したグラフJSONと公開例は、モデル抽出なしでグラフ契約を調べて開きます。

## アルゴリズムを読む順序 [#알고리즘-읽는-순서]

| ステップ | 入力→出力 | 重要な質問 |
| --- | --- | --- |
| [1。データ構造化](/ja/docs/algorithms/extraction) | 要請・原文→検証された分析記録 | 表と文書をどのように分割して処理しますか？ |
| [2。データ検証](/ja/docs/algorithms/validation) | 抽出結果・JSON → 有効なグラフ | 原文の引用検査と参照整合性の検査は何が異なるか。 |
| [3。グラフの配置](/ja/docs/algorithms/board-layout) | オブジェクト・関係 → カード座標 | 反発力・スプリング・衝突分離をどのように組み合わせるか？ |
| [4。関係線とラベル](/ja/docs/algorithms/edge-routing) | カード座標→曲線・ラベル | 一般関係と自己関係の経路はどう違いますか？ |
| [5。時間軸配置](/ja/docs/algorithms/timeline) | 事件の時刻・期間→座標・トラック | 視野を整列し、重複する出来事をどのように分割するのですか？ |
| [6。検索とキャッシュ](/ja/docs/algorithms/exploration) | 検索・選択→表示する部分グラフ | データ全体を保存し、表示量をどのように制限しますか？ |

## モデル判断とコード計算 [#모델-판단과-코드-계산]

| ステップ | 担当すること | 保証範囲 |
| --- | --- | --- |
| オントロジー設計・文書分析 | タイプ、属性、関係、根拠候補の抽出 | モデル判断で結果が異なる場合があります |
| 構造化データの変換 | 検証済み列マッピングへの行変換 | マップされた行ごとにモデルを呼び出さない |
| 抽出検証 | タイプ・属性・識別キー・正確な原文引用検査 | 引用の存在が主張自体の真実を証明していない |
| グラフ検証 | フィールド、サイズ、ID、日付と参照チェック | データの構造的一貫性チェック |
| ナビゲーション・レイアウト | 表示セット、座標、関係線、時間軸の計算 | 保存された素材を表示するルール |

サーバーは、原文と分析履歴をSQLiteおよびデータディレクトリに保存します。グラフの配置と選択状態はブラウザで計算し、ユーザーがドラッグした座標はそのブラウザに保存します。

## 実装への接続 [#구현으로-연결하기]

| 実装 | 役割 |
| --- | --- |
| `server/clarification.ts`, `server/ontology-planner.ts` | 分析範囲確認とオントロジー設計 |
| `server/generic-ingest.ts`, `server/analysis-pipeline.ts` | データ分割・マッピング・モデル分析・キャッシュ |
| `server/ontology.ts`, `src/lib/graph-document.ts` | 抽出の根拠とグラフ契約の検証 |
| `server/ontology-store.ts`, `server/analysis-case.ts` | 保存、オブジェクト接続とケースの統合 |
| `src/lib/graph-exploration.ts` | 選択 周辺拡張、検索、ページ選択 |
| `src/components/graph/GraphRenderer.tsx` | カード・関係線・時間軸配置とレンダリング |

ドキュメントは現在、リモートアプリの実装に基づいています。複雑さは、コードの繰り返し構造を分析した値であり、モデル処理時間やすべての機器のパフォーマンスを保証するものではありません。
