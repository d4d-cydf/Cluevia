`GraphRenderer.tsx`の`boardLayout`と`lanesLayout`はオブジェクト・関係でシーンサイズとカード中心座標を計算します。下のボードの力の計算は最初の配置に使用され、同じボードの後続の結果は既存の座標を保存しながら追加されます。画面上の距離は信頼度や地理的距離を意味しません。

## 1。次数で並べ替える [#1-차수로-순서를-정한다]

Board は各関係の両端の次数を 1 ずつ増やす。オブジェクトは**次数の降順、次いで ID の `localeCompare` 順**に並べる。自己ループは同じオブジェクトの次数に 2 を加えるが、後続のばね力計算からは除外する。

A–B と A–C がある場合、A の次数は 2、B と C は 1 であるため、A から初期化する。同次数の場合の比較は、実行環境の文字列照合規則に影響されることがある。

## 2。黄金角で初期座標を広げる [#2-황금각으로-초기-좌표를-펼친다]

オブジェクト数`V`、ソート後の順番`i`について、次のように開始します。

```text
columns = max(3, ceil(sqrt(V × 1.4)))
width   = max(940, columns × 240 + 80)
height  = max(580, ceil(V / columns) × 160 + 100)
angle   = i × 2.399963229728653
radius  = sqrt((i + 0.6) / max(1, V))
x       = width / 2  + cos(angle) × radius × (width / 2 - 120)
y       = height / 2 + sin(angle) × radius × (height / 2 - 70)
```

乱数なしで中心から外に広がります。次数の大きいオブジェクトは、最初は中心の近くに配置されます。

## 3。力と衝突を150回計算する [#3-힘과-충돌을-150번-계산한다]

| 計算 | ルール |
| --- | --- |
| すべてのオブジェクトペアの反発力 | 距離`d = max(1, hypot(dx, dy))`、サイズ`min(24, 11000 / d²)` |
| 関係別スプリング | 中心距離と255pxの差に`0.012`を掛けた力 |
| 中心方向力 | 中心までの横・縦差にそれぞれ`0.004`を掛ける |
| 座標の移動 | 軸ごとに力を±16pxに制限し、シーン境界内に固定 |

座標差が0の場合は、その軸に`0.01`を使用します。複数の関係があれば、スプリングもそれぞれ加算します。座標範囲は横`115..width-115`、縦`70..height-70`です。

カードは182×74pxで、衝突検査には軸ごとに28px間隔を加算します。

```text
overlapX = 182 + 28 - abs(xA - xB)
overlapY = 74  + 28 - abs(yA - yB)
```

両方の重なり量が正なら、重なりの小さい軸を選び、両カードを逆方向へ重なり距離の 51% ずつ移動させ、再び境界内に制限する。各力計算の後に一回実行し、150 回の反復後に衝突分離だけの追加反復は行わない。境界と反復上限があるため、すべての入力で完全に重なりを解消できるとは限らない。

## 大きな入力とナビゲーション範囲 [#큰-입력과-탐색-범위]

`boardLayout`自体には、オブジェクトが200個を超えるとグループ別格子を書く分岐があります。グループは初めて登場した順序、グループ内オブジェクトは元の順序を維持し、横250px・縦135px間隔で配置します。

現在、レンダラーは、次のいずれかが発生した場合に最初に [ナビゲーション用の部分グラフ](/ja/docs/algorithms/exploration) を作成します: **オブジェクトが 200 個を超える、リレーションシップが 1,000 を超える、イベントが 500 個を超える**。デフォルトのオブジェクト表示の上限は 200 であるため、力の計算はこのサブグラフの最初のボード配置に適用されます。グリッド分岐と実際の画面のページ制限は異なる層にあります。

3上限以内の小さなグラフは、`exploreGraph`を呼び出さずに元のグラフを直接渡します。選択や検索ごとに不要な探索投影を計算せず、検索結果の強調・ぼかし表示はキャンバスで処理します。

## Lanes: グループを熱に変える [#lanes-그룹을-열로-바꾼다]

`groups`順に列を作成し、各グループのオブジェクトを元の配列順に124ピクセルの間隔に置きます。関数自体は空のグループも列として保持します。大きなグラフのナビゲーション投影では、表示するオブジェクトのないグループを事前に除外します。

```text
width     = max(900, 그룹 수 × 254 + 40)
laneWidth = (width - 40) / max(1, 그룹 수)
x         = 20 + laneWidth × (열 번호 + 0.5)
y         = 140 + 행 번호 × 124
```

自動クラスター検出ではなく、入力の`node.group`を使用するバッチです。

## 更新と手動配置 [#갱신과-수동-배치]

Board・Laneの基本配置は`topologyKey`で、グラフID、オブジェクトID・グループ、リレーションシップの両端ID、グループIDの順序配列として作成され、ビュータイプが変わると再計算されます。名前、説明、プロパティ、またはスループットのみが変更された場合、デフォルトのバッチは再計算されません。並び順の変更にはキーの変更も含まれます。タイムラインは、イベントと日付を使用して個別に計算されます。

同じグラフIDのボードを保持している間は、新しい表示セットに残っているオブジェクトの古い座標を保持します。既存のオブジェクトの一部が欠落しても、残りのオブジェクトを最初から再配置しません。消えたIDの座標は現在のシーンから除外し、**新しく入ったオブジェクトのみ**次の順序で配置します。

1. 既存のカードの占有位置を集めます。ユーザーがドラッグしたカードは手動座標を使用します。
2. 新しいオブジェクトに接続しているオブジェクトのうち、座標を持つ最初のものを基準点とする。基準点でも手動座標を優先する。
3. 基準点周辺の6候補を順番に調べます。横230px・縦125px間隔で候補を作成し、既存占有位置と横210px・縦105px範囲が重なる候補は除外します。
4. 周囲に位置がない場合、または基準点がない場合は、5列グリッドで空の位置を見つけます。配置した新しいカードも次のカードの競合チェックに含め、シーンサイズを増やします。

その後、現在のグラフに対応する手動座標を最後に上書きします。同じボードの更新では、全力の計算は繰り返されません。別のグラフまたはLanesに切り替えると、そのビューのデフォルトの配置が計算されます。手動座標はユーザーが指定した値なので、すべてのバッチの重なりを保証するルールではありません。

ドラッグ座標はグラフID・ビュー別`localStorage`に保存します。グラフの内容やサーバーのオブジェクト識別ルールを変更しません。

## 複雑さと検証 [#복잡도와-검증]

小規模な Board の初期配置では、ソートと 150 回の対ごとの力・衝突検査を行うため、時間計算量は `O(V log V + 150(V² + E))`、追加空間は `O(V + E)` となる。大規模入力の格子分岐は `O(V)`、グループごとにオブジェクトを抽出する Lanes は `O(GV)` である。更新時には構造キー生成、既存座標と隣接リストの確認、新規オブジェクトの候補位置探索が必要となる。各候補検査で占有位置を走査するため、コストは追加オブジェクト数と格子の占有状況に依存する。
