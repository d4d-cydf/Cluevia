Clueviaの検証は、**抽出基準検査**と**グラフ契約検査**に分けられます。モデル抽出には2つの層があり、完成したJSONインポートはグラフ契約を確認します。

| 検証機 | 入力 | 確認するもの |
| --- | --- | --- |
| `parseExtraction` | 抽出結果、原文、オントロジー | 種類・属性・関係制約、引用文、識別根拠 |
| `parseGraphDocument` | 不明なJSON値 | フィールド・サイズ・日付・ID・参照 |

## 原文と抽出結果を照合する [#원문과-추출-결과를-대조한다]

`server/ontology.ts`は、引用符の`documentId`が入力データにあることを確認し、その本文に`quote`文字列が正しく含まれていることを確認します。識別子は引用符に存在する必要があり、オントロジーの基礎ベースの主キーで指定された値にも個別の検証を適用します。

たとえば、原文が`고객 번호 C-17`で、モデルが`C-18`を識別子として返すと、その引用に渡すことはできません。同じ名前が登場しても、名前だけで同じオブジェクトであることは証明されません。

保存時引用のUTF-16 開始・終了位置と分析テキストのSHA-256を記録します。同じフレーズが繰り返されると、位置候補とあいまいさが保存されます。ハッシュはテキスト識別値であり、実際には認証値ではありません。

## 許可されたグラフフィールドで新しいオブジェクトを作成する [#허용된-그래프-필드로-새-객체를-만든다]

`parseGraphDocument`は実行時に型・長さ・件数・形式を検査し、必要なフィールドだけで新しいオブジェクトを構成する。不明なフィールドはコピーしない。文字列は長さを検査してから前後の空白を除去する。

```text
최상위 객체 · 스키마 버전 · 작성 경로 · 그래프 ID
  → groups / sources / nodes / edges / events / findings 구성
  → 종류별 ID 집합과 중복 검사
  → 그룹 · 객체 · 관계 · 출처 참조 검사
  → 온톨로지 ID·버전 및 나머지 메타데이터 확인
```

チェックは最初のエラーで中止されます。選択フィールドは省略し、一般選択フィールドに`null`を入れることは省略とは異なります。ただし、`claim`内部のnullableフィールドは、契約に応じて`null`を許可します。

## IDセットで重複と参照を確認する [#id-집합으로-중복과-참조를-검사한다]

| 参考 | 検査する ID セット |
| --- | --- |
| `node.group` | グループ |
| `edge.source`, `edge.target`, `event.nodeIds`, `finding.nodeIds` | オブジェクト |
| `finding.edgeIds` | 関係 |
| すべて `sourceIds` | 出典 |

各配列内のIDは重複できません。異なる種類の配列間でグローバルな重複チェックは行われません。参照配列も内部重複を許可しません。

オブジェクトリストにAのみがあり、関係の終点がBの場合、`edge 관계ID: 존재하지 않는 ID: B`のように失敗します。自己関係など、オブジェクトのペアの複数の関係が許可されます。

## 日付と拡張フィールドを確認する [#날짜와-확장-필드를-확인한다]

日付は`YYYY-MM-DD`または秒・時間帯を含むISO時刻です。正規表現と`Date.parse`を確認し、日付部分をUTC真夜中に往復変換して`2026-02-30`のような誤った日付をろ過します。期間の終了が開始より早ければ拒否します。

| フィールド | ルール |
| --- | --- |
| `ontologyId`, `ontologyVersion` | 両方が同時に存在しなければならない。版番号は1以上の安全な整数とする。 |
| `source.contentHash`, `source.sourceFamily` | 小文字16進数64桁SHA-256形 |
| `edge.claim` | 主張態度、主体、有効期間、発行日と再引用出典検査 |

期間比較と[時間軸座標](/ja/docs/algorithms/timeline)は、タイムゾーンオフセットを反映した絶対時間を使用します。

## 単一グラフと統合ケースの境界 [#단일-그래프와-통합-케이스의-경계]

単一の`GraphDocument`はオブジェクト200個、関係500個、事件300個まで許可します。 `parseGraphText`は、JSONのUTF-8サイズも2,000、000バイト以下であることを確認します。

複数の分析記録を組み合わせたケースは、別々のサーバー投影の結果です。単一の抽出制限をケース全体に再適用しません。 `.case.json` 書き出しも一般グラフJSONとは異なる形式です。

インポートは元のファイルを最初に検証し、`origin`を`imported`に置き換えて保存します。 IDや欠落している参照をランダムに推定して検証をバイパスしません。

## 複雑さと限界 [#복잡도와-한계]

グラフ項目数を`N`、参照数を`R`、検査・コピーするテキスト量を`S`とすると、平均定数時間の集合照会を仮定する際、グラフ契約検査は`O(N + R + S)`で見ることができます。原文引用チェックの文字列検索コストは別途です。

検証の成功は、構造と原文の引用が検査規則に従うことを意味します。 出典の真偽、推論の妥当性、事実の欠落や全体のマージ精度まで判定しません。
