`GraphRenderer.tsx`의 `boardLayout`과 `lanesLayout`은 객체·관계에서 장면 크기와 카드 중심 좌표를 계산합니다. 아래 Board의 힘 계산은 최초 배치에 사용하며, 같은 Board의 후속 결과는 기존 좌표를 보존하면서 추가합니다. 화면상 거리는 신뢰도나 지리적 거리를 뜻하지 않습니다.

## 1. 차수로 순서를 정한다

Board는 관계의 양 끝에 차수를 1씩 더합니다. 객체를 **차수 내림차순 → ID의 `localeCompare` 순서**로 정렬합니다. 자기 관계는 같은 객체에 2를 더하지만 이후 스프링 계산에서는 제외합니다.

A–B와 A–C가 있으면 A의 차수는 2, B와 C는 1이므로 A부터 초기화합니다. 동률 비교는 실행 환경의 문자열 정렬 규칙에 영향을 받을 수 있습니다.

## 2. 황금각으로 초기 좌표를 펼친다

객체 수 `V`, 정렬 후 순번 `i`에 대해 다음과 같이 시작합니다.

```text
columns = max(3, ceil(sqrt(V × 1.4)))
width   = max(940, columns × 240 + 80)
height  = max(580, ceil(V / columns) × 160 + 100)
angle   = i × 2.399963229728653
radius  = sqrt((i + 0.6) / max(1, V))
x       = width / 2  + cos(angle) × radius × (width / 2 - 120)
y       = height / 2 + sin(angle) × radius × (height / 2 - 70)
```

난수 없이 중심에서 바깥으로 펼칩니다. 차수가 큰 객체는 초기에는 중심 가까이에 놓입니다.

## 3. 힘과 충돌을 150번 계산한다

| 계산 | 규칙 |
| --- | --- |
| 모든 객체 쌍의 반발력 | 거리 `d = max(1, hypot(dx, dy))`, 크기 `min(24, 11000 / d²)` |
| 관계별 스프링 | 중심 거리와 255px의 차이에 `0.012`를 곱한 힘 |
| 중심 방향 힘 | 중심까지의 가로·세로 차이에 각각 `0.004`를 곱함 |
| 좌표 이동 | 축마다 힘을 ±16px로 제한하고 장면 경계 안에 고정 |

좌표 차이가 0이면 해당 축에 `0.01`을 사용합니다. 관계가 여러 개면 스프링도 각각 더합니다. 좌표 범위는 가로 `115..width-115`, 세로 `70..height-70`입니다.

카드는 182×74px이고 충돌 검사에는 축마다 28px 간격을 더합니다.

```text
overlapX = 182 + 28 - abs(xA - xB)
overlapY = 74  + 28 - abs(yA - yB)
```

두 값이 모두 양수이면 겹침이 작은 축을 선택해 겹친 거리의 51%씩 양쪽 카드를 이동하고 다시 경계 안으로 제한합니다. 각 힘 계산 뒤 한 번 수행하며, 150회 이후 별도의 충돌 전용 반복은 없습니다. 경계와 반복 상한 때문에 모든 입력에서 완전한 무겹침을 보장하지는 않습니다.

## 큰 입력과 탐색 범위

`boardLayout` 자체에는 객체가 200개를 넘으면 그룹별 격자를 쓰는 분기가 있습니다. 그룹은 처음 등장한 순서, 그룹 안 객체는 원래 순서를 유지하며 가로 250px·세로 135px 간격으로 배치합니다.

현재 렌더러는 **객체 200개 초과, 관계 1,000개 초과, 사건 500개 초과** 중 하나에 해당하면 먼저 [탐색용 부분 그래프](/docs/algorithms/exploration)를 만듭니다. 기본 객체 표시 상한이 200개이므로 이 부분 그래프의 최초 Board 배치에는 힘 계산이 적용됩니다. 격자 분기와 실제 화면의 페이지 제한은 서로 다른 계층입니다.

세 상한 이내의 작은 그래프는 `exploreGraph`를 호출하지 않고 원래 그래프를 바로 전달합니다. 선택이나 검색마다 불필요한 탐색 투영을 계산하지 않으며, 검색 결과의 강조·흐리게 표시는 캔버스에서 처리합니다.

## Lanes: 그룹을 열로 바꾼다

`groups` 순서대로 열을 만들고, 각 그룹의 객체를 원래 배열 순서대로 124px 간격에 둡니다. 함수 자체는 빈 그룹도 열로 유지합니다. 큰 그래프의 탐색 투영에서는 표시할 객체가 없는 그룹을 미리 제외합니다.

```text
width     = max(900, 그룹 수 × 254 + 40)
laneWidth = (width - 40) / max(1, 그룹 수)
x         = 20 + laneWidth × (열 번호 + 0.5)
y         = 140 + 행 번호 × 124
```

자동 군집 탐지가 아니라 입력의 `node.group`을 사용하는 배치입니다.

## 갱신과 수동 배치

Board·Lanes의 기본 배치는 그래프 ID, 객체의 ID·그룹, 관계의 양 끝 ID, 그룹 ID의 순서 있는 배열로 만든 `topologyKey`와 보기 종류가 바뀔 때 다시 계산합니다. 이름·설명·속성·처리량만 달라지면 기본 배치를 재계산하지 않습니다. 배열 순서가 바뀌는 것도 키 변경에 포함됩니다. Timeline은 사건·날짜를 사용하는 별도 계산입니다.

같은 그래프 ID의 Board를 유지하는 동안에는 새 표시 집합에도 남아 있는 객체의 이전 좌표를 보존합니다. 기존 객체 일부가 빠져도 남은 객체를 처음부터 재배치하지 않습니다. 사라진 ID의 좌표는 현재 장면에서 제외하고, **새로 들어온 객체만** 다음 순서로 배치합니다.

1. 기존 카드의 점유 위치를 모읍니다. 사용자가 드래그한 카드는 수동 좌표를 사용합니다.
2. 새 객체와 연결된 객체 중 좌표가 있는 첫 대상을 기준점으로 고릅니다. 기준점도 수동 좌표를 우선합니다.
3. 기준점 주변의 여섯 후보를 순서대로 검사합니다. 가로 230px·세로 125px 간격으로 후보를 만들고, 기존 점유 위치와 가로 210px·세로 105px 범위가 겹치는 후보는 제외합니다.
4. 주변에 자리가 없거나 기준점이 없으면 5열 격자에서 빈 위치를 찾습니다. 배치한 새 카드도 다음 카드의 충돌 검사에 포함하고 장면 크기를 늘립니다.

이후 현재 그래프에 해당하는 수동 좌표를 최종 덮어 적용합니다. 같은 Board의 갱신에서는 전체 힘 계산을 반복하지 않습니다. 다른 그래프나 Lanes로 전환하면 해당 보기의 기본 배치를 계산합니다. 수동 좌표는 사용자가 지정한 값이므로 모든 배치의 무겹침을 보장하는 규칙은 아닙니다.

드래그 좌표는 그래프 ID·보기별 `localStorage`에 저장합니다. 그래프 내용이나 서버의 객체 식별 규칙을 바꾸지 않습니다.

## 복잡도와 검증

작은 Board의 최초 배치는 정렬과 150회의 쌍별 힘·충돌 검사로 `O(V log V + 150(V² + E))`, 추가 공간은 `O(V + E)`입니다. 큰 입력의 격자 분기는 `O(V)`, 그룹마다 객체를 필터링하는 Lanes는 `O(GV)`입니다. 갱신 시에는 구조 키 생성과 기존 좌표·인접 목록 확인, 새 객체의 후보 위치 탐색 비용이 발생합니다. 후보 검사마다 점유 위치를 순회하므로 추가 객체 수와 격자의 점유 상태에 따라 비용이 달라집니다.
