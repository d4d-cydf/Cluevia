---
title: 현재 구현 파이프라인
description: 분석 범위 확정부터 온톨로지 설계, 자료 추출, 근거 검증과 그래프 배치까지.
---

Cluevia는 자료에서 **객체·관계·사건·출처**를 추출하고, 같은 데이터를 Board·Lanes·Timeline으로 보여줍니다. 이 문서는 각 단계의 입력과 출력, 계산 규칙, 한계를 실제 구현과 연결합니다.

## 전체 처리 흐름

```text
질문 · 자료 미리보기 → 확인 질문 → 분석 범위 확정
                                    │
원본 자료 업로드 ────────────────────┤
                                    ▼
                   온톨로지 설계 또는 기존 정의 선택
                                    │
                   ┌────────────────┴─────────────────┐
                   ▼                                  ▼
            표 데이터 컬럼 매핑                  문서 구간 분석
            규칙으로 행 변환                  Codex · 선택적 Jev
                   └────────────────┬─────────────────┘
                                    ▼
                    스키마 · 식별 키 · 원문 인용 검증
                                    ▼
                    SQLite 저장 → 분석 기록별 결과 통합
                                    ▼
                       탐색 범위 선택 → 좌표 계산
                         Board · Lanes · Timeline
```

질문만 있으면 온톨로지 구조를 설계하며 실제 객체와 관계는 만들지 않습니다. 완성된 그래프 JSON과 공개 예제는 모델 추출 없이 그래프 계약을 검사해 엽니다.

## 알고리즘 읽는 순서

| 단계 | 입력 → 출력 | 핵심 질문 |
| --- | --- | --- |
| [1. 자료 구조화](/docs/algorithms/extraction) | 요청·원문 → 검증된 분석 기록 | 표와 문서를 어떻게 나누어 처리하는가? |
| [2. 데이터 검증](/docs/algorithms/validation) | 추출 결과·JSON → 유효한 그래프 | 원문 인용 검사와 참조 검사는 무엇이 다른가? |
| [3. 그래프 배치](/docs/algorithms/board-layout) | 객체·관계 → 카드 좌표 | 반발력·스프링·충돌 분리를 어떻게 조합하는가? |
| [4. 관계선과 라벨](/docs/algorithms/edge-routing) | 카드 좌표 → 곡선·라벨 | 일반 관계와 자기 관계의 경로는 어떻게 다른가? |
| [5. 시간축 배치](/docs/algorithms/timeline) | 사건의 시각·기간 → 좌표·트랙 | 시각을 정렬하고 겹치는 사건을 어떻게 나누는가? |
| [6. 검색과 캐시](/docs/algorithms/exploration) | 검색·선택 → 표시할 부분 그래프 | 전체 데이터를 보존하며 표시량을 어떻게 제한하는가? |

## 모델 판단과 코드 계산

| 단계 | 담당하는 일 | 보장 범위 |
| --- | --- | --- |
| 온톨로지 설계·문서 분석 | 유형, 속성, 관계와 근거 후보 추출 | 모델 판단이며 결과가 달라질 수 있음 |
| 구조화 자료 변환 | 검증된 컬럼 매핑으로 행 변환 | 매핑된 행마다 모델을 호출하지 않음 |
| 추출 검증 | 유형·속성·식별 키·정확한 원문 인용 검사 | 인용의 존재가 주장 자체의 진실을 입증하지는 않음 |
| 그래프 검증 | 필드, 크기, ID, 날짜와 참조 검사 | 데이터의 구조적 일관성 검사 |
| 탐색·레이아웃 | 표시 집합, 좌표, 관계선과 시간축 계산 | 저장된 자료를 표시하는 규칙 |

서버는 원문과 분석 기록을 SQLite 및 데이터 디렉터리에 보관합니다. 그래프 배치와 선택 상태는 브라우저에서 계산하고, 사용자가 드래그한 좌표는 해당 브라우저에 저장합니다.

## 구현으로 연결하기

| 구현 | 역할 |
| --- | --- |
| `server/clarification.ts`, `server/ontology-planner.ts` | 분석 범위 확인과 온톨로지 설계 |
| `server/generic-ingest.ts`, `server/analysis-pipeline.ts` | 자료 분할·매핑·모델 분석·캐시 |
| `server/ontology.ts`, `src/lib/graph-document.ts` | 추출 근거와 그래프 계약 검증 |
| `server/ontology-store.ts`, `server/analysis-case.ts` | 저장, 객체 연결과 케이스 통합 |
| `src/lib/graph-exploration.ts` | 선택 주변 확장, 검색과 페이지 선택 |
| `src/components/graph/GraphRenderer.tsx` | 카드·관계선·시간축 배치와 렌더링 |

문서는 현재 원격 앱 구현을 기준으로 합니다. 복잡도는 코드의 반복 구조를 분석한 값이며, 모델 처리 시간이나 모든 기기의 성능을 보장하지 않습니다.
