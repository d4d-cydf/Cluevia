<Abstract keywords="주장 검증 · 증거 요구 · 논리 구조 · 출처 추적 · 공백 보완">

하나의 결론을 검토하려면 자료에 무엇이 기록되어 있는지와 그 기록이 결론을 얼마나 뒷받침하는지를 구분해야 한다. Cluevia는 이러한 구분을 Why-not Tree로 표현하고, Gap Find를 통해 충족되지 않은 조건을 진단한 뒤 Gap Fill로 필요한 보완 자료를 제시한다. 이 문서군은 알고리즘의 개념적 정의, 실행 계약과 구현 범위를 함께 정리한다. 결과를 해석할 때에는 입증 경로의 완성 여부, 지지 수준과 평가 완결성을 각각 확인해야 한다.

</Abstract>

## 문서의 범위

[메인 알고리즘 지침서](/docs/main-algorithm/overview)는 문제 정의에서 방법론·평가 계획·한계까지 이어지는 기술 보고서로 구성되어 있다. 각 상세 명세는 판정 규칙과 예외 조건을 정의하며, 현재 구현 문서는 해당 계약을 실제 모듈·저장 구조·화면과 연결한다. 현재 자료의 공백 진단과 사용자 보완 경로는 구현되어 있으나, 자동 외부 수집과 수치 정책의 실증적 검증까지 완료되었다는 뜻은 아니다.

## 메인 알고리즘

```text
목표 주장과 사건 범위
       ↓
Why-not Tree: 내부는 주장·AND·OR·NOT_SUPPORT, 최하위는 증거 자료
       ↓
1-3 현재 자료로 가능한 집합 트리 생성
1-4 자료 판정 중 지지만 통과
1-5 사건 메타데이터 일치 검사
1-6 부모별 중복 자료 식별
1-7 출처·인용 계보 추적
1-8 leaf → 부모 → 전체 신뢰도 평가
       ↓
공백 사유 + 미니 그래프 + 다음 액션
       ↓
Gap Fill → 새 자료·판정 버전 → 재평가
```

NOT_SUPPORT는 부정 주장을 입증하는 자료들을 AND로 결합한다. 필요한 자료가 없거나 검토를 마치지 못한 상태를 부정 주장의 입증으로 해석하지 않는다.

## 여섯 가지 공백

| 유형 | 의미 | 보완 방향 |
| --- | --- | --- |
| `EVIDENCE_MISSING` | 필수 자료 없음 | 직접 자료 검색, 확보 불가 시 사용자 요청 |
| `EVIDENCE_INSUFFICIENT` | 해당 주장을 지지하기 부족 | 부족한 사실·조건 설명, 추가 증거 요청 |
| `EVENT_MISMATCH` | 사건 연결 규칙 불일치 | 충돌 지점과 연결 불가 설명 |
| `TRUST_WEAK` | 전체 신뢰도 기준 미달 또는 충분함 미확인 | 미니 그래프와 병목 설명, 근거 강화 |
| `PROVENANCE_UNKNOWN` | 출처 등급 D/E | 원출처 표기 요청 또는 원출처 탐색 |
| `CHAIN_UNKNOWN` | 평가 완료 후 완성 체인 없음 | 필요한 자료 유형을 포함한 체인 완성 전략 3개 |

## 현재 앱 구현과 함께 읽기

온톨로지 설계·원문 추출·SQLite 저장은 공백 진단에 필요한 자료와 근거 연결을 제공한다. 논리·판정 계약과 추출·저장 계약은 서로 다른 책임을 가지므로 각각의 구현 문서에서 검토한다.
