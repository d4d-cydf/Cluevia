应用程序是Vite·Node API ,文档是一个独立的Fumadocs·Next.js包。 我们使用Node.js **22.17或更高的**用于应用程序开发。 只运行文档包时最低版本为22.12.

## 安装和运行应用程序 [#앱-설치와-실행]

请选择 Windows PowerShell 或 WSL 中的一个运行环境，并在该环境安装依赖。

```bash
npm ci --include=dev --include=optional
npm run dev
```

应用默认地址为 `http://127.0.0.1:5173`。切换运行环境时，应先关闭现有服务器，再在目标环境中重新执行 `npm ci`。当前应用没有自动重新安装依赖的 predev 钩子。

使用新分析时，在同一环境运行 `npm run codex:login` 与 `npm run codex:status`。已保存图和公开示例无须模型连接即可打开。环境变量见根目录 `.env.example` 与 [README](https://github.com/d4d-cydf/Cluevia/blob/main/README.md)，请保留已有 `.env.local`。

## 运行文档 [#문서-실행]

运行在项目根中的单独终端。

```bash
npm run docs:install
npm run docs:dev
```

文档地址为 `http://127.0.0.1:3001`。正文位于 `docs/content/docs/**/*.mdx`，侧栏顺序由各目录的 `meta.json` 定义，首页在 `docs/components/home.tsx` 中编辑。

文档启动、构建和类型检查会先检查当前操作系统所需的可执行文件与原生模块。未安装依赖或检测到 Windows/WSL 环境切换时，才重新安装文档依赖；正常情况下不会重复安装。

```bash
npm run docs:typecheck
npm run docs:build
npm run test:docs
```

`docs:build` 将静态网站生成至 `docs/out/`，运行时不需要模型登录或 API 密钥。`NEXT_PUBLIC_CLUEVIA_URL` 指定文档中的应用链接，属于在构建时生效的公开配置。

## 应用程序构建和服务器 [#앱-빌드와-서버]

```bash
npm run build
npm start
```

构建先进行 TypeScript 检查，再生成 `dist/`。`npm start` 同时提供构建后的界面与 API；`npm run preview` 在 Vite 预览中使用相同产品 API。避免多个服务器同时打开同一数据目录。

## 测试 [#테스트]

```bash
npm test
npx playwright install chromium
npm run test:e2e
```

单元及 HTTP 测试检查数据契约、原文依据、存储、任务执行、取消、恢复与 API。需要实际模型调用的评估命令与常规测试分开运行。

| 环境变量 | 使用 |
| --- | --- |
| `PLAYWRIGHT_BASE_URL` | 使用现有服务器进行应用程序浏览器测试 |
| `DOCS_BASE_URL` | 使用现有服务器进行文件测试。 静态 `docs/out/` 服务器也是可能的 |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` | 指定测试可执行的 Chromium |

`test:docs` 使用根目录安装的 Playwright 及 `docs/playwright.config.ts`。默认启动文档开发服务器，检查搜索、文档路由、示例、移动端与主题。

修改算法文档时，应将常量、分支条件与实现链接同当前代码对照。测试通过仅说明所覆盖案例符合预期，不能据此推广到所有输入。
