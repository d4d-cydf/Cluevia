为了使差距诊断有用，其结果必须导致特定的条件，可以在随后的研究中得到证实。 补充:一个行动是对尚未满足的需求的回应，而该行动本身的执行并不能保证足够的证据。 获取的数据和改变的决定将在新的快照中重新评估。

## 共同行动合同 [#공통-액션-계약]

```ts
type FillAction = {

    | 'EXPLAIN_TRUST' | 'TRACE_SOURCE' | 'REQUEST_SOURCE' | 'PROPOSE_CHAINS';
  reason: string;
  requiredEvidence: { kinds: string[]; fields: string[]; eventScopeId: string };
  acceptanceCriteria: string[];
  status: 'PROPOSED' | 'RUNNING' | 'WAITING_USER' | 'COMPLETED' | 'FAILED';
  resultEvidenceIds: string[];
  nextEvaluationStages: string[];
};
```

LLM 生成搜索式、说明和策略；工具执行实际搜索与原文获取；代码验证返回资料、预算和状态。LLM 声称知道某份文献，不等于已经实际取得该资料。

##  EVIDENCE_MISSING · 直接搜索数据，必要时用户请求 [#evidence_missing--직접-자료-검색-필요-시-사용자-요청]

**输入：**缺少资料的 requirement、目标主张、对象与事件条件及允许的资料类型。

1. 指定必须存在哪些字段才能满足要求。
2. 创建一个搜索公式，包括标识符，周期，位置和数据类型。
3. 在互联网上直接搜索相关原文，保存 URL 与正文；支持性结果和反证均保留。
4. 仅符合标题和搜索片段的结果不被视为证据。 比较文本部分，物体和事件。
5. 如果无法获取公开数据，请记录搜索的范围和判决的基础，并向用户请求必要的数据。

“未找到搜索结果”不等于“该资料不存在”。应使用 `NOT_FOUND_WITHIN_BUDGET`、`PRIVATE_RECORD_REQUIRED`、`ACCESS_UNAVAILABLE` 等状态区分无法从互联网取得资料的原因。若已耗尽搜索预算，应明确说明仅在该搜索范围内未找到资料。

**请求示例：**“目前缺少将 O-17 与仓库入库编号关联起来的资料。需要同时载有订单号和入库编号的原始签收凭证，或订单与入库记录的对照表。”

**完成条件：**已取得资料，并形成可能满足 1-3 缺失 requirement 的候选。缺口是否真正消除，仍取决于后续 1-4、1-5、1-7、1-8 的重新评估。

##  EVIDENCE_INSUFFICIENT · 缺乏支持的描述 [#evidence_insufficient--부족한-지지-내용-설명]

**输入：**未通过的 binding、判定、原文片段与验收标准。

说明应按**资料实际记载的内容 → 目标要求确认的事实 → 两者的差异 → 仍需补充的资料**展开，不能仅使用“不可信”这一笼统表述。

**示例：**“当前邮件仅写明预计于 10 月 5 日配送。目标是证明实际交付完成，因此仅凭该邮件并不充分。还需要能够确认交付时间、接收对象和订单号的签收凭证或入库记录。”

若为反证，也须呈现原文中的反对内容。对于 `UNREVIEWED` 或模型错误，应先完成审查，不能将其表述为已经完成的证据不足判定。事件元数据为 UNKNOWN 时，应具体请求缺失字段。

**完成条件：**新增资料或复核后，对应 binding 或替代 binding 被判为 `SUPPORTED`，并通过必要的重新验证。

##  EVENT_MISMATCH ·连接不可能的描述 [#event_mismatch--연결-불가-설명]

**输入:** 失败事件规则 ID 预期的元数据和观察到的元数据。

| 显示 | 示例 |
| --- | --- |
| 我试图连接的说法 | O-17 交货完成 |
| 适用规则 | 同样的订单号码+指定仓库+交货时间 |
| 相互矛盾的项目 | 目标O-17,数据O-71 |
| 对应原文位置 | 签收凭证的订单号字段 |
| 结论 | 该签收凭证不能作为 O-17 已交付的依据 |

向用户说明当前资料无法连接，并从当前候选中排除。其他匹配目标的资料可另作新候选评估，但不能修改现有资料中的号码或日期以强行匹配。

仅缺少元数据时，应请求补充资料，不作事件冲突判定。即使确认并修正了解析错误，也须保留原版本，再使用新版元数据重跑 1-5。

**完成条件：**准确呈现当前连接不可成立的诊断。行动完成不表示目标主张已获证明或缺口已经消除。

## TRUST_WEAK · 迷你图与瓶颈说明 [#trust_weak--미니-그래프와-병목-설명]

**输入:**信任 计算追踪，阈值 ,共享源·依赖性，缺失节点。

迷你图至少应包括通向根节点的路径、形成瓶颈的主张、所用证据、关系运算子，以及各节点的分数或未知状态。AND 的其他必要条件不得隐藏，应以折叠的摘要节点保留。

```text
인도 완료 H [AND, 0.72 / 예제 기준 0.80]
├─ 인도 기록 C1 [0.90]
│  └─ 창고 원본 로그 E1
└─ 주문 연결 C2 [0.80] ← 이 연결의 근거를 강화해야 함
   └─ 주문–입고 연결표 E3
```

**说明示例：**“交付记录与订单关联两项条件都必须满足。当前分数模型得到 0.90×0.80=0.72。新增转载同一日志的文章并不构成独立证据，因此不能提高支持程度。需要核实订单与入库关联的原始编号对照记录。”

<ResearchDiagram kind="bottleneck" number="G2" />

图 G2 对应[完整运行示例](/zh/docs/main-algorithm/worked-example)中的运行 C。在同一 AND 模型下，若只改变一个子分数，可得到以下敏感度。

<Equation number="G1" label={"固定物体的本地敏感性 AND 模型"} tex={String.raw`\begin{aligned}s(H)&=s(C_1)s(C_2)\\\frac{\partial s(H)}{\partial s(C_1)}&=s(C_2),\qquad\frac{\partial s(H)}{\partial s(C_2)}=s(C_1)\end{aligned}`} />

该导数表示公式对输入变化的敏感度，不是实际补充行动的效果预测。新增资料若依赖其他观测或改变逻辑结构，就不能直接复用相同计算。

若条件允许，应按“降低哪项 requirement 的哪种不确定性”比较候选行动。没有相应模型时，不得把预期分数增幅当作确定值展示。若区间过宽源于独立性未知，应优先核查观测来源与路径，而不是单纯增加资料数量。

**完成条件：**新增证据、谱系或依赖性核查后的重新评估确认已达到阈值。降低阈值须记录为独立策略版本，不能与补充证据混同。

## PROVENANCE_UNKNOWN · 标注或寻找原始来源 [#provenance_unknown--원출처-표기-또는-찾기]

**输入:**D/E数据，确认的谱系，停止跟踪的原因。

明确原发布机构、作者、首次发布地址、发布日期、引用页码与记录标识符中缺少的项目。存在引用 URL 时，在 1-7 预算内追踪原始来源；网上无法取得时，请用户补充其掌握的原始出处。

**示例：**“附件图片未标注原报告名称及发布机构。请提供报告原文 URL、发布机构、对应页码或原始文件。”

不能仅因填写了 URL 就提高来源等级。应核对原文与资料内容是否一致，并验证转引路径。即使找到原始来源，主张支持性和事件一致性仍须分别评估。

**完成条件：**谱系核查与来源重新评级解决 D/E 问题，并完成相关候选的复核。

## CHAIN_UNKNOWN · 三种链完成策略 [#chain_unknown--체인-완성-전략-3개]

**输入：**通往根节点的完整链为 0、评估已完成、原因缺口列表与原始逻辑式。

在保留最终目标与必要条件的前提下，提出**三种**不同的资料取得策略。尚不存在的资料与关联须标为计划，不能画成已经发现的事实。

| 战略示例 | 首先要寻找的材料类型 | 预期的连接 | 适合的情况 |
| --- | --- | --- | --- |
| 1. 直接原始记录 | 签收凭证、原始交易记录、业务系统台账 | 在同一文档中核查事件结果与目标标识符 | 原始记录可访问时 |
| 2. 按时序交叉核查 | 发货、入库、签收日志及标识符对照表 | 保持目标键，连接事件前后环节 | 缺少单份完整资料时 |
| 3. 结合独立观测 | 其他机构记录、直接观测资料、独立保存的凭证 | 连接同一对象或事件的独立资料 | 现有资料集中于转引来源时 |

每项策略须包含 `requiredEvidence`、`closedGapIds`、`remainingGaps`、`eventJoinRules`、`sourceIndependenceNeeds` 和 `availability`。并非每个案例都存在三条可行路径。对于不可行的策略，应说明原因及所需访问条件，不能编造来源来凑足数量。

提出原树之外的替代逻辑时，标为 `proposedTreeRevision`，另行审查是否足以支持同一目标。不能删除原有 AND 必要条件来制造完整链。

**完成条件：**向用户提供三种策略及资料请求。真正消除该缺口，还需执行策略并重新确认完整链。

## 对多种证据缺陷的优先和重叠行动 [#여러-공백의-우선순위와-중복-액션]

优先解释阻断 ROOT 的具体缺口，再展示被排除 OR 替代路径的局部缺口。`CHAIN_UNKNOWN` 策略应引用具体原因。同一原文可同时补足资料与来源时，将多个 gap ID 关联到同一行动。

建议优先事项，包括数据可访问性的原因，必须满足的基本需求数量，预期减少不确定性以及实施成本。 这并非自动表达为准确的实用数字。

## 迭代与终止 [#반복과-종료]

```text
액션 실행 → 후보 자료 등록 → 새 snapshot
  → Gap Find 재실행 → 이전 gap과 비교
```

新增输入哈希、判定与谱系均未变化时，不重复相同请求。补充循环状态单独管理，例如需用户资料时为 `WAITING_USER`，达到预算时为 `PAUSED_BY_BUDGET`，要求满足时为 `RESOLVED`；不扩展既定的六类 GapType。

Gap Fill 受有限的 `maxRounds`、搜索次数、URL 数、时间与费用预算约束。须区分无法取得资料与未能证明主张；没有新增资料时，不能自动宣告缺口已解决。
