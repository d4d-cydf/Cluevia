<Abstract keywords={"証拠に基づく推論 · Why-not Tree · 根拠の欠落の診断 · 出典の系譜 · 不確実性"}>

資料間の関係を抽出するだけでは、特定の結論に至るために何が不足しているかを説明できない。Clueviaは、検証対象の主張を論理条件と証拠要件に分解し、現在の資料が要件を満たしていない箇所を構造的に診断する。提案手順は、Why-not Treeの構成、Gap Findによる証拠の候補組合せの評価、Gap Fillによる補完要求の生成からなる。資料の存在、主張に対する適合性、事件の整合性、出典の確認、支持の程度を分けて評価し、同一の観測を再利用した資料を独立した根拠として重複計上しない。本書では、その形式的な契約と実装範囲を記述する。数値は明示したモデルと方針の下での支持スコアであり、別途の較正なしに結論が真である確率とは解釈できない。

</Abstract>

## 1。はじめに [#1-서론]

証拠をレビューする際の難しい問題は、データの量自体ではなく、データと結論の間の論理的な距離です。たとえば、納品予定の通知は納品の実際の完了を検証するものではなく、同じプレスリリースを再引用する複数の記事は複数の独立した観察と同等ではありません。オブジェクトや関係が正確に抽出された場合でも、これらの違いが表現されない場合、画面上のつながりの密度が結論の妥当性であると誤解される可能性があります。

Cluevia が扱う質問は次のとおりです。 **目標 主張 をサポートするパスは、指定されたデータと明示的な推論ルールに基づいて確立されていますか?それが確立されていない、またはまだ確認できない場合、どのような条件でどのようなデータが必要になるのか。** したがって、システムの主な出力は、単一の結論ステートメントではなく、一連の証拠の関連性、評価ステータス、根拠の欠落 の理由、および 補完 の要求です。

この設計の核心は3つの分別である.一,資料の存在と当該主張に対する支持を分離する.二,一つの代替経路が失敗した場合と目標主張全体の立証経路がない場合を分離する.三,検証を完了し得られた不合格判断と資料・合同予算の制限として判断を保留した状態を分離する.この分別は根拠欠乏の説明だけでなく,後の資料収集の範囲を決定するために必要である.

## 2。問題の定義と表記 [#2-문제-정의와-표기]

検証する目標主張をH、現在確保されている資料集合をE、論理構造をT、判定・事件・信頼度政策をΠと表記する。一度の評価は、これらの入力のバージョンを固定したsnapshotに対して行われます。評価中に確保した新資料は、次のsnapshotの入力で登録する。

| シンボル | 意味 |
| --- | --- |
| H | 対象・行為・期間・範囲が明示された目標 主張 |
| E | 実際の本文または検査可能な記録区間を確保したデータセット |
| T | 主張・証拠要件・論理演算子で構成した有向非循環構造 |
| b | 資料の特定区間と証拠要件を連結したbinding |
| F(v) | ノードvのニーズを満たすように構成できる候補bindingセットのコレクション |
| W | 適合性・事件・出典の各判定を通過した立証経路の集合 |
| G | 段階・原因・影響範囲を含む欠落記録の集合 |
| s(v) | 指定された方針に従う支持スコア。未だのときは null |
| Π | 判定規則、信頼度仮定、しきい値、探索予算とそのバージョン |

**定義1 - 証拠要件と証拠資料。**証拠要件はどのような事実が確認されるべきかを記述し、証拠資料はこれを検討できる実際の記録を指す。要求が存在するという事実は、資料が確保されたという意味ではない。本文を読んでいないURL、ファイル名、または検索結果のタイトルだけで証拠リーフを構成しないでください。

**定義 2 — binding.** 適合性判定の単位は、データ全体ではなく、データ区間と特定要求の連結である。同じ文書がある主張には十分な根拠であり、他の主張には不十分かもしれないからだ。 bindingには引用位置、判定、理由と判定バージョンを一緒に保存する。

Tは画面でトリとして展開できるが,同じデータや観測を複数の場所で参照しているため,保存と計算では共有構造を持つDAGとして扱われる.主張依存性の循環は許されない.出典の引用関係で発見された循環は別々のアカウントグラフに記録し,検索を終了する.具体的なタイプと参照規則は, [木構造モデルとデータ契約](/ja/docs/main-algorithm/model) 定義されている.

### 3.1。目標主張と論理構造の構成 [#31-목표-주장과-논리-구조의-구성]

質問を検証可能な主張に正規化した後、その主張が成立するために必要なサブ条件を記述する。この時、元の質問より弱い主張を代わりに検証してはならない。 「引き渡された」と「引き渡される予定と通知された」は別々の主張だ。

各内部ノードには、AND、OR、NOT_SUPPORTのいずれかの演算子と明示的な推論規則を付与する。ANDはすべての必須条件の充足を、ORは少なくとも一つの適格な代替経路を要求する。NOT_SUPPORTは、**否定命題を立証する証拠のAND結合**と定義する。検索で見つからなかったことを否定の証拠とする規則でも、余事象の確率を計算する演算でもない。

LLMは子です 主張 過引用判定を提案する。参照の有効性、原文の引用、論理構造、最終計算はコードによってチェックされます。この役割分担は、モデルの意味解釈を活用しながらも、自由記述が検証手続きを迂回しないようにするためのものである。

### 3.2。現在の資料で可能な候補の構成 [#32-현재-자료로-가능한-후보의-구성]

ステップ1-3では、現在確保されているbindingのみを使用する。 ORノードの候補は子候補の和集合であり、ANDノードの候補は各子の候補を1つ選択して組み合わせた組み合わせである。下でcᵢは子ノード、wᵢはその子の候補を意味する。

<Equation number="1" label={"ANDとORの候補の組み合わせ"} tex={String.raw`\begin{aligned} F_{\mathrm{OR}}(v)&=\bigcup_i F(c_i)\\ F_{\mathrm{AND}}(v)&=\left\{\bigcup_i w_i\;\middle|\;w_i\in F(c_i)\;\forall i\right\}\end{aligned}`} />

<CandidateMatrix number="3" />

まだ資料がない必須要求の候補集合は∅だ。 ANDの必須子一つが∅なら親の候補も∅となる。これを空の証拠だけで成立する候補の一つである`{∅}`と混同してはならない。不十分な条件を排除してANDを弱めるための処理も許可されていません。

ルート候補を構成できない場合でも、すでに存在するデータの局所診断は保存できます。例えば、他の必須条件の資料が欠落している状態でも、提出された予定通知が完了主張を立証できないという事由は残る。局所診断の存在と完成した立証経路の存在は区別して報告する。

| --- | --- | --- |

| 最終確認 | 評価完結性とパス | 評価を完了したが完成経路がない場合は、`CHAIN_UNKNOWN`を記録する。 |

*表1。 Gap Findの判定手順。各ステップの詳細規則は[Gap Findステップバイステップルール](/ja/docs/main-algorithm/gap-find)に従います。

資料が不適格であれば、その資料を必須とする候補を除外する。ORの他の代替経路は評価を続け、反証と除外理由を元の記録に残す。`UNREVIEWED`、モデル呼出しの失敗、事件メタデータの不明を、評価済みの反証判定に置き換えてはならない。

重複検査では、データ数よりも観測の同一性が重要である。同じ原文を移動した2つの文書は2つのファイルですが、1つの観測を共有することができます。 LLMの重複提案は原文と判定の理由により検討し、同一観測で確認された場合は共有アトムに連結する。

### 3.4。 出典の系譜と信頼度集計 [#34-출처-계보와-신뢰도-집계]

新しい資料の条件付き尤度比が 1 なら、当該モデルでは既存の観測に基づく相対的な支持は変化しない。そのため既存資料を保持し、新資料を独立した支持として加算しない。尤度比が 1 以外なら引用系譜を確認し、原出典の確認条件を満たすか有限予算に達した時点で終了する。推定モデルがない場合は 1 に置き換えず、不明と記録する。尤度比の解釈にはモデル選択と不確実性の検討が必要である。[Lund と Iyer、2017](https://doi.org/10.6028/jres.122.027)。

下記の信頼度の積算式は、子ノードの支持の不確実性を独立に扱えるモデルに限って適用する。直列・並列信頼性モデルでも、独立性は計算を正当化する条件である。[NIST 直列モデル](https://www.itl.nist.gov/div898/handbook/apr/section1/apr182.htm)、[NIST 並列モデル](https://www.itl.nist.gov/div898/handbook/apr/section1/apr183.htm)。

<Equation number="2" label={"独立性仮定の下の支持スコア集計"} tex={String.raw`\begin{aligned}s_{\mathrm{AND}}(v)&=\prod_i s(c_i)\\s_{\mathrm{OR}}(v)&=1-\prod_i\bigl(1-s(c_i)\bigr)\end{aligned}`} />

<ResearchPlot kind="support-curves" number="5" />

出典URLが異なるだけでは独立性を認めない。とくに`(a AND b) OR (a AND c)`の二つの経路はaを共有するため、経路のスコアに独立なORを適用できない。a、b、cが相互に独立した観測で、スコアがそれぞれ0.8、0.7、0.6という説明用モデルでは、共有変数を保持した値は0.704となる。経路同士を独立とみなすと0.7712となり、過大に集計される。

この図は計算構造を説明するための例です。製品方針で定められた出典・データ係数を組み合わせても、その値が修正確率になるわけではありません。独立性が不明瞭な場合、または係数が不明な場合は、仮定に一致する保守的な範囲または null が返されます。リネージ終了ルールとセクション計算は[出典の系譜と信頼度](/ja/docs/main-algorithm/confidence)で指定します。

### 3.5。 Gap Fillと再評価 [#35-gap-fill과-재평가]

Gap Fillは、一般的な追加検索を繰り返す手順ではありません。各根拠の欠落から欠落した条件を導出し、その条件を検査できる資料の形態・識別子・期間・出典を要求する。次の表のアクションは設計上の対応関係であり、外部インターネットの自動検索・原文収集は現在の実装範囲と区別しなければならない。

| 根拠の欠落 | 補完の対象 | 対応アクション |
| --- | --- | --- |
| `EVIDENCE_MISSING` | 空の必須要件 | 直接資料を検索し、公開確保が難しい場合は必要な資料を要請する。 |
| `EVIDENCE_INSUFFICIENT` | 資料が満たしていない事実・条件 | 原文の内容と目標の違いを説明し、追加の証拠を要求する。 |
| `EVENT_MISMATCH` | 接続ルールに矛盾する値 | 不一致な対象・視覚・場所などを提示し、当該連結の不適格を説明する。 |
| `TRUST_WEAK` | 支持レベルのボトルネック | 足りない接続をミニグラフで表し、補完根拠を要求する。 |
| `PROVENANCE_UNKNOWN` | 未確認円出典 | 元出典の表記を要求するか、検証可能な系譜を探索する。 |
| `CHAIN_UNKNOWN` | 目標まで完成していないルート | 必要なデータタイプを含むチェーン完成戦略の3つを提示します。 |

*表2。 根拠の欠落タイプと補完要求の対応。

検索や資料追加だけで欠落が解消したとは判定しない。新資料は別バージョンで存在、適合性、事件、出典、信頼度の検査を再び通過する必要がある。目標や論理構造を変更した場合は資料補完と区別し、ツリーバージョンも更新する。[Gap Fill：補完アクション](/ja/docs/main-algorithm/gap-fill)に各アクションの入力、完了条件、終了規則を定める。

## 4。結果の解釈と計算上の制約 [#4-결과의-해석과-계산상의-제약]

評価結果は、**立証経路の状態、支持の程度、評価の完結性**という三つの軸で読む必要がある。経路が完成していても、支持の程度が基準に届かない場合がある。一方、評価が未完了であれば、経路がまだ見つかっていないことから、経路が一切存在しないとは結論できない。いずれの状態も、それだけで対象の主張が偽であることを意味しない。

<ResultMatrix number="6" />

候補列挙の費用は論理の分岐数に依存する。m個の必須条件がそれぞれk個の選択肢を持つ単純なAND–OR構造でも、最大kᵐ個の組合せが生じる。親pの下にあるdₚ個の資料について全組を比較すると、比較回数はdₚ(dₚ−1)/2となる。共有atomを持つ重み付き論理評価も、最悪の場合には大きな計算費用を要する。これらは組合せ構造の費用を説明する式であり、実測の実行時間が常にその上限に比例するという主張ではない。

<Equation number="3" label={"互いに区別される代替組合せと親別比較ペア"} tex={String.raw`\begin{aligned}|F(H)|&=\prod_{i=1}^{m} k_i\quad(=k^m\text{ if }k_i=k)\\N_{\mathrm{pairs}}(p)&=\binom{d_p}{2}=\frac{d_p(d_p-1)}{2}\end{aligned}`} />

<ResearchPlot kind="candidate-growth" number="7" />

したがって、候補・状態・訪問・深さ予算を明示し、予算到達時に未評価の範囲を残す。キャッシュと遅延の評価はコストを削減する手段ですが、必須のニーズを削除したり、未完了を完了に変更したりすることはできません。すでに確認された経路の存在は報告することができるが、経路の不在を確定するためには、その判断に必要な評価を完了しなければならない。

## 5。実装範囲と検証 [#5-구현-범위와-검증]

### 5.1。現在の実装の範囲 [#51-현재-구현의-범위]

現在の実装では、完了または失敗した事例のアーカイブデータに基づいて論理構造と引用の決定を提案し、候補の評価、根拠の欠落の作成、全文検索、ユーザー補完、契約検証後のバージョンの再評価を実行します。 出典の系譜 は、snapshot で登録された接続内をチェックします。外部検索プロバイダーによる自動収集と Web 全体の 出典 追跡は実装されていません。

自動論理生成には限られた抜粋が使用されるため、データ全体を読んだと仮定しません。 出典 係数・閾値・独立性も検討可能な入力仮定で管理する。モジュール別の責任とAPI、必須収容事例は、[実施順序と検査基準](/ja/docs/main-algorithm/implementation)にまとめられている。

### 5.2。評価設計 [#52-평가-설계]

アルゴリズムの契約検証と実際のデータの意味判断精度は別々に評価しなければならない。前者は固定 snapshot の再現可能な検査で確認できる。後者は、判定基準を明示した評価資料とは独立した検討が必要である。次の項目は評価計画であり、まだ報告されていない精度や改善率を意味しません。

| 評価の質問 | 観察項目 | 比較と制御 |
| --- | --- | --- |
| 前提条件の欠落を正しく見つけるか | 根拠の欠落タイプ・影響範囲・原因経路の一致 | 正解条件を指定した AND/OR/NOT_SUPPORT ケース |
| 未完了を不在と誤認しないか | 評価状態とチェーン状態 | 予算消耗・未検討・読み取り失敗を注入した事例 |
| 重複観測がスコアを上げないか | 共有アトム数と支持スコアの変化 | 同一原文の複製・再引用前後比較 |
| イベントリンクルールを保存するか | 期待値・観測値・不一致事由 | 同一名称・異なる識別子と視覚衝突事例 |
| 実際の判断は妥当ですか？ | 適合性・反証・根拠の欠落の検討者一致度 | 別々の実資料評価、不一致の調整手順 |
| 使用コストが許容範囲か | 段階別遅延・呼出数・トークン・キャッシュヒット | 資料規模・形式・モデル・政策を固定した繰り返し実行 |

[完全な実行例](/ja/docs/main-algorithm/worked-example)は資料追加による候補と根拠の欠落の変化を示す構成事例だ。例のスコアとしきい値は説明用であり、実証評価の結果として使用しません。

### 5.3。補助処理時間の観察 [#53-보조-처리-시간의-관찰]

リポジトリには、評価に先立つ**オントロジー設計とスキーマ検証だけを測定した単一入力の観測記録**がある。188 文字入力で旧 high 設定の設計は約 121.9 秒、medium と簡潔なスキーマ・プロンプトを用いた実行は約 84.1 秒だった。同じ設計入力のキャッシュ再利用は、追加モデル呼び出しなしで約 1.67 ms と記録された。抽出全体や Gap Find の所要時間、意味判定の精度を測定した結果ではない。

この比較では複数の設定を同時に変更し、比較対象も過去の実行を用いている。観測差を effort 単独の効果とみなしたり、他の入力の処理時間予測に使ったりすることはできない。測定範囲と再利用条件は[オントロジー設計・抽出](/ja/docs/algorithms/extraction)に示す。原数値と制約はリポジトリの `docs/evaluations/ontology-design-medium-cache.json` に保存している。

## 6。議論と限界 [#6-논의와-한계]

最初に検討すべき制限は、論理構造自体の適切性です。誤って設計された証拠要件について正確に計算しても、その結果が元の質問に対する適切な答えになるわけではありません。したがって、推論規則と出来事の範囲を読み、修正することができなければならず、モデルによって提案された構造はレビューの対象から除外されない。

第二の限界は、観測と出典の依存性である。形式や発行主体が違っても同じ観測を共有する場合があり、一文書内に共有部分と独立観測が共存する場合もある。区別を確認できなければ、単一スコアの精密さより、不明状態と範囲を正直に示すことを優先する。

第三の限界は数値の解釈にある。出典の等級や資料品質の係数は、それ自体では統計的な推定量ではない。真である確率として用いるには、別途のモデル化、較正、検証用データが必要である。本書は、その検証が完了したとは主張しない。

最後に、根拠の補完は必ず成功するとは限らない。非公開記録、アクセス不能な原文、復元不能な時刻情報は、未確認のまま残ることがある。その場合は結論を強制せず、残った条件と探索範囲を説明する。

## 7。結論 [#7-결론]

Cluevia はデータの関係を示すだけでなく、目標 主張 に至るまでに必要な接続やまだ満たされていない条件を記録します。このアプローチの実際的な意義は、判断の根拠を追跡し、次の検討対象を特定することです。今後の評価では、論理設計と意味決定の実際の精度、支持スコアの解釈可能性、調査プロセスにおける補完の要求の有用性をそれぞれ検証する必要があります。
