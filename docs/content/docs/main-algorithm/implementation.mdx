설계 명세가 실행 가능한 시스템으로 이어지려면 의미 판단, 계약 검증, 상태 관리와 수치 계산의 책임을 구분해야 한다. 이 절은 해당 책임을 실제 모듈과 연결하고, 재현 가능한 실행과 검수에 필요한 조건을 정리한다. 현재 자료와 사용자 보완을 사용하는 실행 경로는 구현되어 있으며, 입력에 포함된 URL은 실제 읽기 결과를 보존한다. 외부 검색 공급자를 통한 자동 검색과 웹 전체의 출처 계보 추적은 별도의 범위다. 정책 제안의 구현 여부와 실증적 타당성도 구분해야 한다.

## 구현된 실행 경로

새 케이스의 입력 원문과 URL 읽기 결과를 저장한 직후 `JobManager.onInputsReady`가 기본 Why-not 그래프 생성을 예약한다. 온톨로지 설계·객체 추출과 병렬로 진행하며, 완성된 기본 그래프는 주 분석 중에도 Overview에 표시한다. 자동 Cluevia 진단은 기본 그래프 저장과 주 분석 완료가 모두 확인되어야 시작한다. 객체가 없는 실패 케이스의 원래 기록과 이미 저장한 기본 그래프도 보존하며, 실패한 주 분석을 완료로 취급하지 않는다.

보존된 기록 검색 결과가 없으면 저장된 입력 원문을 제한된 크기로 사용한다. URL 문자열은 연결된 페이지의 본문으로 취급하지 않는다. 비어 있는 요구조건은 `EVIDENCE_MISSING`, 실제 제출 자료가 해당 조건을 입증하지 못하면 `EVIDENCE_INSUFFICIENT`로 표시한다. AND의 다른 조건이 비어 전체 입증 경로를 만들 수 없어도, 존재하는 자료의 부족 사유는 함께 남긴다. 이를 위해 가짜 증거나 입증 경로를 생성하지 않으며, 조사 범위가 불완전하면 판정 완결성과 점수에 적용한 가정을 함께 남긴다.

1. `mode: baseline`은 목표·조건·사건 규칙과 실제 원문의 인용 연결만 제안한다. 서버가 ID·구간·참조를 검사하여 `UNREVIEWED` 기본 snapshot을 먼저 저장한다.
2. `graph-ready + awaitingAnalysis`이면 기본 그래프를 표시하며 주 분석 완료를 기다린다. `baselineInputHash`로 질문·보존 원문·업로드 입력의 동일성을 확인하고 최종 분석 버전을 연결한다. 진행률 변경은 원문 변경으로 처리하지 않는다.
3. `mode: review`는 저장된 binding ID의 자료 판정·메타데이터와 같은 부모의 중복만 검토한다. Claude Low가 미평가 사전확률·우도비·출처 등급을 추정한 뒤 서버가 공백과 점수를 계산한다. 수동 평가를 덮어쓰지 않으며 모델 추정은 `MODEL_ESTIMATE`로 구분한다. [고정 출처 계수와 보정 우도비](/docs/main-algorithm/confidence)를 사용하고 운영 임계값·독립성을 임의로 확정하지 않는다.
4. 공백에서 현재 원문을 검색하거나 공개 검색 링크를 직접 열 수 있다. 사용자 보완 자료는 현재 논리에 연결한 뒤 새 버전으로 평가한다.
5. 과거 버전과 원문은 보존된다. 보고서는 Markdown, 논리·판정·점수 추적을 포함한 전체 진단은 JSON으로 다운로드한다.

| 실제 파일 | 책임 |
| --- | --- |
| `src/types/why-not.ts` | 버전 snapshot, binding, witness, gap, action 계약 |
| `server/why-not-contract.ts` | 입력 상한·트리 참조·인용 위치·사건 메타데이터 검사 |
| `server/why-not-phases.ts` | 기본 구조 생성과 저장된 연결의 판정 요청 분리, 불변 인용·참조 검사 |
| `server/why-not-estimation.ts` | 미평가 수치·출처의 모델 추정 계약, 인용 검증, 수동 입력 보존 |
| `server/why-not-bayes.ts` | 고정 등급 계수, 목표 우도비 결합, 보정 전·후 점수와 계산 이력 |
| `server/why-not-engine.ts` | 후보 조합, 적격성, 공유 atom 계산, 보수적 범위, 공백·액션 생성 |
| `server/why-not-service.ts` | 조기 기본 그래프 예약, 주 분석 완료 대기, SQLite 버전 저장, 보완·취소·재시작 복구 |
| `src/components/WhyNotPanel.tsx` | 논리 구조·공백·원문 검색·검토·보완·버전·보고서 화면 |

### API

모든 경로는 기존 워크스페이스 인증과 케이스 범위를 따른다.

| 메서드·경로 | 동작 |
| --- | --- |
| `GET /api/jobs/:id/why-not` | 최신 진단과 최근 50개 버전 목록 |
| `POST /api/jobs/:id/why-not` | `{ goal, previousId }`로 비동기 생성, 또는 `{ supplement: { name, text, url }, previousId }`로 자료 보완 |
| `GET /api/jobs/:id/why-not/runs/:runId` | 보존된 버전 원문·결과 조회 |
| `POST /api/jobs/:id/why-not/evaluate` | `{ snapshot, previousId }` 계약 검증 후 새 평가 저장 |
| `POST /api/jobs/:id/why-not/cancel` | 진행 중인 검증 중단 |
| `GET /api/jobs/:id/why-not/search?q=...` | 케이스 원문 및 이미 추가한 보완 자료 검색 |

`previousId`가 최신 버전과 다르면 409를 반환한다. 동일 원문 재보완은 거절하고, 변경 없는 검토 저장은 기존 버전을 반환한다. 완료된 버전은 덮어쓰지 않으며 케이스 삭제 시 함께 삭제한다. GET은 모델 호출을 시작하지 않는다. 서버 재시작 시 완성된 기본 snapshot은 유지하고 주 분석 완료 조건을 다시 확인한 뒤 진단을 재개한다. 기본 그래프 저장 전 중단과 입력 변경은 실패 상태와 사유를 남긴다. 실패·취소한 준비 작업을 자동으로 무한 재시도하지 않는다.

### 현재 제한

- 자동 생성은 최대 10개, 각각 최대 10,000자의 실제 원문 발췌를 사용하므로 `coverage.complete=false`로 기록한다. 초기 업로드 자료는 각 파일의 첫 chunk를 사용하며, 보이지 않은 나머지 자료가 없다고 단정하지 않는다.
- 출처 계보 추적은 snapshot에 등록한 자료·인용 연결 안에서 수행한다. 외부 URL을 자동 방문하지 않는다.
- 계보·사건 메타데이터·논리 상세 수정은 고급 JSON 검토를 사용한다. 변경은 서버 검증을 통과해야 저장된다.
- 출처 등급의 계수는 제품 정책으로 고정하며 모델 추정 수치는 인용·추정 이력을 남긴다. 운영 임계값과 독립성 가정도 검토 가능한 입력으로 보존한다. 출력은 실측으로 보정된 진실 확률이 아니다.
- 모델의 논리 설계·의미 판정 품질과 실제 서비스 지연은 별도의 실자료 평가가 필요하다. 자동 테스트의 모델 응답은 대역을 사용한다.

## 책임 분리

| 역할 | LLM의 책임 | 코드의 책임 |
| --- | --- | --- |
| 트리 작성 | 하위 주장·증거 요구·추론 연결 제안 | 계약, 순환, 필수 조건, 버전 검증 |
| 적합성 | 원문을 읽고 enum·사유·인용 제안 | 참조·구간·허용 enum·필수 사유 검사, 지지 관문 |
| 사건 일치 | 메타데이터와 근거 위치 추출 | 확인된 값으로 규칙 검사; UNKNOWN 보존 |
| 중복 | 문맥상 같은 관측인지 판정 | hash 검사, 판정 검증, 대표·의존성 관리 |
| 계보 | 인용 후보와 자료 유형 제안 | 실제 원문 확보, URL 방문·예산, 계보 검증 |
| 신뢰도 | 평가 근거 설명 | 정책값·수식·공유 변수·범위·임계값 계산 |

LLM이 낸 자유 서술만으로 체인 완성이나 최종 수치를 확정하지 않는다. 같은 자료가 다른 주장을 지지하는지 판단할 때는 부모 주장과 요구 조건을 함께 제공한다.

## 실행 의사코드

아래는 제어 흐름을 설명하는 의사코드다. 실제 구현은 후보 폭증을 피하도록 지연 평가할 수 있지만, 각 단계의 의미와 탈락 사유는 유지해야 한다.

```text
function gapFind(snapshot, tree, policy):
    validateTreeAndPolicy(tree, policy)
    run = freezeVersions(snapshot, tree, policy)
    diagnostics = []

    candidates, completeness = buildExistingWitnesses(tree, snapshot) // 1-3
    if candidates is empty:
        recordMissingRequirements(diagnostics)
        return finalize(run, candidates, completeness, diagnostics)

    candidates = checkSupportPerBinding(candidates, snapshot, diagnostics) // 1-4
    candidates = checkGlobalEventRules(candidates, policy, diagnostics)    // 1-5
    candidates = deduplicateWithinParents(candidates, diagnostics)         // 1-6

    provenance = traceSourcesWithBudgets(candidates, policy, diagnostics)  // 1-7
    queueNewEvidenceForNextSnapshot(provenance.discoveredEvidence)
    candidates = applySourceEligibility(candidates, provenance, diagnostics)

    dependencies = buildSharedAtomGraph(tree, candidates, provenance)
    confidence = evaluateOriginalLogic(tree, candidates, dependencies, policy)
    recordWeakTrustWhereApplicable(confidence, diagnostics)               // 1-8
    return finalize(run, candidates, completeness, diagnostics, confidence)

function finalize(run, candidates, completeness, diagnostics, confidence=null):
    collectPendingDecisionsAndInterruptedStages(completeness)
    completeChains = candidates with all required eligibility gates passed
    if completeChains is empty and completeness is COMPLETE:
        add CHAIN_UNKNOWN referring to detailed blocking gaps
    else if completeChains is empty:
        chainStatus = UNDETERMINED
    else:
        chainStatus = COMPLETE_CHAIN_FOUND
    return persistRunResult(run, diagnostics, chainStatus, confidence)

function gapFill(result, policy):
    actions = mergeCompatibleActions(dispatchByGapType(result.gaps))
    executeBoundedReadActions(actions, policy)
    requestUserEvidenceWhenNeeded(actions)
    if inputsChanged() and roundBudgetRemains():
        return gapFind(newSnapshot(), currentTreeVersion(), policy)
    return currentResultWithActionStatus()
```

최종적으로 기준을 충족했다고 표시하려면 ROOT를 막는 공백과 직접 반증의 검토 보류가 없어야 한다. 점수가 높더라도 `CONTRADICTORY_EVIDENCE`가 미해결이면 검토 필요 상태를 유지한다.

분기 하나가 탈락해도 다른 OR 대안의 평가를 계속한다. 자료가 현재 처리 중이거나 판정 호출이 실패한 경우 완결성을 낮추며, 모든 자료를 검사해서 탈락시킨 것처럼 처리하지 않는다. 이미 확인된 완성 체인은 다른 대안이 미완료여도 존재 사실을 보고할 수 있다.

## 모듈 간 결과 계약

| 단계 결과 | 반드시 남길 필드 |
| --- | --- |
| 후보 생성 | requirement별 사용 binding, 선택한 OR 가지, 생략 없이 유지된 AND 요구 |
| 적합성 | binding별 enum·사유·인용·판정 버전·완료 여부 |
| 사건 검사 | 규칙 ID·버전, 기대값·관측값, MATCH/MISMATCH/UNKNOWN |
| 중복 검사 | 비교 단위 부모, 판정 쌍, 대표 자료, atom, 병합 근거 |
| 계보 검사 | 방문 URL·자료, 검증된 연결, LR 종류·값·모형, 종료 코드 |
| 신뢰도 | 노드별 식과 입력, 공유 atom, 가정, 점수·구간·null, 임계값 |
| 공백 | 단계·유형·reasonCode, 영향 범위, 관련 후보와 원인 gap |
| 보완 | 액션·검색 기록·자료 요구, 결과 후보, 재평가 단계, 종료 사유 |

작업·API·UI에서 같은 enum을 공유한다. 판정값과 원문 인용이 불일치하거나 필수 사유가 없으면 schema 오류로 반환하고 검토 보류로 남긴다. 형식 오류를 자동으로 지지 판정으로 보정하지 않는다.

## 캐시와 재평가

캐시 키에는 자료 hash만 넣지 않는다. 다음 요소가 달라지면 해당 단계 결과를 재검사한다.

```text
부모 주장·requirement + 원문 구간·자료 버전
+ 사건 범위·규칙 버전 + 트리 버전
+ 판정 enum·프롬프트·모델 버전 + 출처·신뢰도 정책 버전
```

주장 A에 대한 판정을 주장 B에 그대로 재사용하지 않는다. 새로운 자료가 같은 부모의 중복 묶음이나 전역 의존성을 바꿀 수 있으므로 해당 binding의 상위 노드만 단순 갱신하면 충분하다고 가정하지 않는다. 영향을 받는 중복 그룹·계보·공유 atom과 루트 계산을 재평가한다.

삭제 대신 새 버전을 만들고 이전 결과와 연결한다. 원문, 탈락 트리, 반증, 실패 호출과 중단 원인을 보존해야 동일 입력의 결과를 재현할 수 있다.

위 표기는 캐시의 개념적 의존성을 요약한다. 실제 키에는 해당 모듈의 판정에 영향을 주는 모델·프롬프트·스키마 버전도 포함해야 한다. 서로 다른 주장의 binding을 자료 ID가 같다는 이유만으로 동일하게 취급하지 않는다.

## 결과 화면의 최소 요구

화면은 목표 주장, 전체 평가 상태, 완성 체인 수 또는 확인 여부, 신뢰도·범위·미상, 기준, ROOT를 막는 공백과 다음 액션을 보여준다. 원문·판정 사유·기대/관측 메타데이터·신뢰도 계산 trace를 열 수 있어야 한다.

TRUST_WEAK 미니 그래프는 원래 전체 트리의 요약이다. 표시에서 접은 필수 조건을 계산에서도 빼지 않는다. CHAIN_UNKNOWN의 전략 3개는 확보된 사실 그래프와 구분해 계획임을 표시한다.

## 구현 권장 순서

1. 트리·requirement·binding·판정·gap 계약과 버전 저장을 만든다.
2. 모델 없이 고정 fixture로 1-3 집합 생성과 AND·OR·NOT_SUPPORT 전파를 완성한다.
3. 1-4의 적합성 판정 연결과 1-5 사건 규칙을 추가한다.
4. 1-6 중복 판정, 전역 atom 공유와 1-7 계보 추적을 추가한다.
5. 1-8 독립 계산·공유 변수·의존성 미상 처리와 trace를 구현한다.
6. 여섯 Gap Fill 액션, 미니 그래프와 체인 전략, 유한 재평가 루프를 연결한다.
7. 고정 사례와 실제 자료의 판정 일치도·잘못된 병합·공백 누락·수치 보정을 별도로 평가한다.

문서의 수식 사례만 맞는 것으로 실제 자료에서의 근거 판정 정확성을 검증했다고 말하지 않는다.
