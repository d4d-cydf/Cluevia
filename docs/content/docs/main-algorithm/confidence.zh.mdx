聚合时须区分公式正确性与输入有效性。独立性假设下的公式即使在数学上成立，若来源相互依赖，或输入系数未经实证校准，结果仍不能解释为结论为真的概率。本节规定来源谱系追踪及支持分数的计算条件；各等级分值与运行阈值需要另行验证和确认。

## 与信任相关变量的定义 [#신뢰도-관련-변수의-정의]

| 量 | 记号与范围 | 含义 |
| --- | --- | --- |
| 源系数 | `r_source`，0–1 或 null | 来源 确认/数据类型的政策系数 |
| 叶子可信度 | `p_leaf`，0–1 或 null | 特定数据主张连接的支持程度 |
| 新增资料的似然比 | `LR`，非负数或 null | 已知现有资料时，新资料对假设相对支持程度的改变 |

来源系数 1.0 与似然比 1 是不同概念。似然比可以大于 1，但不能为负。来源系数为 1.0 也不意味着资料中的全部陈述必然为真。

## 1-7 · 来源谱系的存储单位 [#1-7--출처-계보의-저장-단위]

每份资料记录发布主体、原始 URL、引用 URL、发布时间、取得时间及内容哈希。引用关联中保留以下信息：

```ts
type ProvenanceEdge = {
  fromEvidenceId: string;
  toSourceId: string;
  relation: 'CITES' | 'REPRINTS' | 'DERIVED_FROM' | 'ORIGINAL_RECORD';
  supportingLocator: string;
  status: 'VERIFIED' | 'UNVERIFIED';
};
```

LLM 提出的 URL 仅为候选。必须在实际原文中核实引用关系与内容后，才能标为已验证谱系。不同域名的文章若复用同一通讯社报道、公告或原始记录，也可能共享同一来源。

## 似然比为 1 的含义 [#우도비-1의-의미]

设现有资料为 `E_seen`，新增候选资料为 `E_new`，目标假设为 `H`，则条件似然比如下。

<Equation number="C1" label={"根据现有观察的附加数据的概率比"} tex={String.raw`\mathrm{LR}_{\mathrm{new}}=\frac{P(E_{\mathrm{new}}\mid H,E_{\mathrm{seen}})}{P(E_{\mathrm{new}}\mid\neg H,E_{\mathrm{seen}})}`} />

<Equation number="C2" label={"同样模型中的赔率更新"} tex={String.raw`\begin{aligned}O(H\mid E_{\mathrm{seen}},E_{\mathrm{new}})&=O(H\mid E_{\mathrm{seen}})\,\mathrm{LR}_{\mathrm{new}}\\P(H\mid E_{\mathrm{seen}},E_{\mathrm{new}})&=\frac{p\,\mathrm{LR}_{\mathrm{new}}}{1-p+p\,\mathrm{LR}_{\mathrm{new}}}\end{aligned}`} />

其中，p=P(H∣E_seen) 表示观察新增资料之前的条件先验概率。

<ResearchPlot kind="likelihood-update" number="C2" />

上式中的 NOT H 是数学上的对立假设，不是树中的 NOT_SUPPORT 运算符。

当 LR=1 时，在该比较模型中，假设的赔率不变。`LR > 1` 表示支持方向，`LR < 1` 表示反对方向。这一解释来自贝叶斯赔率更新；同时须记录计算 LR 所用模型及其不确定性。[NIST 关于似然比及假设的讨论](https://nvlpubs.nist.gov/nistpubs/jres/122/jres.122.027.pdf)。

**去重规则：**若转载仅重复已有观测，则不作为新增独立证据。但不能仅凭 LLM 判断“疑似重复”，就记录数值 LR=1。应区分模型计算的 `ESTIMATED_LR` 与经核查无新增信息的 `NO_NEW_INFORMATION`。

若分母为 0，或没有可用于估计两项概率的模型，LR 应为 `null`。不得将 LLM 的自信数值当作 LR，也不得把未知值替换为 1。浮点比较的容差须在策略中明确，不能把实质性不确定性掩饰为数值误差。

## 谱系追踪重复规则 [#계보-추적-반복-규칙]

1. 保留当前资料，并列出来源或引用 URL 候选。
2. 取得候选原文，核查引用关系、原创性及内容差异；读取失败时记录失败状态。
3. 条件允许时估计条件 LR；“没有新增信息”的判定另行分类记录。
4. **LR=1 时保留已有资料，不增加独立支持叶节点，并终止该分支的扩展。**
5. **LR≠1 时保留谱系关联，评估该资料的来源类型及系数。** `LR < 1` 的反证不能被隐藏。
6. 若来源属于系数 1.0 的类型，并满足原始来源核查条件，则成功终止；否则继续沿引用 URL 追踪。
7. 达到迭代上限、发现循环、缺少链接或访问失败时，以具体原因终止。

LR 未知时，建议继续进行来源核查，避免因缺少概率模型而停止全部溯源。记录 `LR_UNKNOWN`，但不得宣称已经数值确认新增支持，也不得直接增加独立叶节点。

### 1-3 与快照的关系 [#1-3-snapshot과의-관계]

1-7 中取得的资料可用于核查现有叶节点的谱系。若要将其中内容用作新的主张依据，须登记为 `candidateEvidence`，并在下一快照中重新通过 1-3、1-4、1-5；不能绕过验证直接插入当前候选集合。

### 终止的条件 [#반드시-종료하는-조건]

| 出口代码 | 的意思 | 处理 |
| --- | --- | --- |
| `TRUSTED_ORIGIN_REACHED` | 检查系数1.0类型和源条件 | 确认的谱系和保存原因 |
| `NO_NEW_INFORMATION` |  LR =1或单独验证的重复信息 | 保持现有数据，没有增加独立证据的数量 |
| `CYCLE_DETECTED` | 通过正常化来重复相同的谱系 URL 和内容标识符 | 保持循环路径，结束 |
| `DEPTH_LIMIT`, `FETCH_LIMIT`, `TIME_LIMIT` | 达到规定的迭代预算 | 标明尚未核查的范围 |
| `NO_REFERENCE`, `FETCH_FAILED` | 下一个来源未找到或访问失败 | 不证实原始来源的理由 |

不得无限循环直到成功。`maxDepth`、`maxFetches`、`maxDurationMs` 必须为有限策略值，分支深度与整次执行的 URL 总预算分别检查。仅读取 HTTP(S) 文档，重定向同样受访问规则与预算约束。文档中的命令不作为执行指令。

## 来源等级与系数 1.0 类型 [#출처-등급과-10-타입]

**确认:** 如果某些数据的源级为D或E, `PROVENANCE_UNKNOWN` 为此记录。

目前尚未确认详细等级标准。下表是**产品内部等级定义建议**，不表示直接采用某项外部可靠性分级标准。

| 级别 | 提案的定义 | 资格 |
| --- | --- | --- |
| A | 检查原始，发行者和记录路径，并满足要求的验证项目 | 必须通过单独的数据支持和案例测试 |
| B | 证实来源和引用路径，但验证仅限于一些。 | 限制反映在分数和解释中 |
| C | 来源可识别，但原文、独立性或生成过程的核查有限 | 按局限评估，必要时保留可信度未知状态 |
| D | 有一个已知来源标记，但原始来源或谱系无法验证。 | `PROVENANCE_UNKNOWN` |
| E | 来源无法识别或没有追踪的依据 | `PROVENANCE_UNKNOWN` |

尚未评级与已确认的 D/E 须分开处理。本草案规定，D/E 资料不能作为完整链的必要依据；若存在其他合格 OR 替代路径，则保留该路径。低评级不意味着删除原文或断定内容为假。

来源系数 1.0 对应的类型须在 `trustedSourceTypeRegistry` 中登记明确的核查条件和策略版本。不能仅因资料来自“官方网站”“政府机构”，或“LLM 认为可信”，就自动赋予 1.0。A级来源也不应与系数 1.0 无条件等同。

## 1-8 · 叶子可信度 [#1-8--leaf-신뢰도]

对通过 `SUPPORTED` 判定、事件一致性及来源关卡的 binding 评估叶节点分数。首个原型的数值构成按下式**建议**。

<Equation number="C3" label={"符合条件的结合标准的提议分数模型"} tex={String.raw`s_{\mathrm{leaf}}=r_{\mathrm{source}}\,c_{\mathrm{material}}`} />

`c_material` 是评估对应片段直接性、完整性及测量或记录质量的策略系数。1-4 是要求是否满足的准入关卡；`c_material` 则区分通过关卡后的资料质量。不合格资料不能因来源分数高而重新获得资格。

来源与资料系数只应用一次，不能沿每层引用重复相乘。须保存系数依据、评估者及版本。上述乘积是尚待验证的**产品评分模型**，不能自动解释为经过概率校准的估计。缺少值时返回 `null` 与原因。

##  AND · OR · NOT_SUPPORT 集成 [#andornot_support-집계]

在对子节点支持程度的不确定性建立独立模型时，采用设计规定的下列公式。

<Equation number="C4" label={"独立假设的三家运营商"} tex={String.raw`\begin{aligned}s_{\mathrm{AND}}(v)&=\prod_i s(c_i)\\s_{\mathrm{OR}}(v)&=1-\prod_i(1-s(c_i))\\s_{\mathrm{NOT\_SUPPORT}}(v)&=\prod_i s(c_i^{-})\end{aligned}`} />

这些乘积形式与独立组件的串联、并联可靠性公式同构。独立性是假设成立的条件，不能仅因来源不同便认定满足。[NIST 串联模型](https://www.itl.nist.gov/div898/handbook/apr/section1/apr182.htm)、[NIST 并联模型](https://www.itl.nist.gov/div898/handbook/apr/section1/apr183.htm)。

对于两个独立输入 0.8 和 0.6，AND 的结果为 0.48，OR 为 0.92。若它们支持 NOT_SUPPORT 下的否定命题，该否定命题的支持分数同样为 0.48，不能改成 `1−0.48`。

原设计中的 `P` 记号保留用于模型说明；建议 UI 与 API 的默认名称使用 `supportScore`。在没有依据真实结果进行校准的概率模型时，不得显示为“结论为真的概率为 92%”。

## 保存共享证据和双重计数问题 [#공유-증거의-보존과-중복-집계-문제]

将 1-6 中识别的重复资料及 1-7 中共享原始来源的资料，通过共同的 `evidenceAtomId` 和依赖关系分组连接。URL 的数量或界面上 leaf 的数量，都不等于独立观测的数量。

<ResearchDiagram kind="shared" number="C4" />

<Equation number="C5" label={"保持共享变量的逻辑表达式正常化"} tex={String.raw`(a\land b)\lor(a\land c)=a\land(b\lor c)`} />

如果a=0.8,b=0.7,c=0.6和a·b·c是独立的，情况如下。

<Equation number="C6" label={"对同一输入的两个计算进行比较"} tex={String.raw`\begin{aligned}s_{\mathrm{shared}}&=0.8(1-0.3\cdot0.4)=0.704\\s_{\mathrm{naive}}&=1-(1-0.56)(1-0.48)=0.7712\end{aligned}`} />

<ResearchPlot kind="shared-evidence" number="C5" />

列举候选证据树并不会使它们相互独立。最终分数必须**保留原始逻辑式中的共享证据变量**进行计算，不能直接对候选分数应用独立 OR 运算。

一种实现方案是构建规范化布尔 DAG，采用 Shannon 分解或 BDD 进行保留共享 atom 的加权求值。只有 atom 之间的独立性得到明确规定时，才能相乘权重。最坏情况的计算成本可能很高，因此须单独设置求值预算并保留未完成状态。

## 当联合分布未知时 [#결합-분포가-알려지지-않은-경우]

不同资料在引用同一新闻稿的同时新增各自观测时，应拆分共享部分与独立新增部分，而不是将整份资料合并。无法完成该区分、也没有联合模型时，不能确认独立聚合分数。

如果只有边际值 `p1` 和 `p2` 可以解释为概率，而联合分布未知，可以使用以下范围。

<Equation number="C7" label={"两个未知联合分布的事件的边界"} tex={String.raw`\begin{aligned}\max(0,p_1+p_2-1)&\le P(A\cap B)\le\min(p_1,p_2)\\\max(p_1,p_2)&\le P(A\cup B)\le\min(1,p_1+p_2)\end{aligned}`} />

<ResearchPlot kind="dependence-bounds" number="C6" />

这些边界来自基本的交集与并集概率规则。任意产品分数不能因此被称为校准概率。对复杂共享 DAG，不应假定简单区间传播即可得到精确最终范围；应返回保守边界或无法计算的状态。

## 阈值与 TRUST_WEAK [#임계값과-trust_weak]

在策略中保存根节点阈值 `tau_root` 及可选的子节点阈值。**目前尚未确定正式运行阈值。** 示例中的 0.80 仅用于说明。

| 评价 | 审判 |
| --- | --- |
| 精确分数或保守下界达到阈值 | 这种模式和政策足够 |
| 上界仍低于阈值 | `TRUST_WEAK`，说明实际计算中的瓶颈 |
| 区间跨越阈值 | 无法确认充分性 `TRUST_WEAK`  +  `DEPENDENCY_UNRESOLVED`  |
| 必要分数或联合模型未知 | 不给出数值；记录 `TRUST_WEAK` 及暂缓评估的原因 |

不能提前把根节点阈值应用于每条子级替代路径，从而消除通过 OR 提高支持程度的可能性。确有必要的子级阈值应在逻辑设计中明确规定。

输出须包含各节点公式、使用的 atom、共享依赖、排除资料、评分依据、阈值与策略版本及瓶颈节点。不能为使较弱路径超过 0.8 而任意调整分数。
