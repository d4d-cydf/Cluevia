For a design specification to result in a viable system, the responsibilities of semantics, contract verification, state management, and numerical computation must be separated. This section links the responsibilities to the actual module and sets out the conditions necessary for reproducible execution and verification. The current data and execution path using user supplementation are implemented. External search providers, automatic collection of original text, and HTTP redirect tracking are not yet connected, and the implementation and empirical feasibility of policy proposals must be reviewed separately.

## Implemented Execution Path [#구현된-실행-경로]

Used when opening **Base Diagnosis** in a completed or failed case. Even for failure cases without objects, a separate gap diagnosis version can be saved while maintaining the original failure record. Analysis that is running or waiting does not start diagnosis.

If no archived record search results are found, the saved original input text is used in a limited size. URL strings are not treated as the body of the linked page. Empty requirements are marked as `EVIDENCE_MISSING`, and if the actual submitted data does not prove the conditions, they are marked as `EVIDENCE_INSUFFICIENT`. Even if the other conditions of AND are empty and the entire supporting path cannot be created, the reason for lack of existing data is also left. To this end, we do not create fake evidence or supporting path, and if the scope of the investigation is incomplete, the judgment and score are kept unconfirmed.

1. When you enter claim to be verified, the stored excerpt of the original text is searched, and the model suggests logic, citation judgment, event rule, and direct duplicate judgment.
2. The server checks the textual citations and contracts and evaluates AND·OR·NOT_SUPPORT candidates, event checks, duplicate observations, source gates, and support score.
3. source Grades, coefficients, quality scores, and thresholds are not automatically confirmed. Once you enter the review grounds and save, it will be reevaluated as a new version. If there is no basis for independence, a conservative range is used.
4. You can search the current original text in evidence gap or open the public search link directly. User supplementation data is connected to the current logic and evaluated as a new version.
5. Past versions and original text are preserved. The report is downloaded as Markdown, and the entire diagnosis, including logic, judgment, and score tracking, is downloaded as JSON.

### API [#api]

All paths follow existing workspace authentication and case scope.

| Method/Path | action |
| --- | --- |
| `GET /api/jobs/:id/why-not` | List of latest diagnostics and most recent 50 versions |
| `POST /api/jobs/:id/why-not` | Asynchronous creation with `{ goal, previousId }`, or data supplementation with `{ supplement: { name, text, url }, previousId }` |
| `GET /api/jobs/:id/why-not/runs/:runId` | Search the original text and results of the preserved version |
| `POST /api/jobs/:id/why-not/evaluate` | `{ snapshot, previousId }` Save new assessment after verifying contract |
| `POST /api/jobs/:id/why-not/cancel` | Interruption of ongoing verification |
| `GET /api/jobs/:id/why-not/search?q=...` | Search original case text and already added supplementation data |

If `previousId` is different from the latest version, 409 is returned. Reprinting the same original text supplementation is rejected, and reviewing and saving without changes returns the existing version. Completed versions are not overwritten and are deleted together when deleting a case. When the server restarts, the diagnosis in progress is changed to failed status and the previous snapshot is preserved.

### current limit [#현재-제한]

- Automatic generation uses up to 10 excerpts, so they are recorded as `coverage.complete=false`. Do not assume that there is no unseen data.
- source provenance tracking is performed within the data/citation connection registered in snapshot. Do not automatically visit external URLs.
- Detailed modifications to genealogy, event metadata, and logic use advanced JSON review. Changes are not saved until they pass server verification.
- source Score, threshold, and independence are user input assumptions. The output is not a calibrated truth probability.
- The quality of the model's logical design/semantic judgment and actual service delay require separate evaluation of actual data. Model responses in automated tests use bands.

## Executable pseudocode [#실행-의사코드]

Below is pseudocode explaining the control flow. Actual implementation may be evaluated delayed to avoid candidate explosion, but the meaning of each step and reasons for elimination must be maintained.

```text
function gapFind(snapshot, tree, policy):
    validateTreeAndPolicy(tree, policy)
    run = freezeVersions(snapshot, tree, policy)
    diagnostics = []

    candidates, completeness = buildExistingWitnesses(tree, snapshot) // 1-3
    if candidates is empty:
        recordMissingRequirements(diagnostics)
        return finalize(run, candidates, completeness, diagnostics)

    candidates = checkSupportPerBinding(candidates, snapshot, diagnostics) // 1-4
    candidates = checkGlobalEventRules(candidates, policy, diagnostics)    // 1-5
    candidates = deduplicateWithinParents(candidates, diagnostics)         // 1-6

    provenance = traceSourcesWithBudgets(candidates, policy, diagnostics)  // 1-7
    queueNewEvidenceForNextSnapshot(provenance.discoveredEvidence)
    candidates = applySourceEligibility(candidates, provenance, diagnostics)

    dependencies = buildSharedAtomGraph(tree, candidates, provenance)
    confidence = evaluateOriginalLogic(tree, candidates, dependencies, policy)
    recordWeakTrustWhereApplicable(confidence, diagnostics)               // 1-8
    return finalize(run, candidates, completeness, diagnostics, confidence)

function finalize(run, candidates, completeness, diagnostics, confidence=null):
    collectPendingDecisionsAndInterruptedStages(completeness)
    completeChains = candidates with all required eligibility gates passed
    if completeChains is empty and completeness is COMPLETE:
        add CHAIN_UNKNOWN referring to detailed blocking gaps
    else if completeChains is empty:
        chainStatus = UNDETERMINED
    else:
        chainStatus = COMPLETE_CHAIN_FOUND
    return persistRunResult(run, diagnostics, chainStatus, confidence)

function gapFill(result, policy):
    actions = mergeCompatibleActions(dispatchByGapType(result.gaps))
    executeBoundedReadActions(actions, policy)
    requestUserEvidenceWhenNeeded(actions)
    if inputsChanged() and roundBudgetRemains():
        return gapFind(newSnapshot(), currentTreeVersion(), policy)
    return currentResultWithActionStatus()
```

To finally indicate that the criteria have been met, there must be no pending reviews of evidence gap and direct counterevidence blocking ROOT. Even if the score is high, if `CONTRADICTORY_EVIDENCE` is unresolved, the status requiring review remains.

If a branch is eliminated, evaluation of other OR alternatives continues. If data is currently being processed or a decision call fails, completeness is lowered, and all data is not processed as if it had been inspected and rejected. A completed chain that has already been confirmed can report its existence even if other alternatives are incomplete.

## Inter-module outcome agreement [#모듈-간-결과-계약]

| step result | Fields that must be left |
| --- | --- |
| Candidate Generation | Use by requirement binding, selected OR branch, AND request maintained without omission |
| suitability | binding enum, reason, citation, judgment version, completion status |
| case prosecutor | Rule ID/version, expected value/observed value, MATCH/MISMATCH/UNKNOWN |
| duplicate check | Comparison unit parent, judgment pair, representative data, atom, basis for merging |
| genealogy check | Visit URL/data, verified connection, LR type/value/model, exit code |
| confidence | Expression and input for each node, shared atom, assumption, score·interval·null, threshold |
| evidence gap | Stage/type/reasonCode, scope of influence, related candidates and cause gap |
| supplementation | Action/search history/data request, result candidate, re-evaluation stage, reason for termination |

Tasks, API, and UI share the same enum. If there is a discrepancy between the judgment value and the original text citation or there is no required reason, it is returned as a schema error and left on hold for review. Formal errors are not automatically corrected for support decisions.

## Cache and Revaluation [#캐시와-재평가]

The cache key does not contain only the data hash. If any of the following factors change, the results of that step are reexamined:

```text
부모 주장·requirement + 원문 구간·자료 버전
+ 사건 범위·규칙 버전 + 트리 버전
+ 판정 enum·프롬프트·모델 버전 + 출처·신뢰도 정책 버전
```

The decision for claim A is not reused as is for claim B. Since new data may change duplicate bundles or global dependencies of the same parent, it is not assumed that simply updating only the parent node of the corresponding binding is sufficient. Reassess affected duplicate group, lineage, shared atom and root calculations.

Instead of deleting, create a new version and link it to the previous result. Original text, dropout tree, counterevidence, failure calls and interruption causes must be preserved to reproduce the results of the same input.

<Equation number="I1" label={"Version dependency for decision reuse"} tex={String.raw`K_b=\operatorname{hash}(b,\,v_E,\,v_T,\,v_D,\,v_{\mathrm{event}},\,v_{\mathrm{trust}})`} />

The above notation summarizes the conceptual dependencies of the cache. The actual key must also include the model, prompt, and schema versions that affect the decision of that module. binding of different claim are not treated identically just because their data IDs are the same.

## Minimum Requirements for Results Screen [#결과-화면의-최소-요구]

The screen shows the goal claim, overall evaluation status, number of completed chains or confirmed, confidence·scope/unknown, criteria, evidence gap blocking ROOT, and the next action. You must be able to open the original text, reason for decision, expectation/observation metadata, and confidence calculation trace.

TRUST_WEAK minigraph is essentially a summary of the entire tree. Necessary conditions folded from the display are not excluded from the calculation. The three strategies of CHAIN_UNKNOWN are distinguished from the secured fact graph to indicate that they are plans.

This table is the acceptance criteria for the entire design. Execution verification is performed in `server/why-not-engine.test.ts`, `server/why-not-service.test.ts`, and `tests/why-not.spec.ts`. It deals with combining·evidence gap·Shared observation·Visual comparison·sourceGateway·Suspension·Version preservation·Data supplementation·Report download. External HTTP redirect validation for T18 is not currently in scope. The judgment quality, external search success rate, and large-scale operational load of the actual model are not claim verified by this test.

## Recommended order of implementation [#구현-권장-순서]

1. Create a tree·requirement·binding·judgment·gap contract and version storage.
2. Complete the 1-3 set creation and AND·OR·NOT_SUPPORT propagation with a fixed fixture without a model.
3. Add the conformance decision connection of 1-4 and the 1-5 event rule.
4. Adds 1-6 duplicate determination, global atom sharing, and 1-7 lineage tracking.
5. 1-8 Implements independent calculations, shared variables, unknown dependency processing, and trace.
6. It connects the six Gap Fill actions, a minigraph, a chain strategy, and a finite revaluation loop.
7. The judgment consistency, incorrect merging, evidence gap omission, and numerical correction between fixed cases and actual data are evaluated separately.

Just because the formula in the document is correct does not mean that the accuracy of the basis judgment has been verified on actual data.
