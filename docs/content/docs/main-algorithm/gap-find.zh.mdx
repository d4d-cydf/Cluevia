description: "通过检查合适性，事件匹配和重复情况来构建候选证据树并诊断证据缺口的步骤细节。"
---

差距发现的目的是评估可以从当前数据中构建的支持路径，并解释为什么每个路径应该保持或排除。 目前除外的是特定主张的候选组合，而不是原始数据本身。 因此，一个替代方案的失败，整个目标的缺乏支持途径以及不完整的评估必须在不同的状态下保持。 下面的程序体现了这一原则，每个步骤都有输入和决策规则。

<ResearchDiagram kind="gates" number="F1" />

## 1-1 · 固定目标和事件范围 [#1-1--목표와-사건-범위-고정]

将问题改为可测试的主张，并设定目标，行动，时间，地点和条件。 不要用一个较弱的结论取代用户所要求的结论。

在 `EvidenceNeed` 中记录检验目标所需的项目与判定标准。区分事件发生时间和资料发布时间，未知字段保持未知。若目标或逻辑关联本身尚不明确，应先完善逻辑设计，再判断是否缺少证据。

## 1-2 · 构建 Why-not Tree [#1-2--why-not-tree-생성]

LLM 提出子主张、证据要求及运算符候选。代码检查 ID、引用、循环、空逻辑节点和必要要求。每条内部关联都须提供 `inferenceRule`，说明子条件满足时为何能够支持父主张。

不能仅根据资料数量推断运算子。缺少证据的要求也应保留。依据[已确定的否定命题证明规则](/zh/docs/main-algorithm/model)，将 NOT_SUPPORT 规范化为 AND。

## 1-3 ·从现有的叶子中创建候选证据树 [#1-3--존재하는-leaf로-집합-트리-생성]

仅使用当前快照中实际存在、内容可检验且引用有效的正文或记录片段。只有 URL 而未取得正文，或文件尚未处理完成，均不视为已取得实际证据。

将节点 `v` 的候选集合族记为 `F(v)`。下述集合的元素是与 requirement 关联的 binding，而非仅仅是资料 ID。

<Equation number="F1" label={"候选人组成的基本条件"} tex={String.raw`F(b)=\{\{b\}\},\qquad F(r_{\mathrm{missing}})=\varnothing`} />

<Equation number="F2" label={"欧盟 OR 和组合 AND "} tex={String.raw`\begin{aligned}F_{\mathrm{OR}}(v)&=\bigcup_{i=1}^{n}F(c_i)\\F_{\mathrm{AND}}(v)&=\left\{\bigcup_{i=1}^{n}w_i\;\middle|\;w_i\in F(c_i)\right\}\end{aligned}`} />

NOT_SUPPORT 的候选构造规则与 AND 相同。

对于 `AND(OR(a,b), c)`，候选组合为 `{a,c}` 和 `{b,c}`。若缺少 c，则没有候选组合。不能因为 a 或 b 仍然存在，就将表达式弱化为 `AND(a)`。

<WitnessExplorer number="F2" />

<Callout title={"空集合和空候选之间的区别"}>
`∅` 表示没有可行候选，`{∅}` 表示存在一个无需证据即可成立的空候选。需要证据的主张不得生成 `{∅}`。不能直接套用编程中“空 AND 为真”的约定来判断证据。
</Callout>

根候选集合为空时，记录 `EVIDENCE_MISSING` 及缺失要求路径，并停止该次执行的证据链求值。可以另外保留局部诊断，但不能将其标为已通过后续阶段的完整候选。

当可能的组合过多时，采用惰性生成并设置上限。达到上限应标记为 `INCOMPLETE`，不得据此断定“没有完整链”。初期实现中，若候选组合满足 requirement 的关联方式不同，不能仅通过简单的子集比较将其删除。

## 1-4 ·每个数据的主张支持性 [#1-4--각-자료의-주장-지지-적합성]

对每个 binding，读取对应父主张及 `acceptanceCriteria`，再应用资料判定。只有 `SUPPORTED` 通过，其余判定连同理由排除。未审查状态与模型错误须记录为未完成，与已判定为反证的情况区分。

| 检查 | 示例 |
| --- | --- |
| 这个主题与主张相同吗? | 资料对应的是订单“O-17”，还是名称相似的另一笔订单？ |
| 在数据中所呈现的事实是否足够强大? | 你是否区分了规划/计划和实际完成? |
| 原始部分真的存在吗? | 这句话是从原本文中引用的吗? |
| 是否满足推理规则要求的条件？ | 是否将单纯相遇误当作货物转移？ |
| 是否保留了否定、推测与转引关系？ | 是否将“曾作出否认”误当作事实上的不存在？ |

<Equation number="F3" label={"在适用性检查点之后留下的候选人"} tex={String.raw`F_{\mathrm{fit}}(v)=\{w\in F(v)\mid\forall b\in w,\;\operatorname{verdict}(b)=\mathrm{SUPPORTED}\}`} />

对象与时间等具体事件关联另在 1-5 检查；1-4 已发现的不足理由仍须保留。

### 按父运算符传播不合格判定 [#부모-연산자에-따른-부적격-판정의-전파]

| 父节点 | 不合格子节点的处理 |
| --- | --- |
| AND | 排除所有必须依赖该子节点的候选，原始树中的必要要求仍予保留 |
| OR | 仅排除该替代路径，继续检查其余路径；全部失败时父节点才不合格 |
| NOT_SUPPORT | 与 AND 相同。不能将缺少证据或不合格判定转化为对否定命题的证明。 |

每次排除均记录判定值、原文片段及未满足要求，生成 `EVIDENCE_INSUFFICIENT`。反证即使退出支持候选，也保留在诊断与用户界面中。

## 1-5 · 整个候选证据树的事件一致性 [#1-5--집합-트리-전체의-사건-일치]

检查同一候选证据树中的资料是否构成**同一事件或明确指定的事件间关系**。不能仅因名称或词语相似就将记录拼接起来。

### 事件元数据协议 [#사건-메타데이터-계약]

| 字段 | 比较标准 |
| --- | --- |
| `entityRefs` | 已识别对象及其事件角色；仅名称相同不足以确认 |
| `eventType` | 行为或关系类型。区分下单、发货、到达和签收。 |
|  `occurredAt` 或时间 | 包括实际发生时间和时区，不确定性和精度 |
| `locationRefs` | 位置 ID 或指定包含/移动关系 |
| `recordKeys` | 连接密钥，如订单号码，交易号码等 |
| `publishedAt`, `observedAt` | 存储与发生时分开 |
| `metadataEvidence` | 能够核查字段值的资料与位置 |

LLM 推测的值不能视为已确认值。各事件类型的连接规则须按版本管理。

### 规则类型 [#규칙-종류]

- `SAME_EVENT`：必要标识键、角色与行为一致，并满足时间区间存在**整体公共交集**等规则。
- `ORDERED_EVENTS`：前后事件保持相同目标键，并满足规定时序；不要求不同事件同时发生。
-  `SAME_ENTITY` : 即使事件时间不同，也可以满足定义的相同对象连接规则。

A–B 和 B–C 两组资料分别重叠，并不意味着 A–B–C 整体一致。例如，时间区间 `[1,3]`、`[3,5]`、`[5,7]` 的相邻区间彼此相接，但三者不存在共同时间点。

<EventIntervals number="F3" />

<Equation number="F4" label={"关闭时间间隔的总交叉"} tex={String.raw`\bigcap_i [\ell_i,u_i]\ne\varnothing\quad\Longleftrightarrow\quad\max_i\ell_i\le\min_i u_i`} />

该公式适用于统一时区与精度后的闭区间。开放边界或容差须在事件规则中另行规定。

| 结果 | 处理 |
| --- | --- |
| `MATCH` | 保留候选人 |
| `MISMATCH` | 排除该候选并记录 `EVENT_MISMATCH`，同时保存冲突字段、期望值与观测值。 |
| `UNKNOWN` | 不能确认支持链；记录缺失元数据，生成 `EVIDENCE_INSUFFICIENT` 并保持待定 |

不能将 UNKNOWN 改为 MISMATCH。只有实际不一致才能解释为无法连接。资料本身仍予保留，因为它可能适用于其他主张或事件。

## 1-6 · 以父节点为单位检查重复资料 [#1-6--부모-단위-중복-자료-검사]

以父节点为比较单位，检查各证据 binding 的重复性。LLM 判断它们是否以相同内容支持同一事件或主张，是部分重叠，还是独立观测。

1. 先用相同内容哈希、记录 ID 等识别完全重复的资料。
2. 将同一父节点下其余候选的相关片段、事件元数据与原始来源交给 LLM 判定。
3. 要求给出原文位置和理由，由代码验证响应结构与引用。
4. 仅将已确认的 `EXACT_DUPLICATE` 或 `SAME_OBSERVATION` 归入同一 evidence atom。
5. 保留 `PARTIAL_OVERLAP`、`DISTINCT` 与 `UNKNOWN`，不任意删除疑似重复资料。
6. 只有要求满足信息也相同的候选，才合并为代表候选。被归并资料保留 `duplicateOf` 与理由。

代表资料按原文可访问性、片段完整性、ID 顺序等版本化规则选择。不能只留下高分资料而删除反证。

LLM 对两个资料作出的“相似”判定不保证具有传递性。不能仅凭 A≈B、B≈C 就合并 A、B、C；还应重新检验各资料与代表观测是否等价。

父节点内部去重之后，根节点求值仍须检查跨父节点共享的 **evidence atom 与来源依赖**。局部去重不能保证全局独立。

## 1-7·1-8和最后的证据缺口 [#1-71-8과-최종-공백]

依[来源谱系与可信度](/zh/docs/main-algorithm/confidence)进行溯源、D/E 处理及 AND、OR 聚合。评估已完成而没有合格路径通往目标时，生成 `CHAIN_UNKNOWN`，并关联具体原因缺口。

本指南将链完成定义为**必要关联及资料资格均已满足，可以进行可信度评估**。完整链分数偏低时属于 `TRUST_WEAK`，不能仅因低分再次生成 `CHAIN_UNKNOWN`。连接完整性与数值可信度是两个独立维度。

## 区分证据缺口 OR 替代方案和总结 [#or-대안의-공백과-전체-결론의-구분]

若某条 OR 分支被排除，而另一分支仍能支持目标，则以 `blockingScope=ALTERNATIVE` 记录排除理由，不能将整个结论标为受阻。相反，AND 的必要要求存在缺口时，影响可能沿上级路径一直传播至 ROOT。

所有排除理由均保留，但相同原因、要求、资料及执行版本仅记录一次缺口。`CHAIN_UNKNOWN` 汇总原因，不替代具体的资料不足说明。

## 成本和确定性 [#비용과-결정성]

候选数可能随 OR 选项的组合呈指数增长。应采用逐步剪枝、记忆化与惰性求值，并明确中断范围。父节点有 `k` 份资料时，两两去重检查可能达到 `O(k²)`，因此先用哈希和事件条件缩小比较范围。

<Equation number="F5" label={"每个家长的详尽对比候选人数"} tex={String.raw`N_{\mathrm{comparisons}}=\sum_{p}\binom{d_p}{2}`} />

对已保存的判定快照重新求值时，代码结果应一致。重新调用 LLM 则可能得到不同判定，因此须保存响应与判定版本。
