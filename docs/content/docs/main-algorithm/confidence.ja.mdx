信頼度 集計では、計算式の妥当性と入力値の妥当性を区別する必要があります。独立性を仮定した方程式が数学的に正しくても、出典 が相互に依存している場合、または入力係数が経験的に修正されていない場合、結果は結論の真の確率として解釈できません。ここでは出典の系譜の追跡ルールと支持スコアの計算条件について説明します。各グレードのスコアと運用閾値は別途検証・方針の確認が必要な項目です。

## 信頼度関連変数の定義 [#신뢰도-관련-변수의-정의]

| 値 | 記号・範囲 | 意味 |
| --- | --- | --- |
| 出典係数 | `r_source`、0–1またはnull | 出典確認・資料タイプの方針係数 |
| leaf 信頼度 | `p_leaf`、0–1またはnull | 特定の資料 - 主張接続を支持する程度 |
| 追加資料の尤度比 | `LR`、0以上またはnull | 既存の資料を知っているときに、新しい資料が仮説の相対的な支持をどのように変えるか |

出典係数1.0と尤度比1は異なる。尤度比は1を超え得るが、負にはならない。出典係数1.0であっても、資料のすべての記述が確実に真であることを意味しない。

## 1-7・出典の系譜の保存単位 [#1-7--출처-계보의-저장-단위]

資料ごとに発行主体・原文URL・引用URL・発行時刻・確保時刻・内容 hashを記録する。引用リンクには以下を残す。

```ts
type ProvenanceEdge = {
  fromEvidenceId: string;
  toSourceId: string;
  relation: 'CITES' | 'REPRINTS' | 'DERIVED_FROM' | 'ORIGINAL_RECORD';
  supportingLocator: string;
  status: 'VERIFIED' | 'UNVERIFIED';
};
```

LLMが提案したURLは候補であり、実際の原文で引用関係と内容を確認した後、検証された系譜で表示する。他のドメインの記事でも同じ通信会社・発表文・原本記録を再利用すれば同じ観測系列である可能性がある。

## 尤度比1の意味 [#우도비-1의-의미]

既存の資料を`E_seen`、新しい候補を`E_new`、目標仮説を`H`とすれば条件付尤度比は次のようになる。

<Equation number="C1" label={"既存観測に条件付きの追加資料の尤度比"} tex={String.raw`\mathrm{LR}_{\mathrm{new}}=\frac{P(E_{\mathrm{new}}\mid H,E_{\mathrm{seen}})}{P(E_{\mathrm{new}}\mid\neg H,E_{\mathrm{seen}})}`} />

<Equation number="C2" label={"同じモデルでのoddsの更新"} tex={String.raw`\begin{aligned}O(H\mid E_{\mathrm{seen}},E_{\mathrm{new}})&=O(H\mid E_{\mathrm{seen}})\,\mathrm{LR}_{\mathrm{new}}\\P(H\mid E_{\mathrm{seen}},E_{\mathrm{new}})&=\frac{p\,\mathrm{LR}_{\mathrm{new}}}{1-p+p\,\mathrm{LR}_{\mathrm{new}}}\end{aligned}`} />

ここでp=P(H | E_seen)であり、新資料を観測する直前の条件付事前確率である。

<ResearchPlot kind="likelihood-update" number="C2" />

上記式のNOT Hは数学的対立仮説であり、ツリーのNOT_SUPPORT演算子と区別する。

LR=1 の場合、この比較モデルでは仮説の確率は変わりません。 `LR > 1` はサポート方向、`LR < 1` はその逆方向です。これはベイズ オッズを更新する際に従う解釈であり、LR と不確実性を計算するためのモデルも記録する必要があります。 [NISTの尤度比と家庭議論](https://nvlpubs.nist.gov/nistpubs/jres/122/jres.122.027.pdf)。

**具体化ルール:** 引用されたレプリカが既知の観察を単に繰り返す場合、それは新しい独立した証拠としてカウントされません。しかし、数値 LR=1 が LLM 出力のみを介して統計的に測定されたことは記録されておらず、「重複しているように見えます」。モデルを使用して計算された`ESTIMATED_LR`と、新しい情報が含まれていない`NO_NEW_INFORMATION`の判断を区別します。

分母が0の場合、または両方の確率を推定するモデルがない場合、LRは`null`とする。LLMの自信を示す数値をLRとして用いたり、不明値を1に置き換えたりしない。浮動小数点比較の許容誤差は方針に明示し、実質的な不確実性を単なる数値誤差として扱わない。

## 系譜追跡反復ルール [#계보-추적-반복-규칙]

1. 現在の資料を保存し、出典または引用URL候補をリストします。
2. 候補原文を確保し、引用関係・原本の有無・内容の違いを確認する。読み取り失敗は失敗状態として記録されます。
3. 可能であれば条件付きLRを評価する。新しい情報なしの判断は別の種類で記録されます。
4. **LR=1 なら既存の資料を維持し、その資料を独立支持リーフとして追加しない。その分岐の拡張を終了します**
5. **LR≠1 の場合は系譜の接続を保存し、資料の出典タイプと係数を評価する。** `LR < 1` もこの経路に含め、反証を隠さない。
6. 出典係数1.0タイプで元出典確認条件も満たしたら成功終了する。あるいは、その資料の引用URLを次の対象とする。
7. 繰り返し上限・循環・これ以上リンクなし・アクセス失敗時に決められた事由で終了する。

LR が不明な場合は、基本追跡規則を補う提案方針として、出典確認だけを予算内で続ける。確率モデルがないだけですべての追跡を止めず、`LR_UNKNOWN` を記録する。ただし、支持の増加を数値で確定したり、新たな独立 leaf として加算したりしない。

### 1-3 snapshotとの関係 [#1-3-snapshot과의-관계]

1-7で見つけた資料は、既存の葉の系譜を確認するために使用することができる。新しい主張を支持する内容として採択するには、`candidateEvidence`に登録した後、**次のsnapshotから1-3・1-4・1-5を再通過**しなければならない。現在の候補集合に検証なしにはめ込まない。

### 必ず終了する条件 [#반드시-종료하는-조건]

| 終了コード | 意味 | 処理 |
| --- | --- | --- |
| `TRUSTED_ORIGIN_REACHED` | 係数1.0タイプと円出典条件確認 | 確認した系譜と理由の保存 |
| `NO_NEW_INFORMATION` | LR=1または個別に検証された情報の重複 | 既存資料の維持、独立基礎数の増加なし |
| `CYCLE_DETECTED` | 正規化URL・内容識別子で同じ系譜再訪問 | 循環経路の保存、終了 |
| `DEPTH_LIMIT`, `FETCH_LIMIT`, `TIME_LIMIT` | 設定した繰り返し予算に達する | 未確認範囲を表示 |
| `NO_REFERENCE`, `FETCH_FAILED` | Next 出典 なしまたはアクセス失敗 | 円出典未確認理由表示 |

成功するまで無限繰り返さない。 `maxDepth`、`maxFetches`、`maxDurationMs`は有限のポリシー値であり、四半期ごとの深さと実行全体のURL予算を別々に検査する。 HTTP（S）文書を読み、リダイレクトにも訪問セットと予算を適用します。文書に書かれたコマンドは実行指示として使用されません。

## 出典等級と1.0タイプ [#출처-등급과-10-타입]

**確定:** ある資料の出典等級がDまたはEの場合、該当資料に`PROVENANCE_UNKNOWN`を記録する。

以下は、まだ承認された基準がない状態での**製品用グレード定義の提案**です。外部の特定の信頼度等級規格をそのまま適用したものではない。

| 評価 | 提案の定義 | 適格性 |
| --- | --- | --- |
| A | 原本と発行主体・記録経路を確認し、必須検証項目を満たす | 資料支持・事件検査を別途通過しなければならない |
| B | 出典と引用経路を確認しましたが、一部の検証に限定 | 制限を点数・説明に反映 |
| C | 出典は識別されるが原文・独立性・生成過程の確認が制限的 | 制限に合った評価、必要に応じて信頼度保留 |
| D | 既知の出典表記がありますが、元出典や系譜を検証できません | `PROVENANCE_UNKNOWN` |
| E | 出典 識別できない、または追跡根拠がない | `PROVENANCE_UNKNOWN` |

未評価の等級と、確認済みの D/E は区別する。本草案では D/E を完成チェーンの必須根拠として採用しない。他に適格な OR 代替経路があれば、その経路は維持する。低等級という理由だけで原文を削除したり、内容が偽であると断定したりしない。

係数 1.0 のタイプには、`trustedSourceTypeRegistry` に明示的な確認条件とポリシーバージョンを登録する。「公式サイト」「政府資料」「LLM が信頼できると判断した」といった理由だけで自動的に 1.0 を与えない。A 等級と係数 1.0 も無条件に同一視しない。

## 1-8 · leaf 信頼度 [#1-8--leaf-신뢰도]

`SUPPORTED`、事件一致と出典玄関口を通過したbindingについて評価する。最初の試製品の数値構成は以下を**提案**する。

<Equation number="C3" label={"適格bindingの提案スコアモデル"} tex={String.raw`s_{\mathrm{leaf}}=r_{\mathrm{source}}\,c_{\mathrm{material}}`} />

`c_material`は該当区間の直接性・完全性・測定または記録品質を評価した政策係数である。 1-4は要求を満たすかどうかの関門であり、`c_material`は関門を通過した資料間の品質を表す。不適格データが高い出典スコアで蘇らないでください。

出典・資料係数を一度だけ使用し、引用段階ごとに重複乗算しない。係数決定根拠・評価者・バージョンを保存する。上の積は検証前の**製品スコアモデル**であり、確率で補正された推定値とは自動解釈しない。値がない場合は、`null`と理由を返します。

## AND・OR・NOT_SUPPORT集計 [#andornot_support-집계]

子サポートの不確実性が独立してモデル化されたときに設計で採用された式を適用する。

<Equation number="C4" label={"独立家の下の三つの演算子"} tex={String.raw`\begin{aligned}s_{\mathrm{AND}}(v)&=\prod_i s(c_i)\\s_{\mathrm{OR}}(v)&=1-\prod_i(1-s(c_i))\\s_{\mathrm{NOT\_SUPPORT}}(v)&=\prod_i s(c_i^{-})\end{aligned}`} />

これらの積の形は、独立な構成要素の直列・並列信頼性計算と同じ構造を持つ。独立性は乗算を正当化する前提であり、出典が異なるだけでは満たされない。[NIST 直列モデル](https://www.itl.nist.gov/div898/handbook/apr/section1/apr182.htm)、[NIST 並列モデル](https://www.itl.nist.gov/div898/handbook/apr/section1/apr183.htm)。

独立した二つの入力が0.8と0.6なら、ANDは0.48、ORは0.92となる。これらがNOT_SUPPORTにおける否定命題の根拠であれば、その支持スコアも0.48である。`1−0.48`に置き換えてはならない。

元の設計の`P`表記は模型説明に維持するが、UI・APIの基本名は`supportScore`で提案する。実際の正解で補正した確率モデルがない状態で「結論が真の確率92％」のように表示しない。

## 共有証拠の保存と重複集計の問題 [#공유-증거의-보존과-중복-집계-문제]

1-6で判定した重複資料と、1-7で同じ原出典を共有すると確認した資料は、共通の`evidenceAtomId`と依存グループで関連付ける。URLの数や画面上のleafの数は、独立した観測の数ではない。

<ResearchDiagram kind="shared" number="C4" />

<Equation number="C5" label={"共有変数を保存した論理式の正規化"} tex={String.raw`(a\land b)\lor(a\land c)=a\land(b\lor c)`} />

a=0.8、b=0.7、c=0.6でa・b・cが互いに独立であれば次のようになる。

<Equation number="C6" label={"同じ入力に対する2つの計算の比較"} tex={String.raw`\begin{aligned}s_{\mathrm{shared}}&=0.8(1-0.3\cdot0.4)=0.704\\s_{\mathrm{naive}}&=1-(1-0.56)(1-0.48)=0.7712\end{aligned}`} />

<ResearchPlot kind="shared-evidence" number="C5" />

候補証拠木を列挙しても、それらが独立になるわけではない。最終スコアは、候補のスコアを独立なORで結合するのではなく、**元の論理式に含まれる共有証拠変数を保持して**計算する必要がある。

実装提案は、Boolean DAGを正規化し、共有アトムのShannon分解またはBDDベースの重み付け評価を使用することです。 atom間の独立性が定義されている場合にのみ重み付き乗算を使用します。最悪の場合、計算量が大きくなる可能性があるため、別途評価予算と未完了状態が必要となる。

## 結合分布が不明な場合 [#결합-분포가-알려지지-않은-경우]

同じ報道資料を引用しながら、それぞれ新しい観測も追加した場合、全体を一つにまとめず、共有区間と独立追加区間を分ける。この区分や結合モデルがなければ、独立スコアを確定しない。

確率で解釈可能な周辺値`p1`、`p2`だけあり、結合分布が分からない場合は、次の範囲を使用することができる。

<Equation number="C7" label={"結合分布が未知の2つの事象の境界"} tex={String.raw`\begin{aligned}\max(0,p_1+p_2-1)&\le P(A\cap B)\le\min(p_1,p_2)\\\max(p_1,p_2)&\le P(A\cup B)\le\min(1,p_1+p_2)\end{aligned}`} />

<ResearchPlot kind="dependence-bounds" number="C6" />

これは基本交集合・合集合確率規則で得られる範囲だ。製品のランダムスコアは、この範囲の補正された確率とは表示されません。複雑な共有DAGは、単純な区間反復が正確な最終範囲を与えると仮定せず、保守的範囲または評価不可を返します。

## しきい値とTRUST_WEAK [#임계값과-trust_weak]

ルートの閾値`tau_root`と任意の下位閾値を方針に保存する。**確定済みの運用閾値はまだない。** 例で用いる0.80は説明用の値である。

| 評価 | 判定 |
| --- | --- |
| 正確なスコアまたは保守的下限がしきい値以上 | このモデルと方針で十分 |
| 上限しきい値未満 | `TRUST_WEAK`、実際の計算ボトルネックの説明 |
| 範囲がしきい値を横切る | 十分さが確定できない `TRUST_WEAK` + `DEPENDENCY_UNRESOLVED` |
| 必須スコア・結合模型が未だ | スコアnull、`TRUST_WEAK`+評価保留理由 |

各下位の代替経路にルート閾値を先に適用し、ORによって支持が高まる可能性を除いてはならない。必要な下位閾値は論理設計で明示する。

出力には、ノード別の計算式、使用したアトム、共有依存性、除外した資料、スコアの根拠、しきい値・ポリシーバージョン、ボトルネックノードが含まれる。弱い接続を説明するときは、0.8を超えるためにスコアだけを任意に調整しません。
