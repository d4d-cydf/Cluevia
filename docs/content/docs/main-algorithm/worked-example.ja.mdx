このセクションでは、注文の配達完了を検証するための構成事例を通じて、候補集合、根拠の欠落理由と支持スコアの変化を追跡します。ステップ間の違いを明確にするために、データの内容と適合性の決定を明示的に設定します。以下の資料・スコア・しきい値はすべて説明のための仮定であり、実際の分析の精度や運営デフォルト値を提示する実験結果ではない。

## 目標と論理 [#목표와-논리]

目標Hは「2026-10-05に注文O-17が倉庫Wに引き渡された」。

```text
H [AND]
├─ C1: 해당 인도 행위가 발생했다 [OR]
│  ├─ E1: 입고 로그
│  ├─ E1-copy: 같은 로그의 재게시 자료
│  ├─ E2: 독립 수령 확인 기록 — 나중에 확보
│  └─ E4: 다른 주문의 수령 기록
└─ C2: 그 인도 기록이 O-17과 연결된다 [OR]
   └─ E3: 주문–입고 번호 대조표 — 처음에는 없음
```

C1 データには、O-17 にリンクできるエントリ キー、期間、場所も必要です。 C2 は、領収書キーと注文 O-17 の間の直接のリンクを確認します。それらが同じ文書から抽出された場合、それらの独立性も個別にチェックする必要があります。この例では、1-4 は各レコードが配送完了のアクションをサポートしていることを確認し、1-5 は選択されたレコードとチェックリスト内のイベント キーがリンクされていることを確認します。

## 初期資料と評価仮定 [#초기-자료와-평가-가정]

| 素材 | 内容 | データ判定 | 事件・出典 |
| --- | --- | --- | --- |
| E1 | 10-05倉庫W、入庫R-17完了 | C1へ`SUPPORTED` | ソースログ、例p=0.90 |
| E1-copy | E1ログをそのまま再公開 | C1へ`SUPPORTED` | 同じ観測であり、独立データではありません |
| E4 | 入庫 R-71、注文 O-71 の受領 | 引き渡しという一般条件を支持 | 目標への接続規則には不一致 |
| E5 | O-17を10-05発送予定 | C1へ`INSUFFICIENT` | 予定は実際の完了を証明できません |
| E6 | 出典 なし完了 主張 キャプチャ | 内容上支持を主張 | グレードE、系統未確認 |

E5およびE6も原稿データに残る。ツリーの証拠要件につながれば判定・出典段階で診断し、上の簡略図では省略した。

## 実行A・C2データなし [#실행-a--c2-자료가-없음]

1-3でC1候補資料があってもC2の`F(C2)=∅`なので、ルート候補は空集合である。

<Equation number="W1" label={"必須接続がない場合の候補"} tex={String.raw`F(C_2)=\varnothing\quad\Longrightarrow\quad F(H)=\varnothing`} />

結果はC2の`EVIDENCE_MISSING`とこれを原因とするルート`CHAIN_UNKNOWN`である。後続の信頼度は計算しません。スコアを0にして「偽」とは言わない。

Gap FillはO-17とR-17が一緒に表示された原本対照表・受領証を検索する。公開されていない内部記録の場合は、どのフィールドを含めるべきかを説明し、ユーザーに要求します。 `CHAIN_UNKNOWN`には、元の受領証経路、ログ交差経路、独立確認経路の3つの戦略を提示する。

## 実行B・E3追加、既存代替チェック [#실행-b--e3-추가-기존-대안-검사]

E3にO-17↔R-17、場所W、日付10-05が明示され、支持・事件・出典検査に合格したと仮定する。例p(E3)=0.80である。

| ステップ | 変化 |
| --- | --- |
| 1-3 | C1 選択肢ごとに E3 を組み合わせた候補生成 |
| 1-4 | E5は予定のみなので`EVIDENCE_INSUFFICIENT`に脱落 |
| 1-5 | E4のO-71/R-71はE3のO-17/R-17と合わず`EVENT_MISMATCH` |
| 1-6 | E1とE1-copyは同じ観測で結ばれ、1つのアトムaとして使用されます |
| 1-7 | E6はグレードEなので`PROVENANCE_UNKNOWN`。対応する代替不適格 |
| 1-8 | 適格候補a AND b（E3）のスコア計算 |

E1とE3の不確実性が独立であるという**例仮定**の下で、以下を得る。

<Equation number="W2" label={"実行B - 接続は完了しますが、サポートが不足しています"} tex={String.raw`s_B(H)=0.90\cdot0.80=0.72<\tau_{\mathrm{example}}=0.80`} />

結果は`COMPLETE_CHAIN_FOUND`と`TRUST_WEAK`だ。チェーンは完成しましたが、得点は十分ではありません。 E4・E5・E6のgapは脱落した代案の問題として残り、すべての経路が消えたわけではないので新しい`CHAIN_UNKNOWN`をつけない。

E1-copyを独立データとして誤って計算すると、C1=0.99、H=0.792となる。重複がデータ数を増やしても信頼度は0.72から増加してはならない。

## 実行C・独立受領記録E2追加 [#실행-c--독립-수령-기록-e2-추가]

E2 は独立観測として確認され、p(E2)=0.75 と仮定する。E1 と E2 はそれぞれ単独で C1 を支持する代替資料であり、両方とも E3 による注文への接続を必要とする。

候補は`{a,b}`、`{c,b}`であり、論理式は`(a OR c) AND b`だ。

<Equation number="W3" label={"実行C — 新しい観測後も残る接続ボトルネック"} tex={String.raw`\begin{aligned}s(C_1)&=1-(1-0.90)(1-0.75)=0.975\\s_C(H)&=0.975\cdot0.80=0.78\end{aligned}`} />

<ResearchDiagram kind="bottleneck" number="W2" />

資料が増えたが、依然として0.80より低い。ミニグラフはC2の共有ボトルネックを示しています。両方の候補がbを共有するため、候補のスコアを再び独立ORに合計しないでください。

この段階のGap Fillは、C1と同じ内容の記事追加よりO-17↔R-17の元の接続を確認する資料を要求する。

## 実行D・E3オリジナル系譜の確認と再評価 [#실행-d--e3-원본-계보-확인과-재평가]

Ｅ３の原本記録と発行経路が確認され、該当するbindingの信頼度を0.95に再評価したものとする。値の変更には確認資料・評価根拠と新しい政策又は評価版を残す。単に目標しきい値を超えるために数値を上げるのではありません。

<Equation number="W4" label={"実行D — 円出典確認による再評価"} tex={String.raw`s_D(H)=0.975\cdot0.95=0.92625\ge\tau_{\mathrm{example}}`} />

独立性の仮定とデータの決定も維持される新しい実行のサンプルしきい値を満たします。以前のスコアとTRUST_WEAKレコードは履歴に残り、最新の実行で解消状態をリンクします。 UIの説明は「例スコアモデルで基準を満たす」であり、統計検証なしに「真実確率92.625％」と書かない。

## 否定命題への適用 [#부정-주장에-대한-적용]

主張 N は「締め切り前に取り消されなかった」である。確認区間、記録の完全性、対象の一致、否定命題を直接支持する根拠が必要となる。その二つの必要条件が独立で、スコアが 0.9 と 0.8 なら、AND の結果は 0.72 となる。

どちらかがなければ、1-3の根拠の欠落であり、0.28または1.0に置き換えない。現在、取り消し資料を見つけられなかっただけでNが立証されたわけではない。

## 出典の系譜トレースへの適用 [#출처-계보-추적에-대한-적용]

| パス | 判定 | 処理 |
| --- | --- | --- |
| 再公開ページ→すでに取得した同じログ | 新しい情報なし | 既存データの保持、重複加算なし |
| 記事→原稿記録→発行機関保管原稿 | 段階別原文・引用確認 | 係数 1.0タイプの確認条件を満たせば終了 |
| A → B → A | 循環 | `CYCLE_DETECTED`、訪問リストの保存 |
| 記事→アクセス不可の原文 | 未確認 | LRをランダムに1にしない。 D/E面 `PROVENANCE_UNKNOWN` |

この例の中核は、根拠の欠落解消が「資料数の増加」ではなく、**該当する必須接続の満たしと再検証**として決定されることである。
