---

공백 진단이 유용하려면 그 결과가 다음 조사에서 확인할 수 있는 구체적인 조건으로 이어져야 한다. Gap Fill은 이 조건을 자료의 종류, 필수 필드, 사건 범위와 수용 기준으로 표현한다. 보완 액션은 아직 충족되지 않은 요구에 대한 대응이며, 액션의 수행 자체가 증거의 충분함을 보장하지는 않는다. 확보한 자료와 변경된 판정은 새 snapshot에서 다시 평가한다.

## 공통 액션 계약

```ts
type FillAction = {
  id: string;
  runId: string;
  gapIds: string[];
  targetClaimId: string;
  requirementIds: string[];
  actionType: 'SEARCH_EVIDENCE' | 'REQUEST_EVIDENCE' | 'EXPLAIN_MISMATCH'
    | 'EXPLAIN_TRUST' | 'TRACE_SOURCE' | 'REQUEST_SOURCE' | 'PROPOSE_CHAINS';
  reason: string;
  requiredEvidence: { kinds: string[]; fields: string[]; eventScopeId: string };
  acceptanceCriteria: string[];
  status: 'PROPOSED' | 'RUNNING' | 'WAITING_USER' | 'COMPLETED' | 'FAILED';
  resultEvidenceIds: string[];
  nextEvaluationStages: string[];
};
```

LLM은 검색식·설명·전략을 만들고, 도구는 실제 검색·원문 확보를 수행하며, 코드는 반환 자료·예산·상태를 검증한다. LLM이 알고 있다고 서술한 문서를 실제 확보한 자료로 기록하지 않는다.

## EVIDENCE_MISSING · 직접 자료 검색, 필요 시 사용자 요청

**입력:** 비어 있는 requirement, 목표 주장, 대상·사건 조건과 허용 자료 형태.

1. requirement가 충족되려면 어떤 필드가 있어야 하는지 명시한다.
2. 식별자·기간·장소·자료 종류를 포함한 검색식을 만든다.
3. 인터넷에서 직접 관련된 원문을 검색하고 실제 URL과 본문을 확보한다. 지지·반증 결과를 모두 보존한다.
4. 제목·검색 snippet만 맞는 결과를 증거 leaf로 채택하지 않는다. 원문 구간, 대상과 사건을 대조한다.
5. 공개 자료로 확보할 수 없으면 탐색 범위와 그 판단 근거를 기록하고 사용자에게 필요한 자료를 요청한다.

“검색 결과 없음”은 “그 자료가 세상에 없음”을 뜻하지 않는다. 인터넷 확보 불가의 사유는 `NOT_FOUND_WITHIN_BUDGET`, `PRIVATE_RECORD_REQUIRED`, `ACCESS_UNAVAILABLE`처럼 구분한다. 검색 예산을 소진했다면 그 범위 안에서 찾지 못했다고 설명한다.

**요청 예:** “O-17과 창고 입고 번호를 연결하는 자료가 없습니다. 주문 번호와 입고 번호가 함께 표시된 원본 수령증 또는 주문–입고 대조표가 필요합니다.”

**완료 조건:** 자료가 확보되어 1-3의 빈 요구를 채울 후보가 생김. 공백 해소는 이후 1-4·1-5·1-7·1-8 재평가로 결정한다.

## EVIDENCE_INSUFFICIENT · 부족한 지지 내용 설명

**입력:** 부적격 binding, 판정 enum, 원문 구간과 acceptance criteria.

설명은 “신뢰할 수 없다”는 일반 문구 대신 **자료가 실제로 말하는 것 → 목표가 요구하는 것 → 그 차이 → 추가로 필요한 자료** 순서로 작성한다.

**예:** “현재 메일은 10월 5일 배송 예정이라고만 적혀 있습니다. 목표는 실제 인도 완료이므로 이 메일만으로는 충분하지 않습니다. 인도 시각·수령 대상·주문 번호를 확인할 수 있는 수령증 또는 입고 기록이 필요합니다.”

반증이면 원문에 어떤 반대 주장이 있는지 함께 보여준다. `UNREVIEWED`나 모델 오류라면 부족한 근거로 판정 완료했다고 말하지 않고 검토를 먼저 완료한다. 사건 메타데이터 UNKNOWN도 빠진 필드를 구체적으로 요청한다.

**완료 조건:** 새 자료 또는 재검토로 해당 binding·대체 binding이 `SUPPORTED`가 되고 필요한 재검사를 통과함.

## EVENT_MISMATCH · 연결 불가 설명

**입력:** 실패한 사건 규칙 ID, 기대 메타데이터와 관측 메타데이터.

| 표시할 것 | 예 |
| --- | --- |
| 연결하려던 주장 | O-17 인도 완료 |
| 적용 규칙 | 주문 번호 동일 + 지정 창고 + 인도 기간 |
| 충돌 항목 | 목표 O-17, 자료 O-71 |
| 해당 원문 위치 | 수령증 주문 번호 필드 |
| 결론 | 이 수령증을 O-17의 완료 근거로 연결할 수 없음 |

사용자에게 연결 불가를 알리고 해당 자료를 현재 후보에서 제외한다. 대상에 맞는 다른 자료가 있다면 새로운 후보로 평가할 수 있지만 기존 자료의 번호·날짜를 목표에 맞춰 고치지 않는다.

단순 메타데이터 누락은 이 액션이 아니라 불충분 자료 요청으로 보낸다. 파싱 오류가 확인되어 정정하는 경우에도 원본은 보존하고 새 메타데이터 버전으로 1-5를 재실행한다.

**완료 조건:** 현재 연결이 불가하다는 진단을 정확히 전달한 상태. 액션 완료가 곧 목표 주장 입증이나 gap 해소를 뜻하지 않는다.

## TRUST_WEAK · 미니 그래프와 병목 설명

**입력:** 신뢰도 계산 trace, 임계값, 공유 출처·의존성, 부족한 노드.

미니 그래프는 최소한 루트까지의 경로, 병목 주장, 사용한 증거, 관계 연산자, 노드별 점수·미상 상태를 포함한다. AND의 다른 필수 조건을 숨기지 말고 접힌 요약 노드로 남긴다.

```text
인도 완료 H [AND, 0.72 / 예제 기준 0.80]
├─ 인도 기록 C1 [0.90]
│  └─ 창고 원본 로그 E1
└─ 주문 연결 C2 [0.80] ← 이 연결의 근거를 강화해야 함
   └─ 주문–입고 연결표 E3
```

**설명 예:** “인도 기록과 주문 연결이 모두 필요합니다. 현재 점수 모형에서 0.90×0.80=0.72입니다. 같은 로그를 재게시한 기사 추가는 독립 근거가 아니므로 개선되지 않습니다. 주문–입고 연결을 확인하는 원본 번호 대조 기록이 필요합니다.”

<ResearchDiagram kind="bottleneck" number="G2" />

그림 G2는 [전체 실행 예제](/docs/main-algorithm/worked-example)의 실행 C를 나타낸다. 동일한 AND 모형에서 한 하위 점수만 변한다고 가정하면 다음 민감도를 얻는다.

<Equation number="G1" label="고정된 AND 모형의 국소 민감도" tex={String.raw`\begin{aligned}s(H)&=s(C_1)s(C_2)\\\frac{\partial s(H)}{\partial s(C_1)}&=s(C_2),\qquad\frac{\partial s(H)}{\partial s(C_2)}=s(C_1)\end{aligned}`} />

이는 수식의 변화율이며 실제 보완 액션의 효과 예측값은 아니다. 새 자료가 다른 관측과 의존하거나 논리 구조를 바꾸면 동일한 계산을 재사용할 수 없다.

가능하면 후보 액션을 “어느 requirement의 어떤 불확실성을 줄이는가”로 비교한다. 모형이 없는 상태에서 예상 점수 상승을 확정값처럼 표시하지 않는다. 독립성 미상 때문에 범위가 넓다면 새 자료 수보다 관측 경로 확인을 우선한다.

**완료 조건:** 새 근거·계보·의존성 확인을 재평가한 결과 임계값 충족이 확인됨. 임계값을 낮추는 변경은 자료 보완과 구분하여 별도 정책 버전으로 기록한다.

## PROVENANCE_UNKNOWN · 원출처 표기 또는 찾기

**입력:** D/E 자료, 확인한 계보, 추적 종료 사유.

원문 발행기관·작성자·최초 게시 주소·발행일·인용 페이지·기록 식별자 중 빠진 항목을 설명한다. 인용 URL이 있으면 1-7의 한도 안에서 원출처를 찾고, 온라인에서 확인할 수 없으면 사용자가 알고 있는 원출처 표기를 요청한다.

**예:** “첨부 이미지에 원래 보고서 이름과 발행기관이 없습니다. 보고서 원문 URL, 발행기관, 해당 페이지 또는 원본 파일을 알려주세요.”

URL을 기입했다는 사실만으로 등급을 올리지 않는다. 실제 원문과 자료가 같은 내용인지 확인하고 재인용 경로를 검증한다. 원출처를 찾았어도 주장 지지 판정과 사건 일치는 별도다.

**완료 조건:** 계보 검증과 출처 재평가 결과 D/E 문제를 해소하고, 관련 후보를 다시 검사함.

## CHAIN_UNKNOWN · 체인 완성 전략 3개

**입력:** 루트까지 완성된 체인이 0개이고 평가가 완료된 결과, 원인 gap 목록, 원래 논리식.

최종 목표와 필수 조건을 유지하면서 서로 다른 자료 확보 전략을 **3개** 제시한다. 아직 없는 자료나 연결은 계획으로 표시하고 실제 발견된 사실처럼 그리지 않는다.

| 전략 예 | 우선 찾을 자료 유형 | 예상 연결 | 적합한 상황 |
| --- | --- | --- | --- |
| 1. 직접 원본 기록 | 서명 수령증·원본 거래 기록·업무 시스템 원장 | 사건 결과와 대상 식별자를 한 자료에서 확인 | 원본에 접근 가능한 경우 |
| 2. 시간 순서 교차 검증 | 출하·입고·수령 로그와 식별자 대조표 | 대상 키를 유지하며 사건 전후를 연결 | 하나의 종합 자료가 없는 경우 |
| 3. 독립 관측 결합 | 상대 기관 기록·직접 관측 자료·별도 보관 증빙 | 같은 대상·사건의 독립 자료들을 연결 | 기존 자료가 재인용 한 계열에 몰린 경우 |

각 전략에는 `requiredEvidence`, `closedGapIds`, `remainingGaps`, `eventJoinRules`, `sourceIndependenceNeeds`, `availability`를 포함한다. 모든 사례에서 3개의 실행 가능한 경로가 있다고 보장할 수는 없다. 실행 불가한 전략은 왜 불가능한지와 필요한 접근 조건을 표시하되 가짜 출처를 만들어 숫자를 채우지 않는다.

원래 트리에 없던 대안 논리를 제안하면 `proposedTreeRevision`으로 구분하고 같은 목표를 충분히 지지하는지 검토한 뒤 새 트리 버전에 반영한다. 기존 AND 필수 조건을 지워 체인을 완성한 것으로 만들지 않는다.

**완료 조건:** 전략 3개와 자료 요구를 사용자에게 제공함. 실제 gap 해소는 전략 수행 후 새 실행에서 완성 체인을 확인해야 한다.

## 여러 공백의 우선순위와 중복 액션

ROOT를 막는 상세 공백을 먼저 설명하고, OR의 선택되지 않은 대안 공백은 뒤에 둔다. `CHAIN_UNKNOWN` 전략은 상세 원인을 참조한다. 같은 원문 하나로 missing·provenance 문제를 함께 풀 수 있으면 액션 하나에 여러 gap ID를 연결한다.

우선순위는 자료 접근 가능성, 충족할 필수 요구 수, 기대하는 불확실성 감소, 실행 비용을 이유와 함께 제안한다. 이를 자동으로 정확한 효용 수치라고 표현하지 않는다.

## 반복과 종료

```text
액션 실행 → 후보 자료 등록 → 새 snapshot
  → Gap Find 재실행 → 이전 gap과 비교
```

새 입력 hash·판정·계보가 바뀌지 않으면 같은 요청을 반복하지 않는다. 사용자 자료가 필요하면 `WAITING_USER`, 예산에 도달하면 `PAUSED_BY_BUDGET`, 요구 충족이면 `RESOLVED`처럼 보완 루프 상태를 따로 관리한다. 이는 여섯 GapType을 늘리는 것이 아니다.

Gap Fill은 `maxRounds`, 검색 URL·시간·호출 예산으로 유한하게 실행한다. 확보 불가를 입증 실패와 구분하고, 추가 자료 없이 공백이 해소되었다고 자동 종료하지 않는다.
