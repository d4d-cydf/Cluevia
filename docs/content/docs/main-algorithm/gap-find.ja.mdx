---
title: "Gap Find：段階別の評価規則"
description: "実際の証拠として候補証拠木を構成し、適合性・事象一致・重複を検査して根拠の欠落を診断する段階別仕様。"
---

Gap Findの目的は,現在資料に構成される立証経路を評価し,各経路が維持されるか除外される理由を説明することである.このとき除外されるのは特定の主張に対する候補組合であり,原材料自身ではない.したがって,一つの代替案の失敗,目標全体の立証経路の欠如,評価未完了料を異なる状態に保存しなければならない.下記の手順は,この原則を各段階の入力と判断規則として具体化する.

## 1-1・目標と事件範囲を固定 [#1-1--목표와-사건-범위-고정]

質問を検証可能な主張に変換し、対象、行為、時刻、場所、条件を定める。利用者が求めた結論を、より弱い結論に置き換えない。「所有していたか」と「所有していたと述べる記事があるか」は異なる主張である。

対象の主張を検証するための必要項目と判定基準を`EvidenceNeed`に記録する。事件の発生時刻と資料の発行時刻を分け、不明な項目は不明のまま保持する。目標や論理的なつながり自体が曖昧な場合は、資料不足と断定する前に論理設計を明確にする。

## 1-2・Why-not Tree作成 [#1-2--why-not-tree-생성]

LLMは下位主張・証拠要件・演算子候補を提案する。コードはID、参照、循環、空の論理ノードと必須要求を調べます。各内部接続には、「これらの子条件が満たされたら、なぜこの親主張を支持するのか」を説明する`inferenceRule`が必要です。

資料の数だけから演算子を推定しない。証拠のない要件も保持する。NOT_SUPPORTは[確定した否定命題の立証規則](/ja/docs/main-algorithm/model)に従い、ANDに正規化する。

## 1-3・存在する葉で候補証拠木生成 [#1-3--존재하는-leaf로-집합-트리-생성]

資料本文または検査可能な記録区間が現在snapshotに存在し、参照が有効な葉のみを使用する。 URLだけがあって内容を確保できなかった場合や、ファイル処理が終わらなかった場合、実際の証拠が確保されたとは見なされません。

ノード`v`に可能な候補の集合を`F(v)`と定義する。以下の集合元素は、データIDだけではなく、requirementに連結されたbindingである。

<Equation number="F1" label={"候補構成の基礎条件"} tex={String.raw`F(b)=\{\{b\}\},\qquad F(r_{\mathrm{missing}})=\varnothing`} />

<Equation number="F2" label={"ORの和集合とANDの組み合わせ"} tex={String.raw`\begin{aligned}F_{\mathrm{OR}}(v)&=\bigcup_{i=1}^{n}F(c_i)\\F_{\mathrm{AND}}(v)&=\left\{\bigcup_{i=1}^{n}w_i\;\middle|\;w_i\in F(c_i)\right\}\end{aligned}`} />

NOT_SUPPORTの候補構成にはANDと同じ規則が適用されます。

`AND(OR(a,b), c)`の候補は`{a,c}`と`{b,c}`である。cがなければ候補は0件となる。aまたはbが残っていても、式を`AND(a)`に弱めてはならない。

<WitnessExplorer number="F2" />

<Callout title={"空集合と空候補の区分"}>
`∅`は可能な候補がないという意味で、`{∅}`は空の証拠だけで成立する候補一つという意味だ。証拠が必要な主張に`{∅}`を作らない。空の AND を真に扱うプログラミング慣例を証拠判定に適用してはならない。
</Callout>

ルート候補が空集合の場合、`EVIDENCE_MISSING`と必須要求パスを記録し、その実行の証拠チェーン評価を中止します。サブ診断は別々に行うことができますが、後のステップを通過した完成候補としてマークしないでください。

可能な組み合わせが多すぎる場合は、遅延生成と上限を使用してください。上限に達すると`INCOMPLETE`であり、「チェーンなし」と確定しない。最初は、要求満足度の異なる候補を単純なサブセット比較として削除しません。

## 1-4・各資料の主張支持適合性 [#1-4--각-자료의-주장-지지-적합성]

各bindingごとに該当親主張と`acceptanceCriteria`を読み、資料の判定状態を代入する。 `SUPPORTED`だけ通過し、残りは事由とともに脱落させる。未検討・モデルエラーは「偽と判定される」と区分して未完了と記録する。

| 検査 | 例 |
| --- | --- |
| 対象は主張と同じですか | 注文「O-17」の資料か、それとも名称が似ている別の注文か。 |
| 資料が言う事実の強度が十分か | 計画・予約と実際の完了を区別したか |
| 原文区間が実際に存在するか | 引用が原文にあり、切り取った文脈がないか |
| 推論規則に必要な条件が満たされているか | 単純な遭遇を貨物の前に断定しないか |
| 否定・推測・二次引用を保持しているか。 | 「否定する発言があった」ことを、実際の不存在に置き換えていないか。 |

<Equation number="F3" label={"適合性関門の後に残る候補"} tex={String.raw`F_{\mathrm{fit}}(v)=\{w\in F(v)\mid\forall b\in w,\;\operatorname{verdict}(b)=\mathrm{SUPPORTED}\}`} />

対象・時間の具体的な事件連結検査は、1-5で別途行う。 1-4ですでに確認した不十分な事由も失わない。

### 親演算子による不適格判定の伝播 [#부모-연산자에-따른-부적격-판정의-전파]

| 親 | 不適格な子処理 |
| --- | --- |
| AND | 対応する子を必須とする候補全脱落。前提条件は元のツリーに保持 |
| OR | その選択肢だけが脱落。他の代替検査の継続。すべて脱落すると、親も不適格 |
| NOT_SUPPORT | ANDと同じ。証拠の欠如や不適格判定を、否定命題の立証に置き換えない。 |

不適格ごとに`EVIDENCE_INSUFFICIENT`に判定値・原文区間・不足した要求を記録する。 反証は支持候補から除外した後も診断とユーザー画面に残る。

## 1-5・候補証拠木全体の事件一致 [#1-5--집합-트리-전체의-사건-일치]

一つの候補証拠木に含まれる資料が、**同一の事件、または明示した事件間関係**を構成するかを検査する。名称や語句が似ているという理由だけで記録を結合しない。

### イベントメタデータ契約 [#사건-메타데이터-계약]

| フィールド | 比較基準 |
| --- | --- |
| `entityRefs` | 識別された識別子とインシデント内の役割。名前だけが一致した場合、未確認 |
| `eventType` | 行為・関係の種類。注文・出荷・到着・受領を区別する。 |
| `occurredAt`または期間 | 実際発生時刻と時間帯、不確実性・精度含む |
| `locationRefs` | 場所IDまたは明示された包含・移動関係 |
| `recordKeys` | 注文番号・取引番号など連結キー |
| `publishedAt`, `observedAt` | 発生時刻とは別に保存 |
| `metadataEvidence` | フィールド値が確認できる資料・区間 |

LLMが推定した空のフィールドは、確認された値のように埋められません。リンクルールはイベントタイプ別のバージョンで管理されます。

### ルールの種類 [#규칙-종류]

- `SAME_EVENT`：必須識別キー・役割・行為が当てはまり、時間区間の**全体共通部分**などの規則を満たさなければならない。
- `ORDERED_EVENTS`：先行事象の対象キーが続き、指定した時間順を満たす必要があります。異なる事件を同じ視点に合わせない。
- `SAME_ENTITY`：イベントの時間が異なる場合でも、定義された同じオブジェクト接続規則を満たすことができます。

A–B と B–C の資料がそれぞれ重なることから、A–B–C 全体の一致を仮定してはならない。例えば、時間区間 `[1,3]`、`[3,5]`、`[5,7]` は隣接区間同士が接するが、全区間に共通する時刻は存在しない。

<EventIntervals number="F3" />

<Equation number="F4" label={"閉じた視覚区間の全交差"} tex={String.raw`\bigcap_i [\ell_i,u_i]\ne\varnothing\quad\Longleftrightarrow\quad\max_i\ell_i\le\min_i u_i`} />

この式は、同じ時間帯と精度で正規化した閉じた区間の条件である。開かれた境界や許容誤差は事件規則に別途明記する。

| 結果 | 処理 |
| --- | --- |
| `MATCH` | その候補を維持 |
| `MISMATCH` | 候補を除いて`EVENT_MISMATCH`。衝突したフィールド・期待値・観測値記録 |
| `UNKNOWN` | サポートチェーンとして確定しない。不足しているメタデータを`EVIDENCE_INSUFFICIENT`で記録して保留 |

UNKNOWNをMISMATCHに置き換えないでください。実際の不一致のみを接続不可として説明する。資料自体を削除せず、他の主張・事件には適している可能性がある。

## 1-6・親単位重複データ検査 [#1-6--부모-단위-중복-자료-검사]

親ノードを1つの比較単位にし、その下の証拠 binding の重複を検査する。 LLMは同じ事件・同じ 主張 を裏付ける同一内容なのか、一部重なったのか、独立観測なのかを判定する。

1. 同じcontent hash・記録IDなどで全く同じ資料を先に識別する。
2. 同じ親の残りの候補に関連区間・事件メタデータ・元出典を提供してLLM判定を要請する。
3. 判定に原文位置と理由を要求し、コードが応答構造・参照を検証する。
4. `EXACT_DUPLICATE`または根拠が確認された`SAME_OBSERVATION`だけ同じevidence atomで結ぶ。
5. `PARTIAL_OVERLAP`、`DISTINCT`、`UNKNOWN`は保存する。不確実な冗長性を任意に削除しないでください。
6. requirement別に満たされた情報が同じ候補だけを代表候補に合わせる。除いた資料は`duplicateOf`と事由で残す。

代表資料は原文接近可能性・区間完全性などバージョンのある規則で選択し、同率は安定したＩＤ順で定める。 信頼度が高く見える資料だけ残して反証を消さない。

LLMのペアによる「類似」判定は転移的であると保証されません。 A≈B、B≈CだけでA・B・Cを全て併合せず、代表観測との同等性を再検査する。

親別の重複縮小後も、全ルートの信頼度計算では、**親を横切る共有evidence atomと出典依存性**を確認する。局所重複排除だけでグローバル独立性が確保されない。

## 1-7・1-8と最終根拠の欠落 [#1-71-8과-최종-공백]

[出典の系譜と信頼度](/ja/docs/main-algorithm/confidence)で系譜追跡、D/E処理、AND・OR集計を行う。評価が完了したが、目標まで連結可能な適格チェーンが一つもない場合、`CHAIN_UNKNOWN`を詳細原因gapに連結する。

このガイドラインでは、チェーンの完成は**必須接続とデータ適格性を備え、信頼度評価が可能な状態**に具体化する。完成したチェーンの点数が弱ければ`TRUST_WEAK`であり、点数が低いという理由だけで自動的に`CHAIN_UNKNOWN`を重複生成しない。数値信頼度と連結完成度を別軸に維持するための規則である。

## OR代替の根拠の欠落と全体結論の区分 [#or-대안의-공백과-전체-결론의-구분]

1つのOR分岐が脱落したが、他の枝が目標を支持すれば、脱落事由は`blockingScope=ALTERNATIVE`と記録する。全体の結論が詰まったとマークしないでください。逆に、AND必須要件の根拠の欠落は、上位パスに沿ってROOTに影響を与える可能性があります。

すべての脱落事由を保存するが、同じ原因・requirement・資料・実行バージョンのgapは一度だけ記録する。 `CHAIN_UNKNOWN`は原因要約であるため、具体的な不足資料の説明を置き換えない。

## コストと決定性 [#비용과-결정성]

候補数は、OR代替数の積で指数関数的に増加することができる。段階的プルーニング・メモ化・遅延評価を使用し、中断した範囲を明示しなければならない。親に資料が`k`開ければ、すべてのペアの重複検査は`O(k²)`呼び出し候補を作成できるため、ハッシュと事件条件で比較対象を先に減らす。

<Equation number="F5" label={"親別伝数対比較の候補数"} tex={String.raw`N_{\mathrm{comparisons}}=\sum_{p}\binom{d_p}{2}`} />

同じsnapshot・規則・既に保存された判定で再評価すれば、コードの結果は同じでなければならない。 LLMを新しく呼び出すと結果が変わる可能性があるため、応答と判定バージョンを保持します。
