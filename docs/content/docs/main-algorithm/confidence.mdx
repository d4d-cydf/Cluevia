Cluevia의 현재 Confidence는 **목표 하나에 대한 선형 보정 우도비 모형**이다. 출처 등급을 고정 계수로 바꾸고, 같은 목표의 사전 오즈에 중복을 제거한 보정 우도비를 곱한다. 계산에 쓴 기본값과 가정은 실측 통계와 구분하여 보관한다.

## 1. 출처 등급과 고정 계수

| 출처 등급 | 정의 | 계수 r |
| --- | --- | --- |
| A | 검증된 원자료: 사진, 데이터, 역사사료 | 1.0 |
| B | 당사자가 아닌 정부기관·정부간기구의 공식 발표 | 0.8 |
| C | 당사자 정부기관·정부간기구의 공식 발표, 연구자료 | 0.6 |
| D | 원출처가 검증되지 않은 기사·뉴스 | 0.4 |
| E | 원출처가 검증되지 않은 SNS·블로그 | 0.2 |
| F | AI 생성 데이터, 허위정보 | 0.0 |

평가자는 등급과 그 근거를 저장한다. 표에 없는 임의 출처 계수로 이 값을 덮어쓰지 않는다. 출처 등급 미상은 F라고 확정하지 않고, **계산에서만 r=0을 사용하여 영향을 중립화**하며 기본값 사용 사유를 남긴다. F와 미상은 설명과 데이터 상태에서 구분한다.

정부간기구의 공식 발표도 B/C 분류 대상이며, 해당 사건에서 당사자인지와 그 근거를 설명한다. 기관 이름만으로 B를 확정하지 않는다. 공식 원문을 확보한 경우와 언론이 기관 발표를 재인용한 경우도 구분한다. 분류할 근거가 부족하면 null과 구체적인 이유를 보존한다.

출처 D/E는 낮은 가중치로 Bayesian 계산에 참여한다. 별도의 적격 입증 체인 검사에서는 원출처 미확인 공백을 유지한다. 점수에 반영된다는 이유로 원출처 검증이 완료되지는 않는다. F는 점수를 올리거나 내리지 않으며 입증 체인의 적격 자료로 통과하지 않는다.

## 2. 목표와 사전확률

최종 질문의 가설을 H라고 한다. 모든 계산 입력은 같은 H를 대상으로 한다. 자료가 연결된 Why-not 조건은 입증 구조를 설명하며, 각 조건의 LR을 설명 없이 서로 다른 가설에서 가져와 곱하지 않는다.

```ts
policy.bayes = {
  target: 'GOAL',
  priors: [{
    nodeId: snapshot.rootId,
    probability: 0.5,
    reason: '이 목표에 대한 역사적 통계 또는 명시한 판단 근거'
  }],
  conditionalIndependence: []
};
```

목표에 맞는 역사적 통계나 사용자가 검토한 수치를 우선한다. 미평가 값은 Claude Low가 원문을 근거로 추정할 수 있으며 이 값은 `MODEL_ESTIMATE`로 구분한다. 사용할 통계·추정이 모두 없으면 **0.5**를 기준값으로 사용하고 `priorBasis: BASELINE`과 설명을 저장한다. 자료가 부족하다는 이유로 0 또는 1로 채우지 않는다.

현재 관측과 독립적인 기저율 근거가 없으면 모델은 prior를 `null`, anchors를 빈 배열로 반환한다. 근거 없는 .5를 모델 추정값으로 저장하지 않는다. 이때 .5는 계산기의 중립 기본값이다. 같은 관측을 사전확률과 LR 양쪽에서 중복 반영하지 않는다.

기존 저장 데이터의 조건별 LR은 다중 조건 목표 전체의 LR로 자동 재해석하지 않는다. `target: GOAL`로 명시적으로 검토하기 전까지 목표 계산에서는 LR=1을 사용한다. 목표와 단일 조건이 동치인 기존 자료는 해당 조건의 값을 사용할 수 있다.

## 3. 우도비와 선형 보정

우도비 LR은 H일 때와 H가 아닐 때 자료 E가 관측될 가능도의 비다. 통계나 명시적 추정 근거가 제공되면 해당 값을 보관한다. Claude Low가 추정한 수치는 `MODEL_ESTIMATE`이며 역사적 통계나 실측 보정을 뜻하지 않는다. 사용할 입력이 없으면 **LR=1**을 중립 기준값으로 사용하고 `likelihoodBasis: BASELINE`을 기록한다.

```ts
binding.likelihood = {
  ratio: 0.1,                // 0 이상 유한한 수; 입력 통계가 없으면 null
  basis: 'EXPERT_ESTIMATE',  // CALIBRATED / EXPERT_ESTIMATE / MODEL_ESTIMATE / UNASSESSED
  reason: '같은 목표 H에 대한 비교 자료와 산정 근거'
};
```

<Equation number="B1" label="현재 출처 신뢰도 보정식" tex={String.raw`\mathrm{LR}'_i=r_i\mathrm{LR}_i+(1-r_i)`} />

이 식은 제품에서 선택한 선형 보정 규칙이다. 기존의 `LR^(r × materialCoefficient)` 식은 사용하지 않는다. **자료 품질 계수 materialCoefficient도 현재 우도비 보정에 곱하지 않는다.** 과거 품질 모형 값은 별도로 보관할 수 있다.

- r=1이면 원래 LR을 그대로 사용한다.
- r=0이면 LR 크기와 관계없이 보정 LR=1이다.
- LR=1이면 모든 등급에서 보정 LR=1이다.
- LR이 1보다 작으면 반증 방향, 크면 지지 방향이다. 판정과 입력 방향이 모순되면 해당 업데이트를 중립으로 보류하고 사유를 남긴다.
- LR=0은 허용한다. 음수·NaN·무한대는 입력 계약에서 거부한다.
- 출처 계수를 인용 단계 수만큼 반복 적용하지 않는다.

## 4. 목표 단위의 갱신

<Equation number="B2" label="중복 제거 후 목표 오즈 갱신" tex={String.raw`O_0=\frac{p_0}{1-p_0},\qquad O_*=O_0\prod_{g\in\mathcal G}\mathrm{LR}'_g,\qquad p_*=\frac{O_*}{1+O_*}`} />

모든 자료의 통계가 없으면 p0=.5와 LR=1을 적용하므로 조건이나 노드 수와 관계없이 **50점, C등급**이다. 여러 조건의 기본값 .5를 AND로 다시 곱하지 않는다. 동일 목표에 대한 자료의 영향은 위 곱에서 한 번만 계산한다.

Why-not의 AND·OR·NOT_SUPPORT는 입증 체인, 부족한 조건과 진단 연결에 사용한다. 이미 목표 H에 대해 갱신한 최종 점수에 이 연산을 다시 적용하지 않는다. NOT_SUPPORT는 부정 주장을 입증할 자료를 AND로 요구하는 의미이며, 최종 점수를 1−p로 뒤집지 않는다.

| 입력 | 보정 및 결과 |
| --- | --- |
| prior .9, LR .1, 출처 B(r=.8) | 보정 LR .28; 최종 .715909… → 71.59점, B |
| prior .5, LR 4, 출처 B(r=.8) | 보정 LR 3.4; 최종 .772727… → 77.27점, B |
| prior .5, 출처 A인 독립 관측 LR 2와 3 | 최종 6/7 → 85.71점, A |
| prior .5, 같은 관측 LR 2가 두 번 표시 | 한 번 반영 → 66.67점, B |
| prior .5, 모든 LR 미입력 | 중립 LR 1 → 50점, C |
| prior .37, 출처 F 또는 미상 | 해당 자료 효과는 LR 1 → 기존 37점 유지 |

큰 유한 LR의 곱은 내부 로그 공간에서 계산하여 오버플로를 피한다. 보정 LR=0은 별도 분기로 처리한다. prior=1과 보정 LR=0이 함께 있으면 조건부 확률의 분모가 0이므로 정상적인 사후확률로 처리하지 않는다. `PARTIAL`, 범위 [0,1], 보수적 하한 0점과 모순 사유를 반환한다. JSON에는 Infinity나 NaN을 기록하지 않는다.

사전확률이 0과 1 사이이고 모든 보정 LR이 양수인 유한 값이면 결과도 열린 구간 안에 남긴다. 부동소수점 반올림·언더플로가 1 또는 0을 만들 때만 가장 가까운 표현 가능한 내부값 `1−Number.EPSILON/2`, `Number.MIN_VALUE`를 사용한다. 임의의 99.9점 상한이 아니며, 명시한 prior 0/1이나 LR0의 실제 경계 결과는 유지한다.

## 5. 중복·의존성 처리

같은 관측 atom, 같은 자료의 동일한 인용 구간, 검증된 동일 관측과 복제본은 하나의 묶음으로 계산한다. 같은 URL 또는 출처 이름만으로 합치지 않는다. 동일 관측에 서로 다른 LR 또는 등급 평가가 있으면 가장 큰 값을 선택하지 않고 그 묶음을 중립 LR=1로 보류한다.

동일 관측이 여러 조건에 연결되어도 목표 점수에는 한 번만 반영한다. 각 하위 노드의 참고 점수는 그 노드가 참조하는 관측 ID로 계산하므로, 전역 대표 binding이 다른 조건 아래에 있다는 이유로 한쪽 조건의 점수가 기본값으로 떨어지지 않는다.

`PARTIAL_OVERLAP`은 독립적인 관측이라는 뜻이 아니다. 일부 내용이 겹친다고 확인한 관측 묶음은 공동 LR이 없으면 개별 LR을 곱하지 않고 중립 LR=1, `UNASSESSED`와 부분 중복 사유를 남긴다. A–B와 B–C가 부분 중복이면 연결된 의존 묶음을 함께 처리하되 세 관측 자체를 하나의 정확 중복으로 병합하지 않는다. 수동 독립성 선언으로 알려진 부분 중복을 무시할 수 없다. 이 묶음과 별개인 독립 관측은 계속 반영하며, 묶음 전체가 이미 LR1인 경우에는 추가 효과나 불필요한 평가 보류를 만들지 않는다.

서로 다른 관측의 LR 곱은 H와 그 대립 가설 각각에서 조건부 독립을 가정한다. 명시적 검증 근거가 없으면 이를 **제품 계산 모형의 가정**으로 표시한다. 출처가 다르다는 사실만으로 검증된 독립성이라고 표현하지 않는다.

검증된 같은 출처 계보에서 서로 다른 관측이 나왔으면 같은 관측으로 잘못 합치지 않는다. 동시에 공동 우도 모형도 없으면 해당 의존 묶음의 업데이트를 중립으로 보류하고 `PARTIAL` 사유를 남긴다. 이미 알려진 의존성을 단순한 독립성 체크로 무시하지 않는다.

## 6. 결과 점수와 등급

계산값 `score`는 0–1이고 UI에서는 100을 곱한 점수로 표시한다. `grade`는 반올림 전 계산값으로 구한다. 출처 등급과 최종 결과 등급은 서로 다른 값이다.

100에 가까운 값을 반올림해 100으로 보이지 않도록, 예를 들어 99.9873점은 화면에 `>99.9`로 표시한다. 표시 형식은 계산·저장 점수를 변경하지 않는다. 높은 점수나 A등급은 입력한 우도 모형의 결과이며, 공백이 모두 해소되었다거나 사건의 사실성이 확정되었다는 뜻은 아니다.

| 최종 점수 | 결과 등급 |
| --- | --- |
| 0 | F |
| 0 초과–20 이하 | E |
| 20 초과–40 이하 | D |
| 40 초과–60 이하 | C |
| 60 초과–80 이하 | B |
| 80 초과–100 이하 | A |

```ts
confidence.bayesian = {
  method: 'LINEAR_RELIABILITY_BAYES',
  baselineScore: 0.5, // 같은 관측의 원래 LR로 계산한 보정 전 비교값
  score: 0.5,
  grade: 'C',
  scoreBasis: 'POSTERIOR', // 모순된 경계 입력의 하한이면 CONSERVATIVE_LOWER_BOUND
  posterior: 0.5,
  range: [0.5, 0.5],
  // threshold, sufficient, assumptions, unknownReasons, trace, bindings 등
};
```

출력에는 적용한 원래 LR, 보정 LR, 고정 등급 계수, 기본값 사용 여부, 목표 사전확률, 중복 그룹과 제외 이유를 남긴다. 이 점수는 입력과 제품 모형에 따른 값이며 실측으로 검증된 정답 확률을 뜻하지 않는다.

Cluevia off는 `baselineScore`, on은 `score`를 표시한다. 두 값은 같은 목표·사전확률과 같은 적격 중복 제거 관측을 사용하며, off는 원래 LR, on은 출처 신뢰도를 반영한 보정 LR을 사용한다. off 값을 사전확률 자체로 바꾸어 비교하지 않는다. 예를 들어 prior=.5, LR=5, 출처 B이면 83.33점에서 80.77점으로 바뀐다. 출처 F이면 같은 원래 입력의 비교값 83.33점에서 중립 50점으로 바뀐다. 모든 LR이 중립 1이면 두 값은 모두 50점이며 차이를 만들기 위한 임의 감점은 하지 않는다. 보정 전 prior=1과 원래 LR=0이 충돌하면 비교값에도 하한 처리 사유를 남긴다.

운영 임계값은 저장한 정책을 사용하며 임의의 .8을 기본값으로 넣지 않는다. 높은 점수만으로 출처·자료·사건 공백이 닫히지는 않는다. 미완료 평가가 남으면 최종 수용을 보류하고 `BAYES_ASSESSMENT_INCOMPLETE`인 ROOT/PENDING `TRUST_WEAK` 공백에 이유를 남긴다.

사건 메타데이터는 원문의 실제 값과 인용을 보존한다. actor·location 등 자연어 명칭에서 서로 다른 문자 체계의 값을 비교하면 동일성도 불일치도 확정하지 않고 `UNKNOWN`으로 남긴다. 같은 필드의 다른 확정 충돌, 날짜·식별자·코드의 충돌은 계속 `MISMATCH`다. 번역 차이를 제거했다는 이유로 배치 기록을 전투 기록으로 바꾸거나 누락된 발생 시점을 채우지 않는다.

## 7. 출처 계보 추적

자료의 출처 URL, 인용 구간, 원출처 여부와 확인 근거를 보관한다. 검증한 복제·재인용과 통계적으로 계산한 LR은 구분한다. `NO_NEW_INFORMATION`은 내용상 추가 관측이 없는 판정이며, LLM이 수치 LR=1을 실측했다는 의미가 아니다.

1. 현재 자료를 유지하고 실제 출처·인용 URL 후보를 수집한다.
2. 원문을 읽어 인용 관계, 원본 여부와 내용 차이를 확인한다. 읽기 실패는 실패 상태로 보관한다.
3. 이미 관측한 내용의 복제라면 독립 자료를 추가하지 않고 해당 분기의 확장을 종료한다.
4. 새 내용이 있으면 출처 계보를 유지하고 추가 관측의 목표 관련성·중복·사건 일치를 확인한다.
5. 검증된 원자료에 도달하거나 더 이상 링크가 없을 때 종료한다. 순환, 깊이·요청·시간 예산 초과와 접근 실패도 종료 사유다.

계보의 실제 통계 LR이 미상이면 저장 값은 null로 유지할 수 있다. 목표 점수의 LR=1 기준값과 계보 통계가 확인되었다는 주장은 구분한다. 새로 찾은 자료는 다음 snapshot의 자료·사건·중복 검사를 거친 뒤 채택한다. 현재 입증 체인에 검증 없이 끼워 넣지 않는다.

## 8. 기존 품질 지지 점수와의 구분

기존 `r_source × c_material` 및 공유 atom을 이용한 AND·OR 품질 점수는 과거 결과를 읽고 입증 경로를 검사하는 별도 모형이다. 현재 화면의 기본 Confidence에 이 값이나 종전 power-discount 우도비를 섞지 않는다. 저장된 이전 평가를 읽을 때도 현재 목표·등급 정책으로 재계산하고, 재해석할 수 없는 과거 조건별 통계는 중립 기준값과 이관 사유로 표시한다.

## 9. 기본 그래프를 먼저 완성하는 실행 순서

기본 Why-not 그래프는 **온톨로지 설계와 객체·관계 추출을 기다리지 않고** 생성한다. 입력 원문과 URL 읽기 결과를 저장한 직후 `onInputsReady`가 `scheduleBaseline`을 호출한다. 업로드 자료도 실제로 읽은 chunk 발췌를 전달한다. 이때 기본 구조 생성과 주 분석은 병렬로 진행하며, 그래프 생성 요청에 자료 판정이나 중복 판정을 넣지 않는다.

기본 그래프가 먼저 완성되면 추출 결과가 0개인 상태에서도 Overview에 표시한다. 두 작업의 응답 속도에 따라 주 분석이 먼저 끝날 수는 있지만, Cluevia 진단은 **기본 그래프 저장과 주 분석 완료가 모두 확인된 뒤** 시작한다. 화면에 보여주기 위한 임의 지연이나 가상의 진행 단계를 두지 않는다.

<ResearchDiagram kind="early-overview" number="C1" />

| phase | 수행 작업 | 저장과 화면 |
| --- | --- | --- |
| `building-graph` | 목표·조건 DAG와 제공된 원문의 정확한 인용 연결 생성 | `Overview loading`; 아직 Cluevia 진단 단계가 아님 |
| `graph-ready` | 원문 일치·참조 검증을 통과한 기본 구조 저장 | `baseSnapshot`, `snapshot`, `graphReadyAt` 저장; 주 분석 중에는 `Overview ready` |
| `diagnosing` | 저장된 binding ID의 판정·중복 검토 후 Claude Low의 미평가 수치·출처 추정 | 기본 그래프를 유지하면서 Cluevia loading 표시 |
| `ready` | 결정적 공백 검사, 보정 전·후 점수와 보완 계획 계산 완료 | 진단·애니메이션 정보를 저장하고 Cluevia on 활성화 |

첫 모델 요청의 `mode: baseline`은 노드·사건 규칙과 `evidenceId`, `requirementId`, `quote`만 반환한다. 자료 연결은 실제 원문의 연속 인용이어야 하며 서버가 ID·인용 위치를 부여한다. 새 자료의 판정은 `UNREVIEWED`, 사건 메타데이터는 미평가, 중복 판정은 비어 있다. 연결이 있다는 사실을 지지 판정으로 표시하지 않는다. 없는 자료를 가상 evidence 노드로 만들지도 않는다.

`graph-ready`이면서 `awaitingAnalysis=true`인 실행은 사용 가능한 기본 그래프를 보존한 대기 상태다. 이 상태에서는 review·Claude Low를 호출하지 않으며 Cluevia loading도 표시하지 않는다. 기본 그래프 저장과 주 분석 완료의 두 경로가 각각 최신 저장 상태를 다시 읽고 `releaseAnalysis`로 대기를 해제하므로, 완료 순서가 바뀌어도 같은 진단을 중복 호출하지 않는다.

진단 큐의 `mode: review` 요청은 지정한 저장 binding ID의 판정·이유·부족한 항목·원문 기반 메타데이터와 같은 부모 안의 중복 쌍만 반환한다. 노드, 인용문, 자료 ID와 기본 연결 구조를 다시 쓰는 응답은 거부한다. 지정한 판정의 누락·반복과 존재하지 않는 참조도 거부한다.

`baselineInputHash`에는 질문, 저장된 입력 원문의 식별자·내용 hash·URL, 업로드 ID를 포함한다. 진행률이나 런타임 플래그가 바뀐 것은 입력 변경으로 취급하지 않는다. 주 분석 완료 시 이 입력이 일치해야 최종 `analysisRevision`으로 연결한다. 원문이 달라졌거나 주 분석이 실패·취소되면 기본 그래프를 보존하고 자동 진단을 시작하지 않는다. 서버 재시작 후에도 `awaitingAnalysis`를 확인하므로 대기 중인 그래프가 바로 진단 단계로 넘어가지 않는다.

자료 보완은 기존 목표와 노드 구조, 이전 검토를 보존한다. 새 자료 연결의 판정만 허용하며 원래 자료의 수동 판정을 자동 응답으로 덮어쓰지 않는다. 기본 그래프가 완성된 뒤 진단이 실패하거나 취소되어도 저장된 기본 그래프는 남는다. 주 분석 완료가 확인된 중단 진단은 저장된 기본 구조에서 이어갈 수 있다.

브라우저가 그래프를 여는 GET 요청은 모델 호출을 시작하지 않는다. 서버 준비 작업은 저장된 실행 상태와 입력·분석 버전으로 중복을 방지한다. 기본 그래프가 없는 동안은 `Overview loading`, 기본 그래프만 준비되면 `Overview ready`, 실제 `diagnosing` 중에만 `Cluevia loading`을 표시하며 이 버튼들은 비활성 상태다. 공백 결과·보완 계획·애니메이션 정보를 저장하여 `preparation.ready=true`가 되고 주 분석도 완료되어야 `Cluevia on`을 활성화한다.

Cluevia on/off는 완성된 기본 그래프 위에 저장된 진단을 표시하거나 숨기는 동작이며, 노드·위치·인용을 새로 생성하지 않는다. 애니메이션의 공백 ID·시작 지연·지속 시간도 저장하여 새 세션에서 같은 결과를 재생한다. 경고를 선택하면 해당 공백의 이유와 보완 내용을 그래프 위에서 확인한다. `confidence.bayesian.score`는 0–1, 표시용 `preparation.baselineScore`와 `preparation.score`는 0–100 단위다.

최초 Confidence는 완료된 실행의 `preparation.ready`와 유효한 저장 점수가 확인된 뒤에만 숫자·등급으로 표시한다. 기본 그래프 준비·진단·Claude Low 추정 중에는 **Calculating…**을 표시하며, 계산 기준값 .5를 이미 계산한 50점처럼 미리 표시하지 않는다. 보완 재계산 중에는 이전에 확정한 점수와 Calculating…을 함께 유지한다. 완료 후 실제 계산 결과가 50이면 그대로 50 C를 표시한다.

보완 계획의 `PLANNED`는 필요한 자료·행동을 정했다는 뜻이며 자료 확보 완료를 뜻하지 않는다. Cluevia를 켠 상태에서 보완하면 재검사 중에는 마지막 점수를 유지하고, 새 평가가 저장되면 공백과 점수를 갱신한다. 다른 세션에서 저장한 평가도 주기적으로 확인한다. 반복 제출한 같은 관측이나 LR=1인 중립 자료 때문에 점수를 중복 가산하지 않는다.

### 보완 URL과 새 평가

보완 자료의 URL 필드 또는 본문에서 한 줄 전체로 입력한 URL은 기본 연결을 만들기 전에 실제 원문을 읽는다. 사용자가 작성한 짧은 설명과 웹에서 읽은 본문은 **서로 다른 자료**로 저장한다. 사용자의 설명을 링크 발행기관의 공식 문서로 분류하지 않으며, 링크 문자열 자체를 페이지 본문으로 사용하지 않는다. 본문을 확보한 뒤 기존 요구조건에 연결하고 자료 판정·Claude Low 추정·공백과 점수 계산을 새 버전에서 수행한다.

`WhyRun.urlReads`에 성공·실패, 원래 URL과 최종 URL, 읽은 길이, 잘림 여부와 실패 사유를 남긴다. 공개 웹 문서는 한 번에 최대 8개, 응답당 2 MB, 요청당 10초·전체 25초의 한도로 읽으며, 보완 snapshot에는 자료당 최대 30,000자를 보존한다. 접근에 실패해도 본문을 추측하지 않는다. 남은 실제 입력이 있으면 그 범위만 검토하고, 읽기에 실패하여 새 원문이 하나도 없으면 해당 보완 실행을 실패 상태로 남긴다.

기존 원문과 내용 hash가 같은 자료는 추가하지 않는다. 모두 이미 평가한 원문이면 모델을 다시 호출하지 않고 동일한 입력의 계산 결과를 보존한다. URL이 같다는 사실만으로 서로 다른 관측을 중복 처리하지 않으며, 확인된 동일 관측에 서로 다른 LR이 붙으면 임의로 유리한 값 하나를 택하지 않고 평가 불일치를 남긴다.

## 10. Claude Low의 미평가 입력 추정

자료 판정이 끝난 뒤 `estimate-confidence` 단계가 **Claude, low effort**로 미평가 목표 사전확률·자료 우도비·출처 등급을 추정한다. 이미 저장된 그래프, 인용문과 수동 검토는 유지한다. 출처 분류는 실제 binding에 연결된 자료를 우선하며 점수에 쓰이지 않는 발췌 전체를 불필요하게 다시 분류하지 않는다.

| 입력 | 모델 추정 범위 | 저장 구분 |
| --- | --- | --- |
| 목표 사전확률 | .01–.99 | prior의 `basis: MODEL_ESTIMATE` |
| 자료 우도비 | .01–100 | likelihood의 `basis: MODEL_ESTIMATE`, `hypothesisId: rootId` |
| 미평가 출처 등급 | A–F | `sourceEstimation` 이력과 기존 고정 계수 |

이 범위는 검증되지 않은 모델 추정이 0·1 또는 무한한 확신을 만들지 않게 제한하는 제품 규칙이다. 사용자가 제공한 실제 통계·수동 보정값의 범위를 이 제한으로 변경하지 않는다. `CALIBRATED`, `EXPERT_ESTIMATE`와 이미 저장된 수치·등급은 자동 추정으로 교체하지 않는다.

모든 새 수치와 출처 판정에는 이유 및 제공된 자료의 정확한 인용 anchor가 필요하다. 서버가 `evidenceId`, `quote`, `start`, `end`를 원문과 대조하고 모델명, low effort, 추정 시각을 함께 저장한다. LR은 해당 binding의 실제 인용을 포함해야 하며, 출처 판정은 해당 자료의 인용을 포함해야 한다. A등급은 이미 `originalVerified: true`로 확인된 원자료만 허용하며 모델 응답으로 이 검증 플래그를 켜지 않는다.

미분류 출처가 40개 이하면 응답 schema의 출처 개수를 대상 수로 고정하여 판정 누락을 방지한다. 한 번의 응답은 최대 40개이며 그보다 많은 대상을 모두 평가했다고 표시하지 않는다. 명시적으로 null을 반환한 이유와 누락·검증 오류는 `sourceReason` 및 `estimationNotes`에 남긴다. 출처 답변이 없다는 사실을 검증된 등급으로 치환하지 않으며, 이를 보완하기 위한 추가 모델 호출을 자동으로 반복하지 않는다.

인용이 틀리거나 허용 범위를 벗어난 개별 추정은 적용하지 않고 중립 기본값과 `policy.bayes.estimationNotes`에 사유를 남긴다. 나머지 유효한 추정은 보존한다. 존재하지 않는 ID, 중복 대상 ID나 그래프를 고치려는 응답은 거부한다. 부족한 근거로 판정된 자료의 LR을 임의로 올려 지지 자료처럼 만들지 않는다.

`INSUFFICIENT`, `IRRELEVANT`, `UNREVIEWED` 자료의 모델 LR은 **정확히 1**로 두고 실제 자료 인용과 중립 판단 이유를 남긴다. `SUPPORTED`는 LR≥1, `REFUTED`는 LR≤1 방향을 지킨다. 모든 자료가 불충분이면 출처 등급과 중립 LR 추정 이력이 저장되어도 보정 전·후 점수는 모두 50일 수 있으며, 이를 지지 또는 입증 완료로 해석하지 않는다.

완료된 `INSUFFICIENT` 판정에 LR=1을 저장한 것은 정상적인 중립 입력이다. 이 값만으로 우도비 방향의 미평가 공백을 추가하지 않는다. 원래의 자료 부족 판정은 유지하며, 별도의 적격 보완 자료가 같은 요구를 충족하면 이전 부족 사유는 대안 경로의 기록으로 남길 수 있다. 불충분 판정에 LR≠1을 넣거나 원문 처리가 끝나지 않은 경우에는 계속 적용을 보류한다.

예를 들어 목표 기준값 .5에서 기존 자료가 불충분·LR1이고, 새로운 독립 관측이 `SUPPORTED`, 출처 B, LR4라면 보정 LR은 .8×4+.2=3.4이고 점수는 3.4/4.4≈77.27이다. 같은 관측을 다시 제출하면 곱을 추가하지 않는다. 반증의 `LR<1`은 점수를 낮출 수 있다. 보완 자료를 제출했다는 사실 자체에 가점을 주지 않는다.

모델 추정은 원문에 대한 판단값이며 실측 통계로 표시하지 않는다. UI에서는 AI estimate로 구분하고, 사용자가 그 숫자나 이유를 수정하면 수동 추정으로 전환한다. 모델 값이 없는 경우의 .5·1 기본값과 입력 범위는 계속 유지한다. 추정 호출이 실패해도 완성된 기본 그래프와 기존 검토 결과는 보존된다.
