---
title: "証拠の関連付けモデル"
description: "オブジェクト、関係、イベント、出典を分け、すべての解釈を原文に戻すClueviaのデータモデル。"
---

Clueviaのグラフは、質問に答えるために資料をまとめた文書です。線をたどると関係を読み、出典番号を押すと、その関係がどの資料から出たのかを確認できます。

## 1つの質問、6つのコンポーネント [#하나의-질문-여섯-가지-구성-요소]

| コンポーネント | 記録する内容 | 例 |
| --- | --- | --- |
| オブジェクト · `nodes` | 人、組織、船、場所などを調べる対象 | 調査対象船舶 |
| 関係・`edges` | 2つのオブジェクト間の接続とその解釈 | 船が特定の港を訪問したと報告されています |
| 事件・`events` | 資料に日付が記載されている日または期間 | レポートが公開された日付 |
| 出典 · `sources` | 資料タイトル、リンク、抜粋、発行情報 | 公式レポート |
| 分析・`findings` | 質問に関してまとめた内容 | 複数のオブジェクトと関係を一緒に説明する文 |
| 限界・`limitations` | 資料で確認できない範囲 | ロケーション履歴だけでは取引内容が不明 |

`groups`は、オブジェクトを分類する名前と色を提供します。グループの色は画面を読むための区別であり、信頼度や危険度を意味しません。

## 関係を読むとき [#관계를-읽을-때]

関係には`reported`または`inferred`状態が必ず入ります。

| 状態 | 意味 | 画面表現 |
| --- | --- | --- |
| `reported` | 資料が直接報告した関係 | 一般的な接続線と状態説明 |
| `inferred` | 資料に基づいて解釈した関係 | 点線と推論の説明 |

<Callout title={"出典があると証明されたことは異なります"}>
`reported`は、Clueviaが事実を独立して検証したという意味ではありません。 `inferred` やはり確率や確定判定ではありません。関係の説明と原文、グラフの限界を一緒に読まなければなりません。
</Callout>

例えば、両方の船の近接記録は、遭遇を説明する根拠となり得る。その記録だけで貨物移転や取引内容を断定することはできません。グラフ内のオブジェクトが近くに配置されているという事実にも地理的な意味はありません。

## 出典から離れないグラフ [#출처에서-떨어져-나가지-않는-그래프]

オブジェクト・関係・事象・分析には、それぞれ1つ以上の`sourceIds`が必要です。すべての参照は、文書の`sources`内に実際に存在する必要があります。ノードを結ぶ関係の両端、事象が指すオブジェクト、分析が指す関係も同様に検証します。

```text
분석 문장 → 관련 객체와 관계 → 출처 ID → 자료 제목·발췌·원문 링크
```

この検証が確認するのは、**接続構造の一貫性**である。出典が実際に主張を支持するかは、原文との対照が必要となる。モデル抽出でも正確な引用と識別根拠を検査するが、意味の正確さを保証するものではない。

## 資料の主張とユーザーレビュー [#자료의-주장과-사용자-검토]

関係の`claim.stance`は資料に現れた主張・婦人・撤回・不確実状態を保存します。同じオブジェクトに矛盾する主張があれば、記録別に残して自動事実判定をしません。

ユーザーは関係に別々のレビューステータスとメモを残すことができます。原文の主張態度、抽出の`reported`/`inferred`、ユーザーのレビュー結果は異なる情報です。

サーバーは引用テキストのハッシュとUTF-16位置候補も保持します。同じフレーズが繰り返されると、あいまいさを維持します。統合ケースに保存されているオブジェクトIDを関連付けますが、名前が同じであるため、新しいオブジェクトを結合しません。

## 日付がある場合にのみタイムラインに [#날짜가-있을-때만-타임라인에]

オブジェクトや関係があるとイベント日付を作成しません。資料に日付がない場合は、`events: []`のままにしても有効なグラフです。この場合、Timelineは日付付きイベントがないことを示しています。

イベントには開始日`date`とオプションの終了日`endDate`を入れます。終了日は開始日と同じかそれ以降でなければなりません。日付は`YYYY-MM-DD`、時刻はタイムゾーンを含むISO形式で記録されます。

## 同じ文書を3つの視点に [#같은-문서를-세-가지-관점으로]

| 見る | 基準 | 読む良い質問 |
| --- | --- | --- |
| Board | オブジェクト間の関係に応じた自動配置 | 何が何とつながるか。 |
| Lanes | `groups`による分類 | どのような対象が登場するのか？ |
| Timeline | イベントの指定された日付と期間 | 何がいつ起こったか。 |

3つのビューは同じ`GraphDocument`を使用します。ビューの切り替えにより、マテリアルが新しく分析されたり、モデルが再度呼び出されなくなります。 `highlighted`関係の強調度作成者が指定した表示で、自動信頼度スコアではありません。

## グラフの作成パス [#그래프의-작성-경로]

`origin`は、文書がどのパスで作成されたかを示します。

| 値 | 画面表示 | 意味 |
| --- | --- | --- |
| `published-source` | PUBLIC SOURCES | 公開文献で構成した事例 |
| `imported` | IMPORTED GRAPH | ファイルから取得したグラフ |
| `codex`, `jev`, `structured` | 分析パスの表示 | 文書抽出・Jev・表変換で生成したグラフ |
| `aip` | 以前のAIP作成パス | 既存のFoundryアダプタによって生成されたグラフ |
| `demo` | DEMO | デモ文書 |

ファイルをインポートすると、以前の作成パスに関係なく`imported`として保存されます。このマークは作成パスを示し、コンテンツの正確性を認証しません。
