title: "证据关联模型"
description: "Cluevia的数据模型将对象，关系，事件和源分开，并将所有解释返回原始文本。"
---

图是围绕问题组织资料的文档。可以沿边理解关系，但每项解释都应能够追溯到其原始来源。

## 一个问题，六个组成部分 [#하나의-질문-여섯-가지-구성-요소]

| 组件 | 你录制的内容 | 举例 |
| --- | --- | --- |
| 对象 · `nodes`  | 需要寻找的东西:人，组织，船只，地点等 | 被调查的船舶 |
| 关系 · `edges`  | 两个物体之间的连接及其解释 | 据报道，一艘船已访问了特定的港口 |
| 事件 · `events`  | 在材料中指定的日期或时间段。 | 报告发布日期 |
| 来源 · `sources`  | 材料标题，链接，摘录，出版信息 | 官方报告 |
| 分析 · `findings` | 与问题相关的结论摘要 | 描述多个对象及关系的句子 |
| 限制 `limitations`  | 无法通过数据确认的范围 | 单独地址历史不透露交易细节 |

 `groups` 提供一个名称和颜色来分类对象。 组颜色是用于屏幕阅读，并不能表明信任或风险水平。

## 在阅读关系时 [#관계를-읽을-때]

关系必须标为 `reported` 或 `inferred`。

| 状态 | 的意思 | 屏幕表示 |
| --- | --- | --- |
| `reported` | 资料直接报告的关系 | 实线及状态说明 |
| `inferred` | 根据资料作出的解释 | 虚线及推断说明 |

<Callout title={"有来源不等于已经证实"}>
`reported` 不表示 Cluevia 已独立核实事实；`inferred` 也不是概率或确定性判定。应结合关系说明、原文与图的局限阅读。
</Callout>

例如，两艘船近距离接触的记录可以支持对相遇的解释，却不能单独证明货物转移或交易内容。图中对象位置接近也不具有地理含义。

## 没有离开源头的图表 [#출처에서-떨어져-나가지-않는-그래프]

对象、关系、事件及分析条目各自至少需要一个 `sourceIds` 引用。所有引用必须实际存在于文档的 `sources` 中。关系的两个节点端点、事件引用的对象和分析引用的关系，同样接受引用一致性检查。

```text
분석 문장 → 관련 객체와 관계 → 출처 ID → 자료 제목·발췌·원문 링크
```

这种验证确保连接结构是一致的。 一个人必须与原始文本进行检查，以确定来源是否确实支持这一说法。 在模型提取过程中，也会进行精确的文本引用和识别基础检查，但不能保证语义准确性。

## 材料主张和用户评价 [#자료의-주장과-사용자-검토]

`claim.stance` 记录资料中的肯定、否认、撤回与不确定立场。对同一事项存在矛盾主张时，分别记录，不自动裁定事实。

用户可另行填写关系审查状态与备注。原文中的主张立场、抽取关系的 `reported` / `inferred` 分类，以及用户审查结果是三类不同信息。

服务器还保存引文、原文哈希及 UTF-16 位置候选。同一句话重复出现时保留歧义。整合案例连接已保存的对象 ID，不会仅因名称相同而合并新对象。

## 只有在时间线上如果有日期 [#날짜가-있을-때만-타임라인에]

不能仅因存在对象或关系就编造事件日期。资料未记载日期时，`events: []` 仍属于有效图。此时 Timeline 显示没有带日期事件的状态。

事件包含开始日期 `date` 和可选结束日期 `endDate`；结束日期须等于或晚于开始日期。日期采用 `YYYY-MM-DD`，具体时刻采用含时区的 ISO 格式。

## 同样的文件从三个角度来看 [#같은-문서를-세-가지-관점으로]

| 视图 | 布局依据 | 适合回答的问题 |
| --- | --- | --- |
| Board | 基于对象之间的关系的自动放置 | 什么与什么有关? |
| Lanes | 按 `groups` 分列 | 出现了哪些类型的对象？ |
| Timeline | 活动的指定日期和时间 | 什么发生了，什么时候? |

三种视图共用同一 `GraphDocument`。切换视图不会重新分析资料或调用模型。`highlighted` 关系的突出显示也是作者指定的标记，不代表自动计算的可信度分数。

## 图表创建路径 [#그래프의-작성-경로]

 `origin` 表示文件创建的路径。

| 价值 | 屏幕显示 | 的意思 |
| --- | --- | --- |
| `published-source` | PUBLIC SOURCES | 从开放文献中构建的例子 |
| `imported` | IMPORTED GRAPH | 从文件中进口的图表 |
| `codex`, `jev`, `structured` | 显示分析路径 | 从文件提取，Jev和表格转换中创建的图表 |
| `aip` | 上一个 AIP 创建路径 | 由旧版 Foundry 适配器生成的图 |
| `demo` | DEMO | 演示文件 |

文件导入后，无论原来的生成方式如何，均保存为 `imported`。这些标记说明文档的生成途径，并不证明内容正确。
