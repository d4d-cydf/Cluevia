Clueviaは、React画面とNode APIサーバー、SQLiteリポジトリで構成されています。ドキュメントサイトは`docs/`の別途Next.js・Fumadocsパッケージであり、静的に配布できます。

## 処理層 [#처리-계층]

| 階層 | 実装 | 役割 |
| --- | --- | --- |
| リクエスト入力 | `HomeScreen.tsx` | 質問・資料・確認質問・分析範囲 |
| HTTP | `server/product-api.ts` | 認証、アップロード、作業・グラフ・オントロジー API |
| ジョブの実行 | `server/jobs.ts` | キュー、進行状況、キャンセルおよび再開 |
| オントロジー設計 | `server/ontology-planner.ts` | 資料プロファイルとユーザー意図で定義・マッピング生成 |
| 材料処理 | `server/generic-ingest.ts`, `server/analysis-pipeline.ts` | 表変換、文書抽出、Jev判定とキャッシュ |
| 検証・保存 | `server/ontology.ts`, `server/ontology-store.ts` | 原文・スキーマ検査、オブジェクト・主張・グラフ保存 |
| ケース統合 | `server/analysis-case.ts` | 同じタスクの記録と保存オブジェクトの関連付け |
| 画面計算 | `GraphRenderer.tsx`, `graph-exploration.ts` | ナビゲーション範囲とグラフ座標 |

設計と文書抽出はCodexを使用し、Jevは設定されている場合は限られた判断に参加します。以前のFoundry AIPモジュールは残っていますが、現在のホームとAPIのデフォルトの実行パスではありません。

## 分析作業の寿命 [#분석-작업의-수명]

```text
범위 확인 → 원문 업로드 → queued → running → 완료 / 실패 / 취소
                                       │
                                       └→ 구간별 검증·저장 → 화면 갱신
```

全体のジョブは一度に1つずつ実行し、実行・待機合計最大5個を受け取ります。ジョブ内の抽出ワーカーの並行性は別々の設定です。失敗・キャンセル・再起動の後には、保存されたチェックポイントで残った区間を引き続き実行できます。

質問だけを入力したジョブはオントロジーのみを保存し、実際にグラフを生成しません。完了した部分結果は、ジョブ全体が終了する前に分析画面に表示されます。

## ストレージ階層 [#저장-계층]

| 場所 | 内容 |
| --- | --- |
| サーバーデータディレクトリ、基本 `.cluevia/` | SQLite、アップロード原文、作業と記録、オントロジー・グラフ・根拠 |
| ブラウザIndexedDBとタブドラフト | 分析開始前要請・添付復旧用臨時コピー |
| ブラウザ`localStorage` | 手動カード配置、画面状態、明示的に選択したブラウザ保存グラフ |

デフォルトのリポジトリはサーバーなので、同じサーバーに接続している他のブラウザでも保存グラフを照会します。単一の共有ワークスペースであり、ユーザー固有のデータ分離は提供されません。

## 実行方法 [#실행-방식]

`npm run dev`と`npm run preview`はViteに製品APIをリンクします。 `npm run build`後`npm start`は、Nodeサーバーが構築された画面とAPIを一緒に提供します。同じデータディレクトリを使用する複数のサーバーを同時に実行しません。

`dist/`だけ静的に上げると、サーバージョブとストアAPIは実行されません。ドキュメントの`docs/out/`は、APIなしで静的に提供できます。 [展開範囲](/ja/docs/development/deployment)を参考にしてください。

## アルゴリズム境界 [#알고리즘-경계]

抽出結果の意味は[データ構造化](/ja/docs/algorithms/extraction)、原文・参考文献の妥当性は[データ検証](/ja/docs/algorithms/validation)、画面上の位置と表示セットは[グラフの配置](/ja/docs/algorithms/board-layout)と[検索とキャッシュ](/ja/docs/algorithms/exploration)で扱います。
