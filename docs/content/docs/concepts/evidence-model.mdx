---
title: 근거가 연결되는 방식
description: 객체, 관계, 사건, 출처를 나누고 모든 해석을 원문으로 되짚는 Cluevia의 데이터 모델.
---

Cluevia의 그래프는 질문에 답하기 위해 자료를 정리한 문서입니다. 선 하나를 따라가면 관계를 읽고, 출처 번호를 누르면 그 관계가 어떤 자료에서 나왔는지 확인할 수 있습니다.

## 하나의 질문, 여섯 가지 구성 요소

| 구성 요소 | 기록하는 내용 | 예시 |
| --- | --- | --- |
| 객체 · `nodes` | 사람, 조직, 선박, 장소 등 살펴볼 대상 | 조사 대상 선박 |
| 관계 · `edges` | 두 객체 사이의 연결과 그 해석 | 선박이 특정 항구를 방문했다고 보고됨 |
| 사건 · `events` | 자료에 날짜가 명시된 일 또는 기간 | 보고서가 공개된 날짜 |
| 출처 · `sources` | 자료 제목, 링크, 발췌, 발행 정보 | 공식 보고서 |
| 분석 · `findings` | 질문과 관련해 정리한 내용 | 여러 객체와 관계를 함께 설명하는 문장 |
| 한계 · `limitations` | 자료로 확인할 수 없는 범위 | 위치 기록만으로는 거래 내용을 알 수 없음 |

`groups`는 객체를 분류하는 이름과 색상을 제공합니다. 그룹 색은 화면을 읽기 위한 구분이며 신뢰도나 위험도를 뜻하지 않습니다.

## 관계를 읽을 때

관계에는 `reported` 또는 `inferred` 상태가 반드시 들어갑니다.

| 상태 | 의미 | 화면 표현 |
| --- | --- | --- |
| `reported` | 자료가 직접 보고한 관계 | 일반 연결선과 상태 설명 |
| `inferred` | 자료를 바탕으로 해석한 관계 | 점선과 추론 설명 |

<Callout title="출처가 있다는 것과 입증됐다는 것은 다릅니다">
`reported`는 Cluevia가 사실을 독립적으로 검증했다는 뜻이 아닙니다. `inferred` 역시 확률이나 확정 판정이 아닙니다. 관계의 설명과 원문, 그래프의 한계를 함께 읽어야 합니다.
</Callout>

예를 들어 두 선박의 근접 기록은 조우를 설명하는 근거가 될 수 있습니다. 그 기록만으로 화물 이전이나 거래 내용을 단정할 수는 없습니다. 그래프에서 객체가 가깝게 배치됐다는 사실에도 지리적 의미는 없습니다.

## 출처에서 떨어져 나가지 않는 그래프

객체·관계·사건·분석에는 각각 하나 이상의 `sourceIds`가 필요합니다. 모든 참조는 문서의 `sources` 안에 실제로 존재해야 합니다. 노드를 연결하는 관계의 양 끝, 사건이 가리키는 객체, 분석이 가리키는 관계도 같은 방식으로 검증합니다.

```text
분석 문장 → 관련 객체와 관계 → 출처 ID → 자료 제목·발췌·원문 링크
```

이 검증은 **연결 구조가 일관적인지** 확인합니다. 출처가 실제로 주장을 뒷받침하는지는 사람이 원문과 대조해야 합니다. 모델 추출에는 정확한 원문 인용과 식별 근거 검사도 적용하지만 의미의 정확성을 보장하는 것은 아닙니다.

## 자료의 주장과 사용자 검토

관계의 `claim.stance`는 자료에 나타난 주장·부인·철회·불확실 상태를 보존합니다. 같은 객체에 상충하는 주장이 있으면 기록별로 남기고 자동 사실 판정을 하지 않습니다.

사용자는 관계에 별도의 검토 상태와 메모를 남길 수 있습니다. 원문의 주장 태도, 추출의 `reported`/`inferred`, 사용자의 검토 결과는 서로 다른 정보입니다.

서버는 인용 텍스트의 해시와 UTF-16 위치 후보도 보관합니다. 같은 문구가 반복되면 모호함을 유지합니다. 통합 케이스에서 저장된 객체 ID를 연결하되 이름이 같다는 이유로 새 객체를 합치지 않습니다.

## 날짜가 있을 때만 타임라인에

객체나 관계가 있다고 사건 날짜를 만들어 넣지 않습니다. 자료에 날짜가 없으면 `events: []`로 두어도 유효한 그래프입니다. 이 경우 Timeline은 날짜가 있는 사건이 없다는 상태를 보여 줍니다.

사건에는 시작일 `date`와 선택적인 종료일 `endDate`를 넣습니다. 종료일은 시작일과 같거나 이후여야 합니다. 날짜는 `YYYY-MM-DD`, 시각은 시간대가 포함된 ISO 형식으로 기록합니다.

## 같은 문서를 세 가지 관점으로

| 보기 | 기준 | 읽기 좋은 질문 |
| --- | --- | --- |
| Board | 객체 사이의 관계에 따른 자동 배치 | 무엇이 무엇과 연결되는가? |
| Lanes | `groups`에 따른 분류 | 어떤 종류의 대상이 등장하는가? |
| Timeline | 사건의 명시된 날짜와 기간 | 무엇이 언제 일어났는가? |

세 보기는 같은 `GraphDocument`를 사용합니다. 보기 전환으로 자료가 새로 분석되거나 모델을 다시 호출하지 않습니다. `highlighted` 관계의 강조도 작성자가 지정한 표시이며 자동 신뢰도 점수가 아닙니다.

## 그래프의 작성 경로

`origin`은 문서가 어떤 경로로 만들어졌는지 표시합니다.

| 값 | 화면 표시 | 의미 |
| --- | --- | --- |
| `published-source` | PUBLIC SOURCES | 공개 문헌으로 구성한 사례 |
| `imported` | IMPORTED GRAPH | 파일에서 가져온 그래프 |
| `codex`, `jev`, `structured` | 분석 경로 표시 | 문서 추출·Jev·표 변환에서 생성한 그래프 |
| `aip` | 이전 AIP 작성 경로 | 기존 Foundry 어댑터에서 생성한 그래프 |
| `demo` | DEMO | 데모 문서 |

파일을 가져오면 이전 작성 경로와 관계없이 `imported`로 저장합니다. 이 표시는 작성 경로를 알려 주며 내용의 정확성을 인증하지 않습니다.
