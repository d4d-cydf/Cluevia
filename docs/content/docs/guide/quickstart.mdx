## 1. 앱 실행

Node.js **22.17 이상**을 사용하고 프로젝트 루트에서 실행합니다. Windows PowerShell과 WSL 중 패키지를 설치한 환경에서 앱도 실행하세요.

```bash
npm ci --include=dev
npm run dev
```

앱 주소는 `http://127.0.0.1:5173`입니다. 의존성을 설치하지 않거나 다른 운영체제의 `node_modules`를 사용하면 Vite를 찾지 못할 수 있습니다.

## 2. 공개 사례 열기

보관함의 **GFW · Galápagos 2017**을 열거나 `/case/gfw-galapagos/overview`로 이동합니다. 12개 객체, 15개 관계, 2개 사건, 3개 출처가 있는 미리 작성된 예제입니다. 모델 로그인 없이 사용할 수 있습니다.

**Overview**에서 질문에 직접 답하는 대상과 관계를 먼저 살펴봅니다. 결과가 없으면 찾지 못했다는 안내를 표시합니다. **Board / Lanes**에서 전체 객체와 관계를 선택해 설명·출처를 확인합니다. 실제 선박의 현재 위치가 아니라 2017년 공개 문헌 기반 사례입니다.

## 3. 자신의 자료로 분석

새 온톨로지 설계와 문서 분석을 위해 앱을 실행하는 같은 컴퓨터·OS·사용자 계정에서 로그인합니다.

```bash
npm run codex:login
npm run codex:status
```

1. 홈에서 질문과 UTF-8 텍스트 자료를 입력합니다.
2. **START INVESTIGATION**을 누르고 필요한 확인 질문에 답합니다.
3. 분석 목적·범위·원하는 결과를 확인하고 **이 범위로 분석 시작**을 누릅니다.
4. `/analysis/:jobId`에서 실제 진행 상태와 저장이 끝난 부분 결과를 확인합니다.
5. **ONTOLOGY**에서 유형·속성·관계 정의와 저장된 객체의 근거를 확인합니다.

질문만 있으면 온톨로지를 설계합니다. 실제 객체·관계를 생성하려면 근거 자료가 필요합니다. 질문 없이 자료만 첨부하면 자료를 정리하는 기본 요청을 사용합니다.

자료는 한 작업에 최대 10개입니다. 원시 파일 업로드의 앱 크기 상한은 기본적으로 없지만 서버·브라우저·프록시 자원 제한은 적용됩니다. PDF·사진·Office 파일은 내용을 UTF-8 텍스트로 먼저 추출하세요. URL만으로 웹 본문을 수집하지 않습니다.

Jev 판정은 선택 사항입니다. 사용할 경우 기존 `.env.local`에 `TYPESAFE_API_KEY`를 설정하고 서버를 재시작합니다. 이미 있는 환경 파일을 덮어쓰지 마세요. 자세한 프로젝트 설정은 저장소 [README](https://github.com/d4d-cydf/Cluevia/blob/main/README.md)를 참고하세요.

## 4. 다시 열기와 백업

케이스 사이드바에서 같은 서버에 저장된 결과를 다시 엽니다. 작업이 실패하거나 취소되었으면 **남은 구간 이어서 분석**을 사용합니다. 완료한 기록은 유지됩니다.

개별 그래프 JSON과 통합 케이스 내보내기는 형식이 다릅니다. [저장과 가져오기](/docs/guide/import-export)에서 백업·이동 범위를 확인하세요.
