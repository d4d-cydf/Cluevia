## 1。アプリの実行 [#1-앱-실행]

Node.js **22.17以上**を使用し、プロジェクトルートで実行します。 Windows PowerShellとWSLの間にパッケージをインストールした環境でアプリを実行してください。

```bash
npm ci --include=dev
npm run dev
```

アプリのアドレスは`http://127.0.0.1:5173`です。依存関係をインストールしない場合、または他のオペレーティングシステムの`node_modules`を使用すると、Viteが見つからない可能性があります。

## 2。公開ケースを開く [#2-공개-사례-열기]

ライブラリの**GFW・Galápagos2017**を開くか、`/case/gfw-galapagos/overview`に移動します。 12個のオブジェクト、15個の関係、2個のイベント、3個の出典を持つ事前に作成された例です。モデルログインなしで使用できます。

**Overview**で質問に直接答えるターゲットとの関係を最初に調べます。結果がなければ、見つからなかったという指示が表示されます。 **Board / Lanes**でオブジェクト全体と関係を選択して説明・出典を確認します。実際の船舶の現在位置ではなく、2017年の公開文献ベースの事例です。

## 3。自分の資料で分析 [#3-자신의-자료로-분석]

新しい オントロジー 設計とドキュメント分析のためにアプリを実行する同じコンピュータ・OS・ユーザーアカウントでログインします。

```bash
npm run codex:login
npm run codex:status
```

1. ホームで質問とUTF-8テキストデータを入力します。
2. **START INVESTIGATION**をタップし、必要な確認質問に答えます。
3. 分析目的・範囲・必要な結果を確認し、**この範囲で分析開始**を押します。
4. `/analysis/:jobId`で実際の進行状況と保存済みの部分結果を確認します。
5. **ONTOLOGY**でタイプ・属性・関係定義と保存されたオブジェクトの根拠を確認します。

質問があればオントロジーを設計します。実際のオブジェクト・関係を生成するには、根拠資料が必​​要です。質問なしで資料を添付する場合は、資料を整理する基本的な要求を使用します。

材料は1つの作業に最大10個です。ネイティブファイルアップロードのアプリサイズの上限はデフォルトではありませんが、サーバー、ブラウザ、プロキシリソースの制限は適用されます。 PDF・写真・Officeファイルは内容をUTF-8テキストで先に抽出してください。 URLだけでWeb本文を収集しません。

Jev の評決は任意です。使用する場合は、`TYPESAFE_API_KEY` を既存の `.env.local` に設定し、サーバーを再起動します。すでに存在する環境ファイルを上書きしないでください。プロジェクトの詳細な設定については、リポジトリ[README](https://github.com/d4d-cydf/Cluevia/blob/main/README.md)を参照してください。

## 4。再度開くとバックアップ [#4-다시-열기와-백업]

ケースサイドバーで同じサーバーに保存されている結果を再度開きます。ジョブが失敗またはキャンセルされた場合は、**残りの区間で分析**を使用します。完了した記録は保持されます。

個々のグラフJSONと統合ケースのエクスポートは形式が異なります。 [保存とインポート](/ja/docs/guide/import-export)でバックアップ・移動範囲を確認してください。
