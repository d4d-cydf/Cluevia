## 1. 开始一个问题。 [#1-질문에서-출발하기]

例如:

> Fu Yuan Yu Leng 999 遭遇过的船舶与加拉帕戈斯查扣事件有何关联？

阅读 **CASE BRIEF** 摘要及 **READ WITH CONTEXT** 中的限制。该示例不将船舶相遇视为货物转运已经发生的证据。

## 2. 在 Board 中区分报告与推断 [#2-board에서-보고와-추론-구분하기]

选择**Fu Yuan Yu Leng 999**,并比较以下两个关系。

| 关系 | 标志 | 如何阅读 |
| --- | --- | --- |
| 运输船 → **与四艘船的 AIS 相遇** | `reported`，实线 | 来源报告的相遇关系 |
| 延绳钓船 → **可能向运输船转运** | `inferred`，虚线 | 基于相遇记录的解释 |

在关系详情的 **EVIDENCE** 中点击来源编号。即使基于同一文献，也应区分直接报告的关系与推断关系。

仅凭观测到船舶遭遇，无法确定实际发生了货物转移、鲨鱼的捕获地点，或各船舶的责任。阅读图中的关联时，应同时检查关系名称、状态与说明。

## 4. 在 Overview 中查看直接答案 [#4-overview에서-직접적인-답-확인하기]

**OVERVIEW** 仅显示直接回答问题的对象和关系。本例中的转运关系只是推断出的可能性，因此不会作为实际转运已发生的确定答案显示。选择关系可打开详情与来源；全部对象和关系可在 **BOARD** 中查看。示例还保存了以下事件数据：

| 日期 | 事件 | 标志 |
| --- | --- | --- |
| 2017-08-05 ~ 2017-08-07 | 与四艘延绳钓船相遇 | 有开始和结束日期的期间 |
| 2017-08-13 | 在加拉帕戈斯被查扣 | 单日事件 |

福州港停靠记录保留在关系图中，但资料未给出停靠日期，因此未加入带日期的事件数据。这说明未知日期的条目不会被任意分配时间。导出 JSON 的 `events` 中可以核对事件数据。

## 5. 区分不同来源的作用 [#5-서로-다른-출처의-역할-읽기]

**SOURCES** 列出同一机构的三份来源。

- **当时的情况分析：**用于核查相遇船舶及查扣背景。[GFW 2017 年分析](https://globalfishingwatch.org/impacts/policy-compliance/transhippment-reefer-illegal-sharks/)
- **事件后续报告：**介绍后续调查与分析结果。[GFW 后续报告](https://globalfishingwatch.org/success-story/data-and-analysis-help-track-illegal-shark-fishing/)
- **地图与分析方法：**介绍分析船舶活动及相遇的平台。[GFW 地图介绍](https://globalfishingwatch.org/our-map/)

地图介绍不能替代具体船舶事件的证据。应逐项检查对象和关系引用了哪份来源。

## 适用于我的材料 [#내-자료에-적용하기]

在其他材料上应用相同的结构时，按下列顺序进行排列。

1. **选择一个对象。** 确定与问题相关的对象，如人，组织，地点和文件。
2. **把关系写成句子。**记录谁与什么有关，在哪些材料中。
3. **标明推断。**区分直接报告的内容与包含解释的关系。
4. **仅记录已确认日期。**没有日期的事件不填入猜测的日期。
5. **留下限制。** 在案件中记录无法仅基于数据确认的信息。

自行编写结构时，可参阅[证据关联模型](/zh/docs/concepts/evidence-model)和[图数据契约](/zh/docs/reference/graph-document)；使用摘要资料生成时，参阅[快速入门](/zh/docs/guide/quickstart)。
