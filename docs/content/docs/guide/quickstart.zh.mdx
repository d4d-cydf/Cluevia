## 1. 运行应用程序 [#1-앱-실행]

使用Node.js **22.17或更高**并从项目根运行。 在您安装包的环境中运行应用程序，无论是Windows PowerShell还是 WSL .

```bash
npm ci --include=dev
npm run dev
```

应用地址为 `http://127.0.0.1:5173`。未安装依赖，或使用其他操作系统的 `node_modules` 时，可能出现找不到 Vite 的错误。

## 2. 打开公开案例 [#2-공개-사례-열기]

打开案例库中的 **GFW · Galápagos 2017**，或访问 `/case/gfw-galapagos/overview`。这是包含 12 个对象、15 条关系、2 个事件及 3 个来源的预设示例，不需要模型登录即可使用。

先在 **Overview** 查看直接回答问题的对象和关系；没有直接结果时，界面会明确提示。再在 **Board / Lanes** 中选择对象与关系，核对说明和来源。本例依据 2017 年公开文献整理，不代表船舶当前位置。

## 3. 分析自己的资料 [#3-자신의-자료로-분석]

进行新的本体设计与文档分析前，应在运行应用的同一计算机、操作系统及用户账户中登录。

```bash
npm run codex:login
npm run codex:status
```

1. 在首页输入问题，并添加 UTF-8 文本资料。
2. 点击 **START INVESTIGATION**，回答必要的澄清问题。
3. 核对分析目的、范围和预期结果，再点击 **Start analysis with this scope**。
4. 在 `/analysis/:jobId` 查看实际处理进度和已保存结果。
5. 在 **ONTOLOGY** 查看保存对象类型、属性、关系及依据的定义。

仅提供问题时，系统执行本体设计。生成实际对象与关系还需要证据资料。若只上传资料而未提出问题，系统采用整理资料的默认请求。

每个任务最多使用 10 份资料。原始文件上传默认不设应用层大小上限，但仍受服务器、浏览器及代理资源限制。PDF、图片与 Office 文件须先提取为 UTF-8 文本；仅提供 URL 不等同于已经取得网页正文。

Jev 判定为可选功能。启用时，在已有 `.env.local` 中设置 `TYPESAFE_API_KEY`，再重启服务器，避免覆盖现有环境文件。完整配置见仓库 [README](https://github.com/d4d-cydf/Cluevia/blob/main/README.md)。

## 4. 重新打开与备份 [#4-다시-열기와-백업]

从案例侧栏重新打开保存在同一服务器的结果。任务失败或取消后，可使用 **Resume remaining analysis** 继续处理剩余部分，已完成记录会保留。

单图 JSON 与整合案例导出的格式不同。备份和迁移范围见[保存与导入](/zh/docs/guide/import-export)。
