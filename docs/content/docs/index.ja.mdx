<Abstract keywords={"主張検証・証拠要件・論理構造・出典トラッキング・根拠の欠落補完"}>

結論を検証するには、資料に何が記録されているかと、その記録がどのように結論を支持するかを区別する必要がある。Cluevia はこの関係を Why-not Tree で表し、Gap Find で未充足条件を診断し、Gap Fill で必要な補完資料を提示する。本書はアルゴリズムの概念定義、実行契約、実装範囲をまとめたものである。結果は、立証経路の完成度、支持の程度、評価の完結性を分けて解釈する。

</Abstract>

## 文書の範囲 [#문서의-범위]

 [主要アルゴリズム：仕様と方法論](/ja/docs/main-algorithm/overview) 課題定義から方法論・評価計画・限界まで続く技術報告で構成される.各詳細な命令は判定規則と例外条件を定義し,現在の実装文書は当該契約を実際のモジュール・貯蔵構造・面と結びつける.現在の資料の根拠の欠乏の診断とユーザー補完経路が実装されているが,自動外部収集と統計政策の実証検証まで完了したとは限りません.

## メインアルゴリズム [#메인-알고리즘]

```text
목표 주장과 사건 범위
       ↓
Why-not Tree: 내부는 주장·AND·OR·NOT_SUPPORT, 최하위는 증거 자료
       ↓
1-3 현재 자료로 가능한 집합 트리 생성
1-4 자료 판정 중 지지만 통과
1-5 사건 메타데이터 일치 검사
1-6 부모별 중복 자료 식별
1-7 출처·인용 계보 추적
1-8 leaf → 부모 → 전체 신뢰도 평가
       ↓
공백 사유 + 미니 그래프 + 다음 액션
       ↓
Gap Fill → 새 자료·판정 버전 → 재평가
```

NOT_SUPPORTは、否定命題を証明するデータをANDに結合します。必要な資料がないか、レビューを終えなかった状態を否定命題の立証と解釈しない。

## 六つの根拠欠落 [#여섯-가지-공백]

| タイプ | 意味 | 補完方向 |
| --- | --- | --- |
| `EVIDENCE_MISSING` | 必須データなし | 直接資料検索、確保不可時のユーザーリクエスト |
| `EVIDENCE_INSUFFICIENT` | 該当主張を支持する不足 | 不足した事実・条件説明、追加証拠要請 |
| `EVENT_MISMATCH` | イベントリンクルールの不一致 | 衝突点との接続不可説明 |
| `TRUST_WEAK` | 全体 信頼度 基準未達または十分不確定 | ミニグラフとボトルネックの説明、根拠の強化 |
| `PROVENANCE_UNKNOWN` | 出典グレードD/E | 円出典表記要求または円出典ナビゲーション |
| `CHAIN_UNKNOWN` | 評価完了後完成チェーンなし | 必要なデータタイプを含むチェーン完成戦略3つ |
