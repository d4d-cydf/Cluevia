<Abstract keywords={"主张验证 ·证据要求 ·逻辑结构 ·来源追踪 ·证据缺口补充"}>

检查结论需要区分数据中所记录的内容以及该记录如何支持结论。 通过 Gap Find 诊断未满足条件，然后通过 Gap Fill 呈现必要的补充数据。 这组文件汇集了算法的概念定义，执行合同和实施范围。 在解释结果时，您必须检查是否完成了支持路径，支持水平以及评估的完整性。

</Abstract>

## 文件的范围 [#문서의-범위]

[核心算法指南](/zh/docs/main-algorithm/overview)是一份涵盖问题定义、方法、评估计划及局限的技术报告。各项详细规范明确判定规则与例外条件；当前实现文档则将契约对应到实际模块、存储结构与界面。资料缺口诊断及用户补充路径已经实现，但这不意味着自动外部采集和经实证验证的数值策略已经完成。

## 主要算法 [#메인-알고리즘]

```text
목표 주장과 사건 범위
       ↓
Why-not Tree: 내부는 주장·AND·OR·NOT_SUPPORT, 최하위는 증거 자료
       ↓
1-3 현재 자료로 가능한 집합 트리 생성
1-4 자료 판정 중 지지만 통과
1-5 사건 메타데이터 일치 검사
1-6 부모별 중복 자료 식별
1-7 출처·인용 계보 추적
1-8 leaf → 부모 → 전체 신뢰도 평가
       ↓
공백 사유 + 미니 그래프 + 다음 액션
       ↓
Gap Fill → 새 자료·판정 버전 → 재평가
```

NOT_SUPPORT 将用于证明否定命题的证据以 AND 组合。缺少必要资料或尚未完成审查，均不能解释为该否定命题已经得到证明。

## 六个证据缺口 [#여섯-가지-공백]

| 类型 | 的意思 | 补充方向 |
| --- | --- | --- |
| `EVIDENCE_MISSING` | 缺失所需证据 | 直接搜索数据，如果无法获取数据，用户请求 |
| `EVIDENCE_INSUFFICIENT` | 不足以支持主张 | 缺乏事实和条件的解释，要求提供额外证据 |
| `EVENT_MISMATCH` | 事件连接规则不匹配 | 碰撞点和无法连接的描述 |
| `TRUST_WEAK` | 整体可信度未达到标准，或因未知值无法确认是否充分 | 用迷你图解释瓶颈并补充证据 |
| `PROVENANCE_UNKNOWN` | 源级D/E | 要求原始源标记或搜索原始源 |
| `CHAIN_UNKNOWN` | 评估完成后没有完成链 | 3连锁完成策略，包括所需的数据类型 |
