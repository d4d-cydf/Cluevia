# 분석 성능과 근거 검증 개선

## 측정과 재현

`npm run eval:analysis`는 모델 호출 없이 검색 회귀 검사와 실행 대기열 실험을 출력합니다.
`npm run eval:analysis -- --live`는 `scripts/evaluate-analysis.ts`의 **가상 자료 6종**을 실제 Codex로 추출하고 원문·스키마 검증 후 정답과 비교합니다. 로그인과 모델 접근 권한이 필요하며 실제 호출이 발생합니다. CLI 스크립트에는 환경 변수를 직접 제공하거나 `node --env-file=.env --experimental-strip-types scripts/evaluate-analysis.ts --live`로 실행합니다. 키는 출력하지 않습니다.

2026-10-10, 같은 `gpt-6.1-sol`로 순차 실행한 결과:

| 설정 | 6건 처리 시간 합계 | 호출 p50 | 호출 p95 | 정답 관계 정밀도·재현율 | 잘못된 객체 병합·주장 태도 오류 |
|---|---:|---:|---:|---|---:|
| xhigh | 255.4초 | 40.6초 | 55.3초 | 각 사례 1.0 | 0 |
| high | 166.3초 | 25.7초 | 35.9초 | 각 사례 1.0 | 0 |

원시 보고서는 [xhigh](evaluations/gpt-6.1-sol-xhigh.json), [high](evaluations/gpt-6.1-sol-high.json), [오프라인](evaluations/offline.json)에 있습니다. 소유·소속·위치·부인·철회·동명이인을 검사했습니다. 작은 가상 자료의 단일 실행입니다. 실행 순서, 제공자 부하, 프롬프트 캐시가 다르므로 **실서비스 정확도 또는 추론 설정만으로 인한 35% 개선을 증명하지 않습니다.** 현재 평가기는 객체 정밀도도 출력하지만 이 두 최초 보고서에는 객체 재현율만 기록되어 있습니다.

실제 케이스에서는 처리 내역에 준비 시간, Codex 대기·실행 시간, Jev 판정 시간, 검증 재시도, 타임아웃 재분할, 범위 제외 구간, 첫 그래프까지 걸린 시간을 기록합니다. 병렬 호출 시간은 합계이므로 벽시계 경과 시간과 다릅니다. 모델 토큰은 CLI가 사용량을 반환한 설계·추출 호출에 기록하며, 없는 값을 추정하지 않습니다.

## 실행과 취소

- `CODEX_CONCURRENCY=2`: 추출 worker 전체 한도. 1–8, 기본 2. Jev 동시 실행 설정과 별도입니다.
- `CLUEVIA_JOB_CONCURRENCY=2`: 동시에 진행하는 케이스 수. 1–4, 기본 2. 케이스별 결과 저장은 기존 순서와 트랜잭션을 유지합니다.
- 단계별 effort 기본값은 온톨로지 설계(`CODEX_ONTOLOGY_EFFORT`) `high`, 사용자 질문 생성(`CODEX_CLARIFICATION_EFFORT`) `medium`입니다. 사실 추출·중요 추론(`CODEX_EXTRACTION_EFFORT`), 케이스 대화(`CODEX_CHAT_EFFORT`), Jev 규칙 설계(`CODEX_JEV_PLANNING_EFFORT`)는 전역 `CODEX_REASONING_EFFORT`를 따르며 기본 `xhigh`입니다. 명시적인 단계별 환경 변수가 우선합니다.
- Jev 규칙은 스키마 설계와 분리된 `jev-planning` 호출에서 만듭니다. Jev 키가 설정되고 의미 분석 열을 가진 구조화 자료에 2개 이상 행이 있을 때만, 짧은 프로필로 최대 1회 호출합니다. 실행 스크립트 대신 검증 가능한 선언형 규칙만 저장합니다. 실패하면 추가 규칙 없이 기본 Jev 판정과 Codex 원문 검토를 계속하며 취소는 즉시 전파합니다. 기존 온톨로지 재사용에는 추가 호출이 없습니다. Jev API 자체에는 Codex effort 설정을 전달하지 않습니다.
- `CODEX_ONTOLOGY_TIMEOUT_MS`: 설계 호출 한도. 비우면 `CODEX_TIMEOUT_MS`를 상속하며 예시 설정은 300,000ms입니다. 추출·대화 제한 시간은 별도로 유지합니다.
- Jev 호출 전에 명백한 부인·정정·재인용 단서를 검사합니다. 원문은 Codex 개별 검토로 전달합니다.
- 처음 준비된 묶음 최대 worker 수만큼을 나머지 Jev 판정과 겹쳐서 추출합니다. 전체 파일을 미리 추출하느라 첫 저장이 늦어지지 않도록 선행 추출량을 제한합니다. 영구 캐시에 검증된 결과를 기록하고, 전체 분석 순서가 확정된 뒤 기존 체크포인트 순서로 저장합니다. 준비 중 취소해도 불완전한 계획을 완료된 그래프로 공개하지 않습니다.
- 실행 중 중복 요청은 케이스 안에서만 합칩니다. 다른 케이스의 취소가 동일 자료를 분석 중인 작업을 취소하지 않습니다. 검증된 영구 캐시는 케이스 간 재사용합니다.
- 추출 캐시에 실제 모델과 effort, 확정 범위, 스키마·계약 버전을 포함합니다.

### 온톨로지 설계 시간 초과 복구

설계에는 전체 자료를 스캔한 열·타입·길이 통계와 짧은 예시를 전달합니다. 반복적인 행 예시는 제거하고, 파일당 약 2,400–6,000자 목표로 예시를 줄입니다. 열 이름·관측 타입·최대 길이는 삭제하지 않으므로 열이 많은 스키마는 목표보다 커질 수 있습니다. 질문·확정 범위와 실제 추출 원문은 유지합니다.

설계 응답이 시간 초과되면 예시를 더 축약해 한 번만 자동 재시도합니다. 스키마·매핑 검증 보완도 최대 한 번이므로 스키마 설계 호출은 총 3회 이내입니다. 이후 조건에 맞으면 Jev 규칙 설계가 별도로 최대 1회 실행됩니다. 취소·인증·호출 한도 오류에는 시간 초과 재시도를 적용하지 않습니다. 실패한 설계의 시간과 재시도 횟수도 처리 내역에 기록합니다. 설계 실패 케이스는 기존 자료를 다시 업로드하지 않고 `이어서 분석`으로 재개할 수 있습니다.

2026-10-10 실제 실패 요청의 자료 5개로 설계 단계를 검증했습니다. 설계 프로필 5,421자, `gpt-6.1-sol` / `high` / 300초 설정에서 1회 호출로 226.6초에 검증을 통과했습니다. 객체 유형 8개, 관계 유형 16개, 자료 매핑 10개입니다. 기존 오류는 설계 단계의 180초 한도에서 발생했습니다. 검증 범위는 설계와 스키마·매핑 검사이며 전체 원문 추출은 아직 실행하지 않았습니다. [측정 결과](evaluations/ontology-design-timeout-recovery.json).

추론 effort는 속도·토큰 사용·응답 품질의 절충 설정입니다. 설계에 `high`를 적용하는 것이 모든 자료에서 동일한 정확도를 보장하지는 않습니다. 모델 설정 의미는 [OpenAI reasoning 문서](https://developers.openai.com/api/docs/guides/reasoning)를 참고하세요.

## 확정 범위와 자료 보존

범위 확인 화면에서 원본 파일과 날짜 열·기간을 선택할 수 있습니다. 기간 비교는 구조화 자료의 해당 열에 실제 ISO 날짜가 있을 때만 적용됩니다. 날짜가 없거나 불명확한 자료, 부인·정정·반증 단서가 있는 행은 계속 분석합니다. 자연어 질문만으로 자료를 기계적으로 제외하지 않습니다.

제외된 원본 행도 분석 기록으로 보존하고 원문 검색에 포함합니다. 모든 자료가 확정 범위 밖이면 모델 호출 없이 정상 완료하고 그 이유를 표시합니다. 파일은 전부 읽어 보존하므로 업로드·파싱 시간까지 생략되는 것은 아닙니다. 작업의 범위는 질문과 별도로 저장되어 재개 시에도 유지됩니다.

이미 검토한 온톨로지는 범위 확인 화면에서 선택해 설계 호출을 생략할 수 있습니다. 원본 파일 이름과 열 구조, 관계 의미가 같은 자료에 사용합니다. 새로운 케이스의 객체 식별 범위는 계속 분리됩니다. 일반 문서의 새 설계는 고정된 마지막 구간 표본 대신 문서 전체에서 결정적으로 추출한 reservoir 표본을 사용합니다. 표본 추출은 모든 희귀 유형의 포함을 보장하지 않으며, 스키마로 표현하지 못한 사실은 limitations에 남깁니다.

## 검색과 원문 위치

케이스 대화는 보관 원문에 대한 역색인을 사용합니다. Node SQLite의 선택적 FTS5 확장 없이 Windows/Linux에서 동작하며 첫 검색에 색인을 생성합니다. 한국어 2글자 조각, 조사 제거, 식별자, 제한된 분야별 동의어와 선택 객체의 직접 연결을 검색 후보로 사용합니다. 동의어는 검색 힌트이며 동일 객체의 증거가 아닙니다.

이전 버전의 FTS5 검색 테이블이 있으면 시작 시 일반 검색 테이블로 전환하고 첫 검색에서 색인을 다시 생성합니다. 전환은 하나의 트랜잭션으로 처리하며 케이스·그래프·원문은 보존합니다. 기존 FTS5 테이블 전환은 FTS5를 지원하는 런타임에서 한 번 수행해야 합니다. Windows Node.js 22.17.1에서 구형 DB 복사본의 개발 서버 기동, 데이터 보존 및 전환 실패 시 원복을 검증했습니다.

관련 문장을 원문의 실제 위치에서 최대 10개 기록으로 발췌합니다. 8,000자 뒤에 있는 근거와 최초 분석에서 객체가 없었던 기록도 검색합니다. 답변 화면에 검색 대상과 모델에 전달한 기록 수를 표시합니다. 전달되지 않은 자료 때문에 사실이 없다고 단정해서는 안 됩니다. 의미 임베딩 검색은 현재 사용하지 않습니다.

인용 저장 시 해당 분석 텍스트의 SHA-256과 UTF-16 시작·끝 위치를 기록합니다. 반복 인용은 가능한 위치와 모호함을 보존합니다. 분석 기록의 인용에서 원문 위치로 이동하고 인용을 강조할 수 있습니다. 해시는 분석에 사용한 텍스트를 식별하며, 그 내용이 사실이라는 인증이나 원본 바이너리 파일의 해시가 아닙니다.

## 주장·시간·분석가 검토

새 모델 추출의 관계는 `claim`에 asserted/denied/retracted/uncertain, 발언 주체, 유효 시작·종료, 발행일, 재인용 출처를 담습니다. 알 수 없는 값은 null입니다. 발언 주체·재인용 출처·ISO 날짜는 인용문에 있어야 하며, 날짜가 다른 형식이거나 불명확하면 설명에 보존하고 날짜 필드는 null로 둡니다. 과거 결과는 태도 미분류로 표시합니다.

부정된 관계와 시점이 있는 과거 관계를 현재의 단일 관계 제약과 혼동해 삭제하지 않습니다. 시점별 상충 여부는 분석가가 원문과 함께 검토해야 합니다. 인용 일치는 의미적 진실성 검증이 아닙니다.

관계 선택 화면에서 근거 지지·이견·추가 확인·미검토 상태와 판단 근거를 저장합니다. 근거 지지·이견·추가 확인에는 판단 근거 입력이 필요합니다. 이전 판단 이력을 보존하며 미검토로 되돌릴 수 있습니다. 검토 결과는 케이스 재열기와 서버 재시작 후에도 유지됩니다. Ontology 화면에서는 명시적 식별자가 일치하는 다른 객체를 후보로 보여줍니다. 같은 이름만으로 후보를 병합하지 않습니다. 분석가가 같은 객체로 연결하거나 거부·되돌릴 수 있으며, 연결은 원래 객체와 출처별 주장을 삭제하거나 재작성하지 않습니다.

## 큰 그래프 탐색

큰 케이스는 한 번에 객체 200개, 관계 1,000개, 사건 500개까지 표시합니다. 유형·전체 검색·페이지·선택 객체의 1/2단계 연결로 범위를 변경합니다. 노드 이름 조회는 Map을 사용하며 화면 밖의 큰 노드 목록을 렌더링하지 않습니다. 작은 증분 갱신에서는 기존 배치를 유지합니다. 분석 기록 목록도 100개씩 표시합니다.

표시는 제한하지만 저장·검색·내보내기에는 전체 케이스를 유지합니다. 전체 케이스 JSON은 여전히 클라이언트에 전달하므로 초대형 케이스에서 전송량·메모리 한계가 없어지는 것은 아닙니다.

## 검증 범위

검증: Linux `npm test` 282개 통과·FTS5 전용 2개 생략, Windows 설계·검색 마이그레이션 테스트 29개 통과, `npm run build` 성공. 앞선 그래프 UI 개선의 Playwright 브라우저 테스트 23개도 별도 임시 데이터 저장소에서 통과했습니다.

`npm test`에 worker 취소/병렬 처리, effort 캐시 분리, 서로 다른 케이스 취소 격리, 원문 후반 검색, 범위 제외 자료 보존, 주장·인용 위치 저장, 동일 객체 검토 되돌리기, 1만 객체의 페이지 완전성 검사를 포함했습니다. 브라우저 테스트는 1천 객체의 제한 렌더링·검색·전체 내보내기와 관계 검토 저장·재선택을 검사합니다. API 테스트는 검토 권한·잘못된 입력·재시작 후 복원·판단 되돌리기·케이스 삭제 시 기록 정리를 확인합니다.

입력 문서 형식은 기존 UTF-8 텍스트·CSV·JSON 계열입니다. PDF·Office 파서와 OCR은 이번 다섯 단계의 실행·검색·검증 개선에 포함하지 않았습니다.
