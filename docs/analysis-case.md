# Case 그래프와 분석 기록

기본 결과 화면은 `/analysis/:jobId`의 통합 그래프다. 과거 `/case/:graphId/board` 링크도 분석 작업에 속하는 그래프이면 해당 Case로 이동한다. 수동으로 가져온 그래프와 예제는 기존 화면을 사용한다.

## 저장과 연결

- 각 처리 구간은 순번이 있는 Record다. 그래프가 있는 결과와 객체·관계가 없는 결과, 처리 대기를 구별한다.
- 앞으로 완료되는 hybrid 구간은 원문과 추출 결과를 `analysis_record_archive`에 보존한다. 그래프·완료 체크포인트와 같은 트랜잭션으로 저장하며, 재시작·재시도에 중복 생성하지 않는다.
- Case는 같은 작업의 Record만 읽는다. `entity_claims.entity_id`와 온톨로지 범위·객체 유형을 이용해 저장된 동일 객체를 연결한다. 표시 이름만으로 새로 합치지 않는다.
- 관계와 사건, 주장·추론은 기록별로 남긴다. 같은 객체에 서로 다른 속성 값이 있으면 차이를 표시하고 기록별 값을 유지한다. 상충하는 주장을 자동으로 사실 판정하지 않는다.
- 새 LLM/Jev 호출은 없다. 이 변경은 저장된 분석 결과를 통합하는 계층이다. 추출하지 못한 관계를 새로 추론하거나 구간별 모델 입력을 전역 입력으로 바꾸지는 않는다.

## API와 화면

- `GET /api/jobs/:id/case`: 전체 그래프, Record 목록, 객체·관계·사건·출처에서 원래 Record로 가는 참조, 상충하는 속성 값. 기존 작업 인증이 적용된다.
- `GET /api/jobs/:id/records/:number`: 원래 구간 그래프, 요약·한계, 객체와 관계의 인용 근거, 원문 첫 페이지.
- `GET /api/jobs/:id/records/:number/document?id=...&offset=...`: 해당 기록에 속한 원문의 12,000자 페이지. 다음 페이지를 통해 전체 원문을 볼 수 있다.
- 그래프 선택 항목의 **근거 기록**, 왼쪽 **분석 기록**에서 상세 내용을 연다. 기록을 열어도 통합 그래프와 선택은 유지된다.
- Case에는 구간당 200개 객체 제한을 적용하지 않는다. 200개 초과 시 반복 물리 배치 대신 객체 유형별 격자를 사용한다. 검색 결과 버튼으로 전체 그래프의 객체를 선택할 수 있다. 검색 버튼 목록은 50개까지 표시하며 전체 일치 개수와 검색어를 좁히라는 안내를 표시한다. 그래프 자체의 객체를 잘라내지 않는다.
- `EXPORT`는 전체 통합 그래프·기록 목록·근거 연결·속성 차이의 `.case.json` 스냅샷을 저장한다. 원문 전체와 구간별 전체 추출 결과는 이 파일에 포함되지 않는다. 이 형식의 재가져오기는 현재 지원하지 않는다. 기존 개별 그래프 Import 제한은 그대로 유지한다.

## 이전 데이터

기존에 저장된 그래프와 인용 원문은 재분석 없이 통합한다. 이전 버전에서 완료 후 삭제한 빈 구간의 상세 원문 연결은 복원할 수 없으므로 명시적으로 안내한다. 전체 처리 수와 빈 기록의 완료 상태는 유지한다. 분석이 중단된 경우에는 현재까지의 통합 결과와 미처리 기록을 표시한다.

백엔드 코드가 변경되어 개발 서버 재시작이 필요하다. 실행 중인 작업이 있으면 완료 후 재시작하거나, 중단된 작업을 같은 분석 화면에서 이어서 실행한다.
